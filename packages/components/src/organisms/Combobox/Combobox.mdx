<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Combobox" tier="Organism" />

A text field with a list of options under it. Type to narrow the list, then choose one with the arrow keys and Enter, a
mouse or a finger. The value is the chosen option's `value`, and the field shows its label. Use it where a person picks
one item from a list too long to scan, a country, a person, a record, and where the list may be fetched as they type.
"Autocomplete" is the same control. It differs from `Select`, which has no typing and suits a short list, and from
`TagsInput`, which makes chips out of whatever is typed. Focus stays in the field the whole time; the highlighted option
is pointed at rather than focused (a *combobox* in the WAI-ARIA sense).

### Import

```tsx
import { Combobox } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use it to choose one item from a list long enough that scanning it is slow: a country, a person, a project.
- Give it a name with `aria-label` or a `FormField`, so the field and its list both say what is being chosen.
- Pass `filter={false}` and fetch the options yourself when the list lives on a server, and show `loading` while you wait.
- Give each option a short, distinct `label`; put the detail in `description`, and the words people also search by (synonyms, codes) in `keywords`.
- Say why an option can't be chosen with `disabled="reason"`, rather than leaving it dimmed and unexplained.
- Use `allowCustomValue` when the list is only a suggestion and any text is acceptable.
- Use `presentation={{ base: "full-width", sm: "anchored" }}` in a form people fill in on a phone: the list spans the screen and sits on the side with room, rather than squeezing under a narrow field.
- Use `onCreate` when a person may add an item the list doesn't hold yet (a label, a company); return the new option so it is chosen.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for a handful of options: a `Select`, or a `RadioGroup`, shows them without typing.
- Don't use it to collect several values: that is `TagsInput` for free text, or `MultiSelect` for a list.
- Don't fetch on every change of text: search only on `reason === "input"`, since a pick, a clear and a reset write a label, not a query.
- Don't put interactive controls inside a row: a row is chosen as a whole, and focus never enters it.
- Don't rely on a placeholder as the name; it goes as soon as there is text.

</Callout>
</div>

## Best practices

- The value is always one of the options unless `allowCustomValue` is set. Text that matches nothing is put back to the
  last choice when the field is left, so what is shown and what is submitted never disagree.
- `value` and `inputValue` are two things. `value` is the chosen option's id; `inputValue` is the text in the field. Keep
  just `value` in your state in the usual case. Pass `inputValue` as well when you need to show a label for a value
  whose option has not loaded yet (a saved id, a record fetched later).
- Rows have a fixed height, set by `size` (and taller for an option with a `description`), so a list of thousands draws
  only the rows in view. A custom `renderOption` must fit its row; long text is cut with an ellipsis.
- The list is not narrowed by the label of a chosen option shown unedited: opening a field that already holds a value
  shows every option, with the chosen one marked.
- A reply to an older search can arrive after a newer one. Keep a request counter in your own code and drop what is
  stale, as the "fetched as you type" story does.
- `autoHighlight` makes Enter choose the first match while typing. Turn it off (it is already off with
  `allowCustomValue`) when Enter should commit exactly what was typed.
- Inside a `Form`, a hidden input carries `name` and `required` and the chosen value, so the form refuses a field with
  nothing chosen and focuses the field you can see. A form with only a combobox and no submit button doesn't submit on
  Enter, because a browser needs one text-only field for that; give the form a submit button.
- Once a list holds more than a hundred rows, group headings are drawn as plain rows rather than as grouped regions, and
  each option is read with its group's name after its own.
- `presentation="full-width"` measures the part of the page the person can see (the visual viewport), so an on-screen keyboard that covers the bottom of the screen is counted: the list goes above the field when there is little room below, and its height is what is left. `align` has no effect there, and `side` is only its first choice. Pass a map to change with the screen.
- Typed text matches an option when its label and `keywords` together hold every word of it, in any order, so "york new"
  finds "New York" and "uk" can find "United Kingdom". Only the label is marked, and every matching stretch of it, not
  only the first.
- When any option has an icon, the rows without one keep a blank place for it, so the labels stay in line. A row you
  draw yourself with `renderOption` is yours to align.
- `onCreate` adds a last row, "Create …", while the typed text names no option. It is highlighted only when nothing
  else matches, so Enter still chooses a real match first. Add the new option to `options` yourself: until you do, the
  field still shows its label, and the value is kept.

## Accessibility

<Callout tone="info" title="A combobox whose focus never leaves the text field">

- The field is a native text input with `role="combobox"`, `aria-expanded`, `aria-controls` (while open),
  `aria-autocomplete="list"` and `aria-haspopup="listbox"`. Focus stays in it while the list is open; the highlighted
  option is named by `aria-activedescendant`, so a screen reader reads each option as the arrow keys reach it.
- The list is a `listbox` named like the field (from `aria-label`, `aria-labelledby` or the field's visible label). Each row is
  an `option` with `aria-selected`; one that can't be chosen has `aria-disabled`, and its reason is read after its name.
  Groups are `group`s named by their heading; in a list long enough to be windowed, each option is read with its group's name instead.
- The "Create …" row is an option like any other, reached with the arrow keys; while its promise is out it is `aria-disabled`, and a rejection is announced.
- "No results", "Type to search" (a list with no options and nothing typed yet) and "Loading…" are rows in the list that can't be chosen, so a list is never empty to assistive technology.
  A loading list is `aria-busy`.
- The number of matches is announced in a status region that was already in the page, only as the person types and the
  count changes, never when the list merely opens. An error is announced when it appears.
- The caret and clear buttons are for the pointer and are not tab stops; the keyboard has the arrow keys, Escape and
  Alt+Down. Each is at least 24 × 24 pixels at every size.
- Enter while an input method is composing a character does nothing. Pressing a row never moves focus, so a touch
  keyboard stays up.
- Escape closes the list and puts back the label of the last choice. With the list closed it passes through, so a
  `Dialog` around the field still closes.
- The matched text in a label is marked with `Highlight`; the row is also told apart from its neighbours by its
  background, so the mark is never the only cue.
- In Windows high contrast, the highlighted row is outlined and the list keeps its border.

</Callout>

| Key | Behaviour |
|---|---|
| Down arrow | Opens the list and highlights the chosen option, or the first; when open, highlights the next option and wraps. |
| Up arrow | Opens the list and highlights the last option; when open, the previous one, wrapping. |
| Alt + Down, Alt + Up | Opens or closes the list without moving the highlight. |
| Page Down, Page Up | Move the highlight ten options (while open). |
| Enter | Chooses the highlighted option. With none highlighted it commits what was typed (`allowCustomValue`) or puts back the last choice, and closes the list. With the list closed it does what Enter does in any field. |
| Escape | Closes the list and puts back the last choice's label. |
| Tab | Leaves the field. Text that names an option exactly chooses it; other text is put back (or committed, with `allowCustomValue`). |
| Home, End, Left, Right | Move the caret in the text, as in any field. |
| Typing | Opens the list and narrows it; the first match is highlighted. With `onCreate`, a "Create …" row comes last. |

## Code examples

```tsx
{/* countries: [{ value: "ca", label: "Canada" }, { value: "mx", label: "Mexico" }, …] */}
<Combobox aria-label="Country" options={countries} onValueChange={(value) => setCountry(value)} />

{/* Native input props pass through: a numeric keyboard on a phone, no spell checking */}
<Combobox aria-label="Postcode area" options={areas} inputMode="numeric" spellCheck={false} maxLength={5} />

{/* Options fetched as the person types: search only for typing, and drop stale replies */}
<Combobox
  aria-label="Search countries"
  options={results}
  filter={false}
  loading={isFetching}
  onInputValueChange={(text, reason) => reason === "input" && search(text)}
/>

{/* Let a person add an item the list doesn't hold; return it so it is chosen */}
<Combobox aria-label="Label" options={labels} onCreate={(text) => addLabel(text)} />

{/* Show a saved choice before its option has loaded */}
<Combobox aria-label="Assignee" options={people} value={assigneeId} inputValue={assigneeName} />

{/* Choosing in a Dialog: the list sits above the dialog, takes the mouse, and leaves the dialog open */}
<Dialog>
  <Dialog.Trigger asChild>
    <Button>Ship to…</Button>
  </Dialog.Trigger>
  <Dialog.Content aria-label="Ship to">
    <Dialog.Body>
      <Combobox aria-label="Country" options={countries} />
    </Dialog.Body>
  </Dialog.Content>
</Dialog>

{/* Words in another language, and numerals that differ */}
<Combobox
  aria-label="País"
  options={paises}
  formatNumber={new Intl.NumberFormat("ar-EG").format}
  labels={{ noResults: "Sin resultados", clear: "Borrar", results: (n) => `${n} resultados` }}
/>

{/* With a label and helper text; the wiring is done for you */}
<FormField label="Country" helperText="Where the order ships" required>
  {(fieldProps) => <Combobox {...fieldProps} name="country" options={countries} />}
</FormField>
```
