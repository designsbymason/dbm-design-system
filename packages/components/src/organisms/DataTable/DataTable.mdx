<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="DataTable" tier="Organism" />

A table of data you give it as `columns` and `data`, with the behaviour an app needs around the rows: sorting by a column,
choosing rows, paging, a long list drawn a window at a time, a loading state, an empty state and a menu of actions per row. It
draws a real `Table`, so it is a native `<table>` in its own scroll frame, and it composes `TableToolbar`, `Pagination`,
`Checkbox`, `Select` and `Menu` rather than redrawing them.

It holds the state of the interaction and nothing else. Your data stays yours: it sorts and pages the rows you pass in the
browser, or, with `sortMode="manual"`, draws the rows you pass and asks you for new ones. Every piece of state (the sort, the
choice, the page, the page size, the hidden columns) is controlled with a value and a change callback, or uncontrolled with a
default.

### Import

```tsx
import { DataTable } from "@dbm-design-system/components";
```

Its parts are `DataTable.Toolbar`, `DataTable.Selection` and `DataTable.Pagination`, placed as direct children. `useDataTable()`
reads and changes the table's state from your own parts inside it.

## Properties

`DataTable` also accepts any other native `<table>` attribute beyond what's listed here (e.g. `onFocus`, `title`) — passed
straight through to the table element. `ref`, `id`, `data-testid` and the `aria-*` props reach the `<table>`, where assistive
technology expects them; `className` and `style` go on the box that holds the toolbar, the table and the pagination.

<PropertiesTable of={DataTableStories} order={propOrder} />

A column is an object, not a component:

| Field | What it does |
|---|---|
| `id` (required) | A name no other column has. Sorting, hiding and the sort announcement refer to it. |
| `header` (required) | The column's heading. A heading that isn't text needs a `headerLabel`. |
| `accessor` | Reads the column's value from a row: what the cell shows without a `cell`, and what it is sorted by without a `compare`. |
| `cell` | Draws the cell from the row. |
| `sortable` | Lets a person sort by it. Needs an `accessor` or a `compare`. |
| `compare` | Orders two whole rows, smallest first, for a value that isn't a number, a date or text. |
| `align`, `numeric` | Where the content sits, and end-aligned tabular figures. |
| `width`, `minWidth` | A length. A column with a `width` cuts a long cell with an ellipsis instead of widening. |
| `rowHeader` | Draws the cells as row headers, so a screen reader reads a row's name on entering it. |
| `wrap` | Lets the text wrap. A table with any wrapping column is never drawn a window at a time. |
| `headerLabel` | The words that name the column when `header` isn't text. |

A `TableToolbar` drawn above the table; it takes its parts (`TableToolbar.Row`, `.Search`, `.Filter`, `.ActiveFilters`,

The bulk-action row of the toolbar, read from the table's own selection: it says how many rows are chosen, offers **Clear

## Variants

### Sorting

A sortable column's heading is a button that cycles ascending, descending and none. The sorted column carries `aria-sort`, and
a live region says "Sorted by Salary, descending". Rows that tie keep their order, and an empty value goes last in either
direction. Sorting happens before paging, so it orders the whole set.

<Canvas of={DataTableStories.Sorting} />

### Selection

`selectionMode="multiple"` adds a column of checkboxes and a header checkbox that is checked, mixed or clear for the rows on the
page; a shift-click chooses a range. `"single"` replaces the choice. The chosen ids are kept across sorting and pages, and
`isRowSelectable` says which rows can't be chosen. A chosen row has three marks, since a fill alone is quiet: the checked
checkbox, a marker on the start edge of its checkbox cell (in `border.brand`, held transparent in every row so choosing one moves
nothing), and a fill one step stronger than the `brand` tone's stripe, so a chosen row isn't mistaken for a striped one.

<Canvas of={DataTableStories.Selection} />

### Pagination

`DataTable.Pagination` turns paging on. Changing the page size goes back to the first page. A page that is past the end is held
to the last one.

<Canvas of={DataTableStories.Pagination} />

### With a toolbar and paging

The toolbar goes above the table and the pagination below it, wherever they are among the children. Here the app holds the search
text and the filtered rows; the table holds the selection, the sort and the page.

<Canvas of={DataTableStories.WithToolbar} />

### Row actions

`rowActions` draws a trailing column, usually an `IconButton` that opens a `Menu`. Its heading is read by a screen reader and not
drawn.

<Canvas of={DataTableStories.RowActions} />

### A long table, drawn a window at a time

Above 100 rows, an unpaged table with a `maxHeight` draws only the rows in view, so five thousand rows cost about what fifty do.
Every row is one line of a fixed height from a token, `aria-rowcount` and `aria-rowindex` tell a screen reader the real size, and
a cell with a `width` is cut with an ellipsis. `virtualize` decides it by hand.

<Canvas of={DataTableStories.LongTable} />

### Sorting and paging on a server

With `sortMode="manual"` the table draws `data` as given and reports `onSortChange` and `onPageChange`; you answer with new rows
and say how many there are in all with `totalCount`. `loading` draws placeholder rows while you wait.

<Canvas of={DataTableStories.ServerSide} />

### Column visibility

`hiddenColumns` and `onHiddenColumnsChange` choose which columns are drawn. The menu is your own; `useDataTable()` reads and sets
the same list from inside the table.

<Canvas of={DataTableStories.ColumnVisibility} />

### Loading and empty

A loading table shows placeholder rows and is `aria-busy`. An empty one says `emptyState`, or "No results".

<Canvas of={DataTableStories.LoadingAndEmpty} />

### All sizes

`size` sets the type, the padding and the fixed height of a row (`data-table.row-height.*`) together.

<Canvas of={DataTableStories.AllSizes} />

### Pinned first and last columns

`stickyFirstColumn` and `stickyLastColumn` are `Table`'s: they pin the first and last column. With a selection, the checkbox column
is the first, so it is the one that stays; the actions column is the last.

<Canvas of={DataTableStories.PinnedColumns} />

### Tones

`tone` is `Table`'s, with `brand` as the default: a header in the brand's solid colour, with the stripes and the hover tinted to
match. `neutral` leaves the header and the caption unfilled, and `info`, `success`, `warning` and `danger` are fixed status
colours.

<Canvas of={DataTableStories.Tones} />

### Right to left

Alignment and pinning are logical, so a page with `dir="rtl"` mirrors the table. The page size select opens a Radix list that
doesn't read the page's direction, so give `DataTable.Pagination` `dir="rtl"` as well; the range's numbers are isolated, so
"1–10 of 47" reads in order.

<Canvas of={DataTableStories.RightToLeft} />

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Name the table with a `caption`, an `aria-label` or an `aria-labelledby`; a dev-mode warning fires if it has none.
- Give each row an `id` (or `getRowId`) that is stable, so the choice survives a reload of the data.
- Give the column that names each row `rowHeader`, and `getRowLabel` the same words, so a row's checkbox says whose it is.
- Make the `accessor` of a sortable column return a number, a date or text; use `compare` for anything else, including text
  that must be ordered by another language's rules: the default orders text in English, whatever the visitor's browser language, so
  a server and a browser agree.
- Hold the sort, the page and the choice yourself (controlled) when they belong in the URL or on a server.
- Use `sortMode="manual"` with `totalCount` when the rows don't fit in the browser.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for a handful of static rows with nothing to do: that is `Table`.
- Don't make `onRowClick` the only way to reach what a row opens: it adds a tab stop per row and is not announced as a link. Put a
  link in the row too.
- Don't pass a new `columns` array on every render of a large table: it sorts again each time. Define it once, or `useMemo` it.
  (A `getRowId` or `isRowSelectable` written inline is fine: they don't sort again.)
- Don't put a long, wrapping paragraph in a cell of a table you want to be windowed: a row there is one line.
- Don't use `virtualize` with pagination: pages already bound the rows drawn.

</Callout>
</div>

## Best practices

- Right-align numbers (`numeric`) so figures line up, and put a unit in the heading rather than in every cell.
- Keep the default sort in `defaultSort` (or the controlled `sort`) so the first view is the order you mean.
- Put the bulk actions that are safe first and the destructive one last, and name each for what it does.
- For a server, show `loading` during the request and keep the old rows' count in `totalCount`, so the footer doesn't jump.
- A table inside a `Card` uses `variant="ghost"`.
- Pair the toolbar's `Summary` with the footer's range so the two agree about how many rows there are.

## Accessibility

<Callout tone="info" title="A native table with real buttons and checkboxes in it">

- It is a `<table>` with `scope="col"` headers and, for a `rowHeader` column, `scope="row"` headers. It is not a `grid`: there is
  no cell-by-cell arrow-key model to learn, and every control in it is an ordinary tab stop in reading order.
- A sortable heading is a `<button>` whose name is the heading's own text. The sorted column carries `aria-sort`; the other
  columns carry none. Sorting is announced ("Sorted by Name, ascending") in a live region that is in the page before it speaks.
- Row checkboxes are named for the row ("Select Ada Lovelace"), and the header checkbox is "Select all rows" and exposes the mixed
  state. A chosen row sets `data-selected` and no `aria-selected`, which a plain table row doesn't support.
- A paged or windowed table sets `aria-rowcount` and each row's `aria-rowindex` across the whole set, so a screen reader hears the
  real size and position. The page controls announce the page and the footer's size select announces the new count.
- `onRowClick` makes each row a tab stop, activated by Enter or Space on the row itself; a press on a control inside the row is
  that control's.
- Every interactive target is at least 24 × 24px at every size (the sort button, the checkbox, the row menu's button).
- The sort button's focus ring is drawn inside it, since a header cell and the scroll frame clip what is outside. On a solid
  tone's header it takes the text's colour.
- A chosen row's fill is `bg.brand-subtle-hover` with `text.primary` over it, and it is quiet (1.14:1 against the surface in Purple
  light), so it is never the only mark: the checked checkbox and a 4px marker in `border.brand` on the edge of its checkbox cell
  say it too. Forced colours drops the fill and draws the marker in the system's highlight colour.
- An arrow on a column that isn't sorted is drawn at `opacity.80` and keeps 3:1 against its header (brand or neutral) in all four
  themes, which a real-browser check measures.
- A cell cut with an ellipsis (a column with a `width`) carries its whole text as its `title`; a screen reader reads the full text
  from the cell anyway.

</Callout>

## Code examples

```tsx
const columns: DataTableColumn<Employee>[] = [
  { id: "name", header: "Name", accessor: (row) => row.name, sortable: true, rowHeader: true },
  { id: "salary", header: "Salary", accessor: (row) => row.salary, cell: (row) => money(row.salary), sortable: true, numeric: true },
];

<DataTable
  aria-label="Team"
  columns={columns}
  data={employees}
  selectionMode="multiple"
  getRowLabel={(row) => row.name}
  onSelectionChange={setChosen}
>
  <DataTable.Toolbar aria-label="Team table tools">
    <TableToolbar.Row>
      <TableToolbar.Search>
        <SearchInput aria-label="Search the team" onSearch={setQuery} />
      </TableToolbar.Search>
    </TableToolbar.Row>
    <DataTable.Selection>
      <Toolbar aria-label="Bulk actions" variant="secondary">
        <Toolbar.Button>Delete</Toolbar.Button>
      </Toolbar>
    </DataTable.Selection>
  </DataTable.Toolbar>
  <DataTable.Pagination />
</DataTable>

{/* Words the table writes are a labels object; numbers go through formatNumber */}
<DataTable aria-label="Équipe" columns={columns} data={employees} labels={{ selectAll: "Tout sélectionner", empty: "Aucun résultat" }} />

{/* Native props reach the table element */}
<DataTable aria-label="Team" columns={columns} data={employees} onFocus={() => trackFocus("team")} title="Team members" />
```
