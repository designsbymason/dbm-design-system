<ComponentHeader title="Dialog" tier="Organism" />

A window that interrupts the page for focused work: a form, a detail view, a confirmation. By default it
is _modal_, meaning the page behind it is dimmed by a **scrim** (a translucent layer over the page), can't
be scrolled, clicked or reached with the keyboard, and keyboard focus is held inside the dialog until it
closes, when it returns to whatever opened it. Some libraries call this component a "modal". A compound
component, meaning it is made of named sub-parts you compose together: `Dialog.Trigger`, then
`Dialog.Content` holding `Dialog.Header`, `Dialog.Body` and `Dialog.Footer`.

### Import

```tsx
import { Dialog } from "@dbm-design-system/components";
```

## Properties

`Dialog` itself renders no DOM element of its own: it is a plain context provider around its sub-parts
(matching Radix's `Dialog.Root`), so it has no `className`/`style`/`id`/`data-testid`/`ref` of its own
to accept.

<PropertiesTable of={DialogRootStories} order={propOrder} />

### Dialog.Trigger properties

The element that opens the dialog on click. Also accepts any other native `<button>` attribute beyond
what's listed here (e.g. `onFocus`, `disabled`), passed straight through.

<PropertiesTable of={DialogTriggerStories} order={triggerPropOrder} />

### Dialog.Content properties

The dialog panel itself, with its scrim. Also accepts any other native `<div>` attribute beyond what's
listed here (e.g. `onKeyDown`, `dir`), passed straight through to the panel. `role`, `aria-modal` and
`data-state` are set by the dialog and can't be replaced.

<PropertiesTable of={DialogContentStories} order={contentPropOrder} />

### Dialog.Header properties

The top section: usually a `Dialog.Title` and optionally a `Dialog.Description`. Also accepts any other
native `<div>` attribute beyond what's listed here.

<PropertiesTable of={DialogHeaderStories} order={headerPropOrder} />

### Dialog.Title properties

The dialog's name, rendered as a heading. Takes no `id`: the dialog generates one and points its
`aria-labelledby` at it. Also accepts any other native heading attribute beyond what's listed here.

<PropertiesTable of={DialogTitleStories} order={titlePropOrder} />

### Dialog.Description properties

A sentence or two on what the dialog is for. Takes no `id`, for the same reason as the title. Also
accepts any other native `<p>` attribute beyond what's listed here.

<PropertiesTable of={DialogDescriptionStories} order={descriptionPropOrder} />

### Dialog.Body properties

The main content: a scroll region that takes the height left between the header and the footer.
`className`, `style` and `id` go on its outer frame. Also accepts any other native `<div>` attribute
beyond what's listed here.

<PropertiesTable of={DialogBodyStories} order={bodyPropOrder} />

### Dialog.Footer properties

The bottom section: the dialog's actions. Also accepts any other native `<div>` attribute beyond what's
listed here.

<PropertiesTable of={DialogFooterStories} order={footerPropOrder} />

### Dialog.Close properties

An element that closes the dialog on click, placed anywhere inside `Dialog.Content`. Also accepts any
other native `<button>` attribute beyond what's listed here.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use a `Dialog` for a task or decision that has to be finished or dismissed before the person goes on:
  an edit form, a confirmation, a detail view too big for a popover.
- Give every dialog a `Dialog.Title`. If the design shows no heading, wrap it in `VisuallyHidden` rather
  than leave it out.
- Put the primary action last in the footer, and a `Dialog.Close` beside it for the way out.
- Set `closeOnOutsideClick={false}` on a form with unsaved changes, so a stray click doesn't throw the
  work away, and leave the footer's own buttons as the way out.
- Use `fullScreen={{ base: true, md: false }}` for content that needs the room on a phone.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use a `Dialog` for a short hint or a small set of actions anchored to a control: that is a
  `Popover`, which doesn't interrupt the page.
- Don't open a dialog on page load or without the person asking for it. It takes over the screen and
  traps focus.
- Don't stack dialogs more than one deep. One confirmation opened from a dialog is fine; a third layer
  means the flow wants a page.
- Don't turn off both the close button and the footer's close action: the only way out would be Escape.

</Callout>
</div>

## Best practices

- Keep the header short (a title and at most one sentence of description). Put everything the person
  reads or fills in inside `Dialog.Body`, which scrolls on its own while the header and footer stay put.
- Pick the smallest `size` that fits the content: `xs`/`sm` for a confirmation, `md` for most forms,
  `lg`/`xl` for a preview or an editor. On a phone every size becomes the width of the screen less a
  gutter, so you don't need to design a second layout for it.
- Open a dialog from a real control (`Dialog.Trigger`, or your own button calling `setOpen(true)`), so
  focus has somewhere to go back to on close.
- Use `divided` when the body is long enough to scroll, so the lines under the header and over the footer
  show that content continues past the edge.
- Use `modal={false}` only for a docked tool panel the person works beside. A non-modal dialog doesn't
  dim, lock or trap anything, and an overlay that blocks nothing is usually better as a panel in the
  layout.

## Accessibility

<Callout tone="info" title="Focus, labelling and the page behind are handled by the dialog">

- `Dialog.Content` is `role="dialog"` with `aria-modal="true"` when modal. `Dialog.Title` and
  `Dialog.Description` are wired to it with `aria-labelledby` and `aria-describedby` automatically; a
  dialog with only an `aria-label` still gets a hidden title so the wiring has something to point at.
- Focus moves into the dialog on open (to its first focusable element, or choose one with
  `onOpenAutoFocus`), `Tab` and `Shift+Tab` loop inside it, and `Escape` closes it and returns focus to
  the trigger.
- While a modal dialog is open the rest of the page is hidden from assistive technology and can't be
  scrolled or clicked.
- A press on the scrim closes the dialog; a press inside a popover or select opened from the dialog does
  not. `Escape` closes only the top-most layer, so a popover closes before the dialog behind it.
- The close button's name is "Close"; translate it with `labels`.
- The body is a scroll region. When it overflows it takes a tab stop and shows a focus ring, so a
  keyboard user can scroll it; give it a name with `aria-label` if more than one region is on screen.
- The panel's text sits on the surface colour at the same contrast as a card. In forced-colours mode
  (Windows high contrast) the panel gets a visible border, since a shadow isn't drawn. Under
  `prefers-reduced-motion` the panel fades without moving.

</Callout>

## Code examples

```tsx
<Dialog>
  <Dialog.Trigger asChild>
    <Button>Edit profile</Button>
  </Dialog.Trigger>
  <Dialog.Content>
    <Dialog.Header>
      <Dialog.Title>Edit profile</Dialog.Title>
      <Dialog.Description>Changes are saved to your account.</Dialog.Description>
    </Dialog.Header>
    <Dialog.Body>
      <FieldLabel htmlFor="display-name">Display name</FieldLabel>
      <Input id="display-name" placeholder="Jane Doe" />
    </Dialog.Body>
    <Dialog.Footer>
      <Dialog.Close asChild>
        <Button variant="secondary">Cancel</Button>
      </Dialog.Close>
      <Button>Save changes</Button>
    </Dialog.Footer>
  </Dialog.Content>
</Dialog>

{/* Controlled: open it from your own state, and close it when something finishes */}
function Saved() {
  const [open, setOpen] = useState(false);
  return (
    <Dialog open={open} onOpenChange={setOpen}>
      <Dialog.Content aria-label="Saved" size="xs">
        <Dialog.Body>
          <Text>Your changes were saved.</Text>
        </Dialog.Body>
        <Dialog.Footer>
          <Button onClick={() => setOpen(false)}>Done</Button>
        </Dialog.Footer>
      </Dialog.Content>
    </Dialog>
  );
}

{/* A form with unsaved changes: only the footer's buttons close it */}
<Dialog.Content closeOnOutsideClick={false} closeOnEscape={false} showCloseButton={false}>
  …
</Dialog.Content>

{/* Choose where focus lands when it opens */}
<Dialog.Content
  onOpenAutoFocus={(event) => {
    event.preventDefault();
    nameInputRef.current?.focus();
  }}
>
  …
</Dialog.Content>

{/* A native <div> attribute, passed straight through */}
<Dialog.Content aria-describedby="terms-summary" dir="rtl">
  …
</Dialog.Content>
```
