<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="FieldGroup" tier="Molecule" />

Groups several fields under one name. It renders a native `<fieldset>` with a `<legend>`, which is how a
screen reader learns that "Street", "City" and "Postcode" are parts of one shipping address: the legend is
announced ahead of each field in the group. A sighted reader gets the same meaning from a visible heading and,
optionally, a border or a tinted box around the set.

`FieldGroup` holds the fields' layout (stacked, or side by side and wrapping), an optional description under
the legend, and an error about the group as a whole. It hands its `disabled` and `size` to the `FormField`s
inside as defaults. It owns no values and runs no validation: each field keeps its own value and its own error.

### Import

```tsx
import { FieldGroup, FormField, Input } from "@dbm-design-system/components";
```

## Properties

`FieldGroup` also accepts any other native `<fieldset>` attribute beyond what's listed here (e.g. `form`,
`name`) — passed straight through to the fieldset. A prop that sets `disabled` or `aria-describedby` is
combined with what the group computes, never a replacement for it.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Group fields that answer one question together: an address, a date of birth, a set of contact details.
- Write the legend as a noun phrase that names the set ("Shipping address"), not an instruction.
- Use `error` for a rule that spans fields ("give an email or a phone number"), and leave each field's own
  `error` on that field.
- Use `orientation="horizontal"` for short, related fields (day, month, year) and let it wrap on a small screen.

</Callout>
<Callout tone="danger" title="Don't">

- Don't wrap a single field in a `FieldGroup` — that is a `FormField`.
- Don't use it for one choice among options: `RadioGroup` and `CheckboxGroup` already carry their own name.
- Don't leave the legend empty or put a long paragraph in it; it is read out in front of every field.
- Don't nest groups more than one level deep — a screen reader announces every legend on the way in.

</Callout>
</div>

## Best practices

- Keep the legend short and put the explanation in `description`; the description is read after the group's
  name, once, not in front of each field.
- Choose `outlined` or `filled` when several groups share a page and need to read as separate blocks; `ghost` is
  right when the page already separates them with headings.
- Prefer `hideLegend` only when a visible heading right above already names the group.
- Set `size` on the group to size every field's label at once; set it on a field to make an exception.

## Accessibility

<Callout tone="info" title="A native fieldset and legend: the strongest grouping semantics there are">

- The group is a `<fieldset>` named by its `<legend>`, announced as "Shipping address, group" on entering it.
  `hideLegend` keeps the legend in the accessibility tree and takes it off the page.
- `description` and `error` are joined into the group's `aria-describedby`, together with any ids you pass.
- A group-level `error` is a `role="alert"`, announced when it appears.
- `disabled` is the native `<fieldset disabled>`: every native control inside becomes unfocusable and
  uneditable, and each `FormField` inside is marked disabled too, so its label and helper text dim with it.
- A group has no `aria-required` or `aria-invalid` (a group role supports neither); an invalid group is shown
  by its border or accent and by the announced error.
- In forced-colours mode the filled variant keeps an edge, since a background fill is dropped there.

</Callout>

## Code examples

```tsx
<FieldGroup legend="Shipping address" description="Where should we send it?">
  <FormField label="Street">{(field) => <Input {...field} />}</FormField>
  <FormField label="City">{(field) => <Input {...field} />}</FormField>
</FieldGroup>

<FieldGroup legend="Date of birth" orientation="horizontal" variant="outlined">
  <FormField label="Day">{(field) => <Input {...field} inputMode="numeric" />}</FormField>
  <FormField label="Month">{(field) => <Input {...field} inputMode="numeric" />}</FormField>
  <FormField label="Year">{(field) => <Input {...field} inputMode="numeric" />}</FormField>
</FieldGroup>

<FieldGroup legend="Contact" error="Give us an email address or a phone number.">
  <FormField label="Email">{(field) => <Input {...field} type="email" />}</FormField>
  <FormField label="Phone">{(field) => <Input {...field} type="tel" />}</FormField>
</FieldGroup>

{/* Native fieldset attributes pass straight through, such as form, to tie it to a form elsewhere on the page */}
<FieldGroup legend="Preferences" form="settings-form" name="preferences">…</FieldGroup>
```
