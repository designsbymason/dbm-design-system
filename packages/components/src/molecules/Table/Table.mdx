<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Table" tier="Molecule" />

A lightweight, non-interactive table for presenting tabular data — real `<table>` semantics with DBM's own
styling, density, and responsive scrolling. It's a compound component, meaning it's made of named sub-parts you
compose together rather than one component with a long list of props: put `Table.Caption`, `Table.Header`,
`Table.Body`, and (optionally) `Table.Footer` inside `Table`, each holding rows (`Table.Row`) made of header cells
(`Table.HeaderCell`) and data cells (`Table.Cell`). Every sub-part renders the native element its name suggests, so native table features like
`colSpan`, `rowSpan`, and `scope` work directly.

`Table` deliberately has no sorting, row selection, or pagination — it's for displaying data, not manipulating it.
A sortable, selectable, paginated table is the job of the future `DataTable`, which builds on this one.

### Import

```tsx
import { Table } from "@dbm-design-system/components";
```

## Properties

`ref`, `className`, `style`, `id`, `data-testid`, and the `aria-*` props all apply to the `<table>` element itself,
where assistive technology expects them; `containerClassName` and `maxHeight` target the scroll container around
it instead. Also accepts any other native `<table>` attribute beyond what's listed here (e.g. `onClick`, `title`) —
passed straight through to the `<table>`.

<PropertiesTable of={TableStories} order={rootPropOrder} />

<PropertiesTable of={TableCellStories} order={cellPropOrder} />

### Table.Empty properties

The message row for a table with no data, rendered as a native `<tr>` holding a single `<td>` that spans every column.
Place it inside `Table.Body` in place of the rows. Also accepts any other native `<td>` attribute beyond what's listed
here (e.g. `colSpan`, `title`) — passed straight through to the cell; `colSpan` overrides the column count it reads
from the table's first row.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Reach for `Table` to present read-only tabular data — invoices, rosters, comparison charts — where rows and
  columns genuinely relate to each other.
- Give every table a name: a visible `Table.Caption` is best, or `aria-label`/`aria-labelledby` when a visible one
  doesn't fit the layout.
- Mark numeric columns with `numeric` — on both the header cell and the body cells. It right-aligns and sets tabular
  figures, so every digit takes the same width and a column of figures lines up exactly. (Nunito's digits are already
  equal-width, so with it `numeric` is chiefly the alignment shorthand; it matters where a font's digits are
  proportional, such as the system font a page falls back to if Nunito isn't loaded.)
- Mark the first cell of a row that labels the rest of it as `<Table.HeaderCell scope="row">`, not a plain
  `Table.Cell`.
- Set `maxHeight` whenever you use `stickyHeader` — a header can only stay pinned inside a scroll area that has a
  height to scroll.
- Use `stickyFirstColumn` on a wide table whose first column identifies the row (an ID, a name), so the label stays in
  view while the reader scrolls sideways.
- Use `stickyLastColumn` when the trailing column should stay in view too — an actions column, a running total. It
  combines with `stickyFirstColumn` to pin both edges.
- Show a skeleton while data is on its way with `<Table.Body loading>`, so the table keeps its shape and doesn't jump
  when the rows arrive; and render a `Table.Empty` — saying what to do next — when there's genuinely nothing to show.
- Use `variant="ghost"` when embedding a `Table` inside a container that already has its own border (a `Card`).
- Use `tone="brand"` to give a table a strong, on-brand header — typically the primary table on a page. It follows
  the active brand theme, so it resolves to Purple or Emerald automatically.
- Use `tone="success"`, `"warning"`, `"danger"`, or `"info"` when a table's whole subject carries that meaning — a
  list of failed payments, a set of items awaiting review. These are fixed status colours that don't change with the
  brand.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use a `Table` for page layout. If the content isn't genuinely tabular, reach for `Grid` or `Stack`.
- Don't put interactive controls in every cell of a large table and expect sorting or selection to come with them —
  those belong to the future `DataTable`.
- Don't skip `Table.Header` and put column labels in ordinary body cells — assistive technology relies on real
  header cells to announce which column a value belongs to.
- Don't put a non-neutral `tone` on every table on a page — a filled header is a strong accent, and it stops
  standing out when everything has one.
- Don't rely on a tone's colour alone to convey its meaning. A `danger` table should also say so in its caption or
  surrounding text — not everyone perceives the colour difference.
- Don't rely on `striped` or `hoverable` to communicate meaning (a "selected" or "flagged" row) — they're purely
  reading aids and carry no semantics.

</Callout>
</div>

## Best practices

- Keep column labels short. A long label makes its column wider than its data needs.
- Choose `size` by data density, not decoration: `xs`/`sm` for dense reference data, `md` for general use, `lg`/`xl`
  when a table is the primary content of a spacious page.
- Put summary rows (totals, averages) in `Table.Footer` rather than as the last body row, so they read as a
  summary and stay visually set apart.
- Don't wrap a table in your own `overflow` container to make it responsive — `Table` already scrolls sideways
  inside its own frame when it's wider than the space it's in. Use `containerClassName` if you need to adjust that
  frame.
- For a very large dataset (hundreds of rows), prefer pagination or the future `DataTable`'s virtualized rendering
  over one enormous `Table`.

## Accessibility

<Callout tone="info" title="A real table, plus keyboard access to its own scrolling">

- Each sub-part renders the native table element, so screen readers announce it as a table with its row and column
  structure, and read each cell together with its header. `Table.HeaderCell` defaults to `scope="col"`; set
  `scope="row"` for a row header.
- A `Table.Caption` names the table automatically. Without one, provide `aria-label` or `aria-labelledby`.
- A scrollable area has to be reachable from the keyboard (WCAG 2.1.1). While the table is wider than its space, its
  scroll frame becomes focusable — `Tab` onto it, then use the arrow keys to scroll — and is announced as a region
  named after the table. When the table fits, the frame is not focusable at all, so it adds no extra tab stop.
- While `loading`, the body is marked busy (`aria-busy`) and a visually hidden "Loading" message (set your own with
  `loadingLabel`) is announced; the skeleton shapes themselves are hidden from assistive technology. `Table.Empty`
  is an ordinary cell spanning the table, read like any other content.
- `stickyFirstColumn` and `stickyLastColumn` change only how the table looks while scrolling — the DOM order, header associations, and
  keyboard behaviour are unchanged.
- `striped` and `hoverable` backgrounds keep body text (`text.primary`) at 6.5:1 or better — comfortably above the
  4.5:1 AA text-contrast floor — in every theme, light and dark. Under any non-neutral `tone`, header
  and caption text (its `text.on-*` token on its solid fill) is 4.71:1 or better in every theme, and body text on the
  tinted stripe and hover backgrounds is 9.66:1 or better.

</Callout>

## Code examples

```tsx
<Table striped>
  <Table.Caption>Recent invoices</Table.Caption>
  <Table.Header>
    <Table.Row>
      <Table.HeaderCell>Invoice</Table.HeaderCell>
      <Table.HeaderCell>Status</Table.HeaderCell>
      <Table.HeaderCell align="end">Amount</Table.HeaderCell>
    </Table.Row>
  </Table.Header>
  <Table.Body>
    <Table.Row>
      <Table.HeaderCell scope="row">INV-001</Table.HeaderCell>
      <Table.Cell>Paid</Table.Cell>
      <Table.Cell align="end">$250.00</Table.Cell>
    </Table.Row>
  </Table.Body>
  <Table.Footer>
    <Table.Row>
      <Table.HeaderCell scope="row" colSpan={2}>Total</Table.HeaderCell>
      <Table.Cell align="end">$250.00</Table.Cell>
    </Table.Row>
  </Table.Footer>
</Table>

{/* A toned table: solid header and caption, tinted stripes and hover */}
<Table tone="brand" striped hoverable>
  {/* … */}
</Table>

{/* A status-toned table */}
<Table tone="danger" aria-label="Failed payments">
  {/* … */}
</Table>

{/* Numeric columns: right-aligned, tabular figures */}
<Table.HeaderCell numeric>Amount</Table.HeaderCell>
<Table.Cell numeric>$1,234.50</Table.Cell>

{/* A first column that stays put while the rest scrolls sideways */}
<Table stickyFirstColumn>
  {/* … */}
</Table>

{/* A trailing column that stays in view too — alone, or with the first column */}
<Table stickyLastColumn>
  {/* … */}
</Table>
<Table stickyFirstColumn stickyLastColumn>
  {/* … */}
</Table>

{/* Skeleton rows while loading; an empty message when there's nothing to show */}
<Table.Body loading loadingRows={5} />
<Table.Body>{rows.length ? rows : <Table.Empty>No invoices yet</Table.Empty>}</Table.Body>

{/* A header that stays pinned while a long body scrolls */}
<Table stickyHeader maxHeight="24rem">
  {/* … */}
</Table>

{/* No visible caption — name the table another way */}
<Table aria-label="Team roster" size="sm" hoverable>
  {/* … */}
</Table>

{/* A native <td> attribute, passed straight through: a cell spanning two columns */}
<Table.Cell colSpan={2}>Spans two columns</Table.Cell>

{/* A native <table> attribute, passed straight through */}
<Table title="Invoices" aria-label="Invoices">
  {/* … */}
</Table>
```
