<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="CodeBlock" tier="Molecule" />

A block of source code: syntax-highlighted, with an optional title, line numbers, highlighted lines, a copy
button, and a way to collapse a long one. It is a `<figure>` around a scrollable `<pre><code>`, and it draws
the code as text, never as HTML.

Highlighting is a small built-in tokenizer with no dependency. `ts`, `tsx`, `js`, `jsx`, `json`, `css`, `html`,
`bash` and `diff` work as they are; `python`, `yaml`, `sql`, `markdown`, `go`, `rust`, `java`, `c`, `cpp`, `csharp`,
`kotlin`, `swift`, `ruby`, `php` and `toml` are one line each to turn on, so an app that doesn't use them doesn't ship them; and a grammar of your own, or another highlighter,
plugs in the same way. Any other language is drawn as plain text. It is a lexer, not a full grammar — it reads
well, and it will not catch every corner of a language.

### Import

```tsx
import { CodeBlock } from "@dbm-design-system/components";
// Only for a language outside the core (python, yaml, sql, markdown, go, rust, java) or one of your own:
import { pythonLanguage, registerCodeLanguage } from "@dbm-design-system/components";
```

## Variants

Each example below writes `code={source}` (or `config`, `command`, …) where it needs a piece of text. That is a
placeholder for your own string, not a prop or an import: the comment at the top of the snippet says what it
stands for, and the languages example writes its code inline.

### Languages

<Canvas of={CodeBlockStories.Languages} />

### More languages

Python, YAML, SQL, Markdown, Go, Rust and Java, with the usual aliases (`py`, `yml`, `postgres`, `md`, `golang`,
`rs`). They are opt-in: call `registerCodeLanguage` once, when the app starts, with each one you use
(`pythonLanguage`, `yamlLanguage`, `sqlLanguage`, `markdownLanguage`, `goLanguage`, `rustLanguage`,
`javaLanguage`), and every block can use it. Until you do, a block in that language is drawn as plain text, and in development the console says which call is missing. A
bundler drops the ones you don't import. A Markdown block draws the lines of a fenced code block as they are, so a
snippet of another language inside it is never mistaken for Markdown.

<Canvas of={CodeBlockStories.MoreLanguages} />

### Further languages

C, C++, C#, Kotlin, Swift, Ruby, PHP and TOML (aliases `h`, `c++`, `cc`, `hpp`, `cs`, `kt`, `kts`, `rb`), opt-in
in the same way (`cLanguage`, `cppLanguage`, `csharpLanguage`, `kotlinLanguage`, `swiftLanguage`, `rubyLanguage`,
`phpLanguage`, `tomlLanguage`). Each is approximate, and says where: nested block comments in Kotlin and Swift are
read as one level, an interpolated string (`$"…"`, `"…$name…"`, `"…#{x}…"`) is one colour throughout, Ruby's `/`
is always a division (never a regex), and a PHP file's text outside `<?php … ?>` is drawn as it is written, not told
apart from code.

<Canvas of={CodeBlockStories.FurtherLanguages} />

### Your own language or highlighter

A language is a name and a function from the code to lines of `{ type?, text }` tokens, with `type` one of
`keyword`, `string`, `number`, `function`, `type`, `property`, `tag`, `comment`, `inserted` or `deleted`. Register
it with `registerCodeLanguage`, and it wins over a built-in language of the same name, which is how a fuller
grammar replaces the approximate one; that call returns a function that undoes it. Blocks already on the page
redraw when one is registered, so a grammar loaded later (`import()`, then register) colours the blocks that were
drawn plain. To highlight a single block, pass `highlighter` instead: it is tried first, and returns tokens, or
`undefined` to leave the block to the registered and built-in languages.

Whatever your code returns is checked before it is drawn: it must be lines of tokens with no newline inside one,
and joining them must give back the code exactly. Anything else, or an error, draws the block as plain text with a
warning in development, so a faulty highlighter can never lose or change the code. It is data, never HTML, so
there is nothing to sanitise. The 30,000-character limit that protects the built-in languages does not apply to
yours: a large block costs what your highlighter costs.

<Canvas of={CodeBlockStories.OwnLanguage} />

### Sizes

`size` is on the shared scale. It sets the code's font size, the space around it and the size of the header
buttons. `md`, the default, is the size the block has always had; `xs` and `sm` share the smallest font in the
system and differ in the space around the code. Pick the size for the surface it sits on: a dense side panel
takes `sm`, a tutorial that is read as prose takes `lg`.

<Canvas of={CodeBlockStories.Sizes} />

### Minimal: less header

`showLanguage={false}` drops the language label and keeps the title and the buttons. `showHeader={false}` drops
the whole strip: no title, no language, and the copy button (and the wrap toggle, if it is on) move to the top
corner of the code, always visible, with the first line starting below them so they never cover code. A title is
then not drawn, but still names the block. Add `copyable={false}` for nothing but the code, and give it an
`aria-label` when it has no title.

### Highlighted lines

`highlightLines` takes line numbers and ranges (`[2, "4-6"]`), by the numbers shown. A highlighted line has a
band across the full width and an accent on its edge, so it does not rely on colour alone.

<Canvas of={CodeBlockStories.HighlightedLines} />

### A diff with line numbers

`showLineNumbers` on a `diff` gives the gutter two columns, the line's number in the old file and in the new one,
read from the diff's `@@ -12,4 +12,5 @@` hunk headers (the output of `git diff` has them). A removed line has an old
number only, an added line a new one only, and a context line both; the header lines have none. A diff with no
hunk headers, such as a hand-written `-`/`+` snippet, has no file positions to show, so it is drawn without a
gutter. As with every gutter, the numbers are decoration: not selected, not copied, not read out. In a numbered
diff `highlightLines` counts the rows, from 1, and `startLine` is not used.

<Canvas of={CodeBlockStories.DiffLineNumbers} />

### A wrap button

`wrapToggle` puts a button in the header that turns wrapping on and off, for readers who would rather scroll or
rather wrap. It is a toggle button: its pressed state says which, and its name stays "Wrap lines". `defaultWrap`
starts it on. To own the state, pass `wrap` and `onWrapChange`, as `expanded` works on a collapsible block. A
collapsed block still shows exactly its first lines when it is switched.

<Canvas of={CodeBlockStories.WrapToggle} />

### Long lines that scroll

Without `wrap` a long line scrolls sideways. While the code overflows, the scrolling area is a tab stop with a
name, so a keyboard can reach it; a snippet that fits adds no tab stop.

<Canvas of={CodeBlockStories.Scrolling} />

### The copy button

It copies exactly `code`, shows a check mark for a moment, and announces "Copied" — or "Copy failed" if the

<Canvas of={CodeBlockStories.CopyButton} />

### Shell commands: the prompt is not copied

In shell code (`bash`, `sh`, `shell`, `zsh`, `console`), a leading `$ ` is drawn as written but taken off when the
code is copied, so a command pastes and runs. Only `$` followed by a space counts, indentation is kept, and a line
without a prompt (a comment, output) is copied as it is — so keep a command's output in a block of its own. Pass
`stripPrompt={false}` to copy the code exactly as written.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Give a snippet a `language` so it is coloured, and a `title` when it is a file.
- Use `highlightLines` and `startLine` to point at the lines a paragraph is about, in an excerpt.
- Use `collapsible` for a long listing, so the page keeps its shape and the whole text is still a click away.
- Use `wrap` for a command that people will read, and let code that is meant to be compared with an editor
  scroll. Add `wrapToggle` when readers differ.
- Show output, logs and errors as plain text (no `language`), so nothing in them is mistaken for syntax.
- Set `maxHeight` on a block that could be very long, so it scrolls instead of pushing everything down.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for a word or two inside a sentence. That is `Code`.
- Don't rely on `highlightLines` alone to say something important. It is announced as well as drawn, but the
  text around the block is where the reason belongs.
- Don't expect a full parse: an odd construct may be coloured a little wrong. It is for reading, not for a
  build.
- Don't pass HTML you have built into `code` expecting it to render. It is shown as text, on purpose.
- Don't hide the copy button on a command that people are meant to paste, and don't set `showHeader={false}`
  on a block with no `title` without an `aria-label` to name it.

</Callout>
</div>

## Best practices

- Write a shell command as `$ pnpm add x` when it sits in prose with its output, and leave the `$` out when the
  block is only there to be copied; either way the prompt is never copied.
- Keep a block short enough to read at a glance. Ten to twenty lines shows an idea; more belongs in a file
  people can open, or behind `collapsible`.
- Name blocks that are compared with each other ("Before" and "After") with `title`, and colour a change with
  the `diff` language rather than by hand.
- A very long or unusual input is drawn as plain text past 30,000 characters in the built-in and shipped languages, rather than stalling the page. A grammar you bring has no such limit, so keep its cost proportional to the code's length.
- Register a language once, when the app starts (on the server too, if you render there), not in a component: registering is app-wide, and a component that registers on every render does the work again.
- Give a block without a `title` an `aria-label` that says what it is ("Install command").

## Accessibility

<Callout tone="info" title="A named figure holding real text">

- The block is a `<figure>` named by its `title`, `aria-label` or `aria-labelledby`. The code is real text in a
  `<pre><code>`, so it can be selected, searched, translated and read by a screen reader as written.
- The scrolling area is a **tab stop, with a name, only while the code overflows**, so it can be scrolled with
  the arrow keys; a snippet that fits adds no tab stop. A collapsed block clips its height on purpose and is
  not a tab stop for that; only sideways overflow makes it one.
- The copy button is an ordinary button named "Copy code". Pressing it announces "Copied" or "Copy failed"
  in a live region that was already in the page. The result is not carried by the icon alone.
- The wrap button is a toggle button: `aria-pressed` says whether wrapping is on, and its name, "Wrap lines" (`labels.wrap`),
  does not change with it. It comes before the copy button, and both come before the code, so a keyboard reaches
  them first, with or without a header.
- With `showHeader={false}` the title is not drawn, so it names the block as text instead (an `aria-label` or
  `aria-labelledby` still takes precedence), and the scrolling area is named by it too. The buttons move to the top
  corner of the code and are always visible.
- The expand button is a real button with `aria-expanded` and `aria-controls`, and says how many lines it will
  reveal.
- Line numbers are drawn by CSS and marked as decoration (CSS alternative text), so a screen reader does not read
  them as part of the code, and selecting the code does not select them. Both are checked in the browser's own
  accessibility tree and against a real selection, not assumed: generated content is read out by default.
- A highlight is also *said*: the first line of each highlighted run is preceded by "Highlighted line:" or "3
  highlighted lines:" for people who can't see the band. The words are `labels.highlighted`, and, like a line
  number, they are never selected or copied.
- In forced colours (Windows high contrast) the band and syntax colours give way to the system's, and the edge
  accent stays as the highlight's visible cue; plain lines show no accent, and the fade over a collapsed block is
  removed.
- A highlighted line has a band and a 4px edge accent, in addition to its colour. The band's colour and every
  syntax colour is measured against `bg.code-block` and `bg.code-highlight` in all four themes, as are the line
  numbers and title (`text.secondary`): 4.5:1 or more (AA) everywhere.
- The copy, wrap and expand buttons are at least 24 × 24px (WCAG 2.5.8) at every `size`.
- Code stays left to right in a right-to-left page; the header follows the page, and its logical properties
  mirror without a prop.

</Callout>

## Code examples

```tsx
<CodeBlock language="tsx" title="SaveButton.tsx" showLineNumbers highlightLines={[2, "4-6"]} code={source} />

<CodeBlock language="bash" code="pnpm add @dbm-design-system/components" />

{/* An excerpt from further down a file */}
<CodeBlock language="ts" showLineNumbers startLine={42} highlightLines={[44]} code={excerpt} />

{/* Long: show ten lines, and the rest behind a button */}
<CodeBlock language="json" collapsible code={config} />
<CodeBlock language="json" maxHeight="16rem" code={config} />

<CodeBlock language="bash" wrap code={command} />
<CodeBlock language="bash" wrapToggle defaultWrap code={command} />   {/* a button that turns wrapping on and off */}
<CodeBlock language="ts" size="sm" code={source} />                    {/* xs | sm | md (default) | lg | xl */}
<CodeBlock language="ts" title="total.ts" showLanguage={false} code={source} />
<CodeBlock language="ts" showHeader={false} aria-label="total.ts" code={source} />  {/* buttons in the corner of the code */}
{/* yaml is opt-in: registerCodeLanguage(yamlLanguage), once, when the app starts */}
<CodeBlock language="yaml" code={workflow} />
<CodeBlock language="bash" code={"$ pnpm add x"} />              {/* copies "pnpm add x" */}
<CodeBlock language="bash" stripPrompt={false} code={"$ pnpm add x"} />  {/* copies "$ pnpm add x" */}
<CodeBlock language="ts" copyable={false} code={snippet} />
<CodeBlock language="bash" code={command} onCopied={() => track("install-copied")} />

{/* Translated */}
<CodeBlock
  code={config}
  collapsible
  labels={{ copy: "Copier le code", expand: (count) => `Afficher ${count} lignes de plus` }}
/>

<CodeBlock language="ts" code={source} onFocus={() => trackFocus("example")} />

{/* A visible label names the block */}
<span id="install-label">Install</span>
<CodeBlock aria-labelledby="install-label" language="bash" code={command} />
```
