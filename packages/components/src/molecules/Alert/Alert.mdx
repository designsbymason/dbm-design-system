<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Alert" tier="Molecule" />

An alert is a message that stays in the page: something the reader should know, or do something about
— a saved form, a failed upload, a plan about to expire. A compound component: put `Alert.Title`,
`Alert.Description` and `Alert.Actions` inside `Alert`, in any order and any of them optional, or just
plain text for the shortest one. It is not a `Toast`, which floats over the page and goes away on its
own; an alert sits where you put it and stays until the situation changes or the reader dismisses it.

Choose what it is about with `tone`, how it is drawn with `variant`, and how big it is with `size`.
`banner` makes it edge to edge, for a message about a whole page or section, `actionsPlacement="inline"`
puts its actions beside the message, `align="center"` centres it for an announcement, and `sticky` keeps
it at the top as the page scrolls. `dismissible` adds a button that closes it, and the companion
`usePersistentDismiss` hook remembers the dismissal across visits.

### Import

```tsx
import { Alert, usePersistentDismiss } from "@dbm-design-system/components";
```

The message itself. Also accepts any other native `<div>` attribute beyond what's listed here (e.g.
`onClick`, `title`) — passed straight through to the underlying element.

<PropertiesTable of={AlertDescriptionStories} order={descriptionPropOrder} />

### Alert.Actions properties

What the reader can do about it — the row that holds the alert's actions. It has to be a direct child of
the alert, which sets it apart from the message so that it can sit beside it (`actionsPlacement`); one
wrapped in another element is treated as part of the message. It holds anything (an
`Alert.Action`, a `Link`, your own control), but only an `Alert.Action` takes the alert's colours. Also
accepts any other native `<div>` attribute beyond what's listed here (e.g. `onClick`, `title`) — passed
straight through to the underlying element.

<PropertiesTable of={AlertActionsStories} order={actionsPropOrder} />

### Alert.Action properties

One thing the reader can do about the message: a `Button` that takes the colours and the size of the
alert around it, so it reads against every tone and variant — including a solid one, where a
brand-coloured button would be nearly invisible. It takes everything `Button` takes, except `variant`
(here, `"primary"`, `"secondary"` or `"tertiary"`) and `size` (always the alert's). Also accepts any
other native `<button>` attribute beyond what's listed here (e.g. `onFocus`, `title`) — passed
straight through.

<PropertiesTable of={AlertActionStories} order={actionPropOrder} />

### usePersistentDismiss

A hook for remembering that a message was dismissed — implemented in `@dbm-design-system/primitives`
and exported from `@dbm-design-system/components` too, so one install covers it.
`usePersistentDismiss(key, options?)` returns `{ ready, dismissed, dismiss, reset }`.

| Name | Type | Description |
|---|---|---|
| `key` | `string` | Names the message. Change it (`"summer-sale-2027"`) to show a new message to people who dismissed the last one. Stored as `dbm-dismissed:<key>` |
| `options.storage` | `"local" \| "session"` | Where to remember it: across visits (`"local"`, the default) or for this tab only |
| `options.expiresAfter` | `number` | How long a dismissal lasts, in milliseconds. Left out, it lasts until `reset` or until the browser's storage is cleared |
| `ready` | `boolean` | `false` on the server and on the first render while a server-rendered page hydrates; `true` once the browser has been asked |
| `dismissed` | `boolean` | Whether it has been dismissed, in this tab or (with `"local"`) another. `false` until `ready` |
| `dismiss()` | `() => void` | Remembers the dismissal |
| `reset()` | `() => void` | Forgets it, so the message shows again |

### With actions

`Alert.Action` is a `Button` that takes the alert's colours and its size. Choose how prominent it is
with `variant`: a filled `"primary"` (the default), an outlined `"secondary"`, or a text-only
`"tertiary"`.

<Canvas of={AlertStories.WithActions} />

### Actions on every tone and variant

How each action looks depends on the alert it is in. On a `"solid"` alert the primary is inverted (a
light fill with the tone's colour as its label), the secondary is outlined in the on-fill colour, and
the tertiary is plain on-fill text. On a `"subtle"` or `"outlined"` alert the primary is filled in the
alert's own tone, and the secondary and tertiary take the tone's own text colour for their label (for
`"neutral"`, secondary text), so an `info` alert's secondary action reads in info blue.

### Banner

`banner` draws the alert edge to edge, with square corners and no side borders. The dashed frame here

<Canvas of={AlertStories.Banner} />

### Actions beside the message

`actionsPlacement="inline"` puts `Alert.Actions` beside the message, at the end of the row — the usual
layout for a banner, where stacking the actions makes it needlessly tall. It doesn't depend on the
page's width: the actions drop below the message on their own when the alert's own width can't fit both,
so an alert in a narrow column stacks by itself. Drag the corner of the second box to see it.

<Canvas of={AlertStories.InlineActions} />

### Centred content

`align="center"` centres the message and its actions, with the text centred too — for an announcement.
The icon sits inline at the start of the first line (the title, or the description when there is no
title), so it centres with those words instead of standing apart from them. The dismiss button stays at
the end of the row, and the content stays centred whether or not there is one; in a narrow alert the text
stops short of the button. If the first thing in the alert is plain text, or a title drawn onto your own
element (`asChild`), the icon can't sit in that line and stays before the whole message.

<Canvas of={AlertStories.Centered} />

### Appearing after the page loads

An alert that appears after the page has loaded — an error after a submit, a message after a route change,
one reopened through `open` — fades and slides in, and the space it takes opens smoothly so what is below
moves down rather than jumping. One that is already in the page when it loads is simply there: it doesn't
animate. There is nothing to set. Press the button to add one.

<Canvas of={AlertStories.Appearing} />

### Sticky

`sticky` keeps the alert at the top of the page as the reader scrolls, and lifts it with a shadow
while it is stuck. It is built on `Affix`. Scroll the box below; in a scrolling panel of your own, pass
that panel as `scrollContainerRef`, and use `stickyOffset` to leave room for a sticky header. The
sticky element is the alert's own outermost element, so put the alert directly inside the container it
should stick within — anything that wraps it becomes the box it sticks within, and it won't stick.

<Canvas of={AlertStories.Sticky} />

### Dismissible

`dismissible` adds a button. Uncontrolled, it closes the alert and reports it through
`onOpenChange(false)`; the alert then collapses away rather than vanishing, so what is below moves up
smoothly (not at all with reduced motion). Nothing inside it can reopen it, so `onOpenChange` is only
ever called with `false`.

<Canvas of={AlertStories.Dismissible} />

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use an alert for something the reader needs to notice or act on, placed near what it is about.
- Choose the tone for what the message means, not for the colour you'd like: `danger` for a failure,
  `warning` for something that needs attention, `success` for a confirmation, `info` for news.
- Say what happened and what to do in the title and description; put each action in `Alert.Actions`
  as an `Alert.Action`, so it reads against the alert's tone and variant.
- Use `banner` for a message about a whole page or section, and `sticky` only for one the reader must
  not lose sight of. Make a sticky alert dismissible.
- Put a banner's actions beside its message (`actionsPlacement="inline"`), and centre a one-line
  announcement (`align="center"`); leave a longer message start-aligned, which reads better.
- Use `role="none"` for a message that is already on the page when it loads.
- Remember a dismissal with `usePersistentDismiss` for a message that would otherwise return on every
  visit — and change the key when the message changes.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use an alert for feedback that should disappear on its own ("Saved") — that is a `Toast`.
- Don't stack several alerts; combine them, or show the most important one.
- Don't rely on the icon or the colour alone to carry the meaning. The text must say it too.
- Don't put a persistent dismissal on a `danger` message the reader must see each time, such as a
  failed payment.
- Don't wrap a sticky alert in another element: it would stick within that wrapper instead of the page.
- Don't put a sticky banner on a page that is already short of vertical room, such as a phone in
  landscape, unless it is dismissible.

</Callout>
</div>

## Best practices

- Every part is optional. A one-line message is best as plain text or a lone `Alert.Title`; add a
  description when there is more to say than a phrase.
- The default `role` follows the tone. Use `role="alert"` deliberately for an urgent message that
  isn't `danger` or `warning`, and `role="none"` for anything already on the page at load — a live
  region that is present when the page loads can be announced before the reader has asked for it.
- Use `Alert.Action` for the alert's actions, not a plain `Button`. A `Button` keeps the brand colours,
  which are nearly invisible on a `"solid"` alert (1.0–1.6:1) and clash with a tone on the others;
  `Alert.Action` takes its colours from the alert, and its size follows the alert's `size`. Anything
  else in `Alert.Actions` (a `Link`, your own control) keeps its own colours, so check that it reads.
- Make one action `"primary"`, and the rest `"secondary"` or `"tertiary"`; a single action is usually
  `"primary"`.
- `Alert.Title` is a paragraph so that an alert doesn't add a heading to the page's outline. When it
  does belong in the outline, use `asChild` with the right heading level.
- With `banner`, put the alert as a direct child of the page or section container, so it can reach the
  edges. Stack `sticky` alongside a sticky site header by giving it `stickyOffset` equal to the header's
  height.
- When the alert goes away with keyboard focus inside it (the dismiss button, or an action that closes
  it), focus moves to the next focusable element in the page, or the previous one if there is none,
  rather than dropping to the top of the document.
- The hook stores only a timestamp, under `dbm-dismissed:<key>`, in the browser's own storage. Whether
  that needs a reader's consent depends on where your readers are; decide that for your own site.

## Accessibility

<Callout tone="info" title="A live region that follows the tone, with a dismiss button that keeps focus in the page">

The alert carries `role="alert"` for `danger` and `warning`, which interrupts a screen reader, and
`role="status"` for `info`, `success` and `neutral`, which waits for a pause; `role` overrides either,
including `"none"` for a plain, unannounced block. An alert that is already on the page when it loads
should be `"none"`, since it isn't news. The icon is hidden from assistive technology, so the message
must be in the text. `aria-label`, `aria-labelledby` and `aria-describedby` are passed through for an
alert that needs a name of its own.

The dismiss button is a real `<button>` named by `labels.dismiss` ("Dismiss"), and is at least 24 × 24
CSS pixels at every size. Removing a focused
control drops focus to the top of the document, so when the alert leaves with focus inside it, focus
moves to the nearest focusable element outside it (the next, else the previous).

| Key | Behaviour |
|---|---|
| `Tab` | Moves through the alert's own actions and its dismiss button, in reading order |
| `Enter` / `Space` | Activates the focused button or link, including the dismiss button |

**Contrast**, measured in light and dark. Text in the `"subtle"` variant sits on the tone's tint:
`text.primary` is 13.46–13.56:1 in light and 9.66–17.59:1 in dark, and the description's
`text.secondary` is 6.56–6.61:1 in light and 7.47–13.61:1 in dark. The tone's icon on the tint is
4.51–6.22:1 in light and 5.86–10.68:1 in dark, and at least 4.0:1 under the dismiss button's hover
fill. In `"solid"`, the text on the fill is 4.70–6.50:1 in light and 8.19–8.22:1 in dark, and
6.88–9.56:1 and 10.32–10.68:1 while the dismiss button is hovered. In `"outlined"`, the border is the
tone's state-identifying border colour (4.70:1 or more against the surface). The focus ring is
`border.focus` on the first two variants (3.56–8.44:1 against the tints across both brands and both
modes), and the on-fill icon colour on `"solid"` (4.70–8.22:1), where `border.focus` would be unreadable.

**The actions** are chosen so that each reads against the alert around it. On a `"solid"` alert: the
primary's label on its fill is 4.71–6.88:1 in light and 8.19–10.47:1 in dark, its edge against the
alert 4.70–6.50:1 and 8.19–8.22:1; the secondary's outline and label, and the tertiary's label, are
4.70–6.50:1 and 8.19–8.22:1. On a `"subtle"` alert: the primary's label is 4.70–6.50:1 and 8.19–8.22:1
and its edge against the tint 4.51–6.22:1 and 5.86–10.68:1; the secondary's border is 4.51:1 or more in
light and 4.34:1 or more in dark, and the secondary's and tertiary's tone-coloured label is 4.51–6.59:1 in
light and 7.47–10.68:1 in dark (the `info` label on the `info` tint is 4.5068:1, the tightest margin in the
system). On an `"outlined"` alert: the primary's edge is 4.70–6.50:1 and 7.94–8.42:1, the secondary's
border 4.70:1 or more and 6.08:1 or more, and the labels 4.71–6.88:1 and 7.94–10.47:1. A test measures every combination from the
colours the browser draws — every tone, variant and action — in light, dark and Emerald. While an
action is hovered the label stays at 4.51:1 or more in light and 7.47:1 or more in dark; on a subtle
alert the secondary and tertiary hover fill is the page surface rather than the tone's hover tint, since a
tone label on that tint falls to 4.15:1 for `info` in light mode. The focus ring
on an action is the on-fill colour on `"solid"` and `border.focus` on the rest.

**Motion**: dismissing fades the alert and collapses its row away. An alert that appears after the page has
loaded fades and slides in; one already in the page when it loads does not animate. With
`prefers-reduced-motion` both are instant. A live region announces a message when it is inserted, so the
entrance changes nothing for a screen reader.

</Callout>

## Code examples

```tsx
<Alert tone="danger" dismissible>
  <Alert.Title>Payment failed</Alert.Title>
  <Alert.Description>Your card was declined. Update it to keep your plan.</Alert.Description>
  <Alert.Actions>
    <Button size="sm">Update card</Button>
  </Alert.Actions>
</Alert>

{/* A whole-page announcement that stays at the top, and stays dismissed */}
function Announcement() {
  const { ready, dismissed, dismiss } = usePersistentDismiss("summer-sale-2027", { expiresAfter: 7 * 24 * 60 * 60 * 1000 });
  return (
    <Alert banner sticky dismissible open={ready && !dismissed} onOpenChange={(open) => !open && dismiss()}>
      <Alert.Description>Summer sale ends Sunday.</Alert.Description>
    </Alert>
  );
}

{/* Controlled */}
<Alert dismissible open={open} onOpenChange={setOpen}>{/* ... */}</Alert>

{/* A banner: actions beside the message, and an announcement centred */}
<Alert banner align="center" actionsPlacement="inline" dismissible>
  <Alert.Description>Summer sale: 20% off everything until Sunday.</Alert.Description>
  <Alert.Actions>
    <Alert.Action>Shop now</Alert.Action>
  </Alert.Actions>
</Alert>

{/* Actions: a Button that takes the alert's colours and size */}
<Alert tone="warning" variant="solid">
  <Alert.Description>Your trial ends in three days.</Alert.Description>
  <Alert.Actions>
    <Alert.Action>Add a payment method</Alert.Action>
    <Alert.Action variant="tertiary" asChild><a href="/pricing">See plans</a></Alert.Action>
  </Alert.Actions>
</Alert>

{/* A heading as the title, and no announcement for a message already on the page */}
<Alert tone="warning" role="none">
  <Alert.Title asChild><h2>Your trial ends soon</h2></Alert.Title>
</Alert>

{/* A native <div> attribute on Alert, passed straight through */}
<Alert onClick={() => track("alert-click")}>Your session will expire soon.</Alert>
```
