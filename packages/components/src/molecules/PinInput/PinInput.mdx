<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="PinInput" tier="Molecule" />

A field for a short code — a one-time code sent by text message, a verification code, a PIN — drawn as one
cell for each character. It is a single real `<input>` lying invisibly over the cells, so a code that arrives by
text message can be autofilled, a pasted code fills the cells, a screen reader finds one field with one name, and a
surrounding `<form>` submits the code under `name` as one string. Typing fills the cells in order and overwrites the
character in the cell you are on; the arrow keys, Home and End move between cells; pressing a cell moves to it.

### Import

```tsx
import { PinInput } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `onComplete` to submit or verify as soon as the last cell fills, so there is no button to press for a code
  that people expect to be checked on its own.
- Give the field a name: a visible `FieldLabel` (or a `FormField`), or `aria-label` when the surrounding text
  already says what the code is.
- Keep `autoComplete="one-time-code"` (the default) for a code sent by text message, so a phone can offer it.
- Use `mask` for a PIN or a secret, and `revealable` so a person can check what they typed.
- Say what went wrong near the field when a code is rejected, with `hasError` and an error message.
- Set `isLoading` from `onComplete` until your request answers, so a code being checked can't be typed over.
- Use `transform="uppercase"` for a code that is shown in capitals but entered either way.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for a long string, a password or a free-text answer — `Input` and `PasswordInput` are for those.
  A code is short and a fixed length.
- Don't use `mask` for a code that arrives by text message: the person can't check a masked code against the
  message.
- Don't rely on the placeholder to say what to type; it is decorative and is not read out.
- Don't put the cells in separate inputs of your own — one field is what makes autofill, paste and screen readers
  work.

</Callout>
</div>

## Best practices

- Match `length` to what you actually send; a six-digit code is the most familiar, four for a PIN.
- Use `groups` for a code people read aloud or copy from a message in chunks (`[3, 3]`), and `type="alphanumeric"`
  for an invite code that mixes letters and digits.
- Pasting is forgiving by design: spaces and dashes are dropped, so `482-916` and `482 916` both fill six cells.
- A code stays left to right in a right-to-left page, the way a phone number does.
- On a narrow screen the cells shrink together and stay square rather than overflowing; set `size` to suit the
  space you have.
- Keep the value in your own state (`value` / `onValueChange`) when a sibling needs it, for example a "Resend code"
  button that clears the field.

## Accessibility

<Callout tone="info" title="One real, labelled text field, with the cells drawn from it">

- The field is a single native `<input>`, so it has one tab stop, one accessible name and one value for a screen
  reader to read; the cells are decorative and hidden from assistive technology.
- Name it with `aria-label`, `aria-labelledby`, or a `FieldLabel` whose `htmlFor` points at its `id` (a
  `FormField` does this for you).
- Left and Right move one cell, Home and End go to the first cell and the first empty one, Backspace deletes, and
  a typed character overwrites the character in the cell you are on. Shift and the other modifier keys keep their
  native selection behaviour.
- Tabbing in lands on the first empty cell; pressing a cell moves to it.
- `hasError` sets `aria-invalid`. `required` and a minimum length of `length` are real form constraints, so a
  `<form>` stops a submit with a missing or short code.
- A masked code is a password-type field, so a screen reader announces bullets instead of the characters; the show
  button is a toggle (`aria-pressed`) with its own name.
- The active cell and the caret use outlines and text, which stay visible in Windows high-contrast mode.
- The caret stops blinking, and the cells stop shaking when an error appears, when the person has asked for
  reduced motion. An error is never shown by the shake or the border colour alone: `aria-invalid` is set, and the
  error message you show beside the field says what is wrong.
- While `isLoading`, the field is set aside from editing without being disabled (it keeps focus and its value),
  `aria-busy` is set, and a status message ("Verifying code", translatable through `labels`) is announced.
- The field's text is at least 16px, so iOS does not zoom the page when it takes focus.

</Callout>

| Key | Behaviour |
|---|---|
| Characters | Fill the cells in order, overwriting the character in the active cell. Characters the `type` does not accept are dropped. |
| Left, Right | Move to the previous or next cell, never past the first empty one. |
| Home, End | Move to the first cell, or the first empty cell. |
| Backspace | Delete the active cell's character, or the last character from the first empty cell. |
| Shift + arrows, Ctrl or Cmd + A | Select several cells, as in any text field. |
| Paste | Fills the cells from the cleaned-up text. |

## Code examples

```tsx
<PinInput aria-label="Verification code" onComplete={verify} />

{/* A four-digit PIN that can be shown */}
<PinInput aria-label="PIN" length={4} mask revealable />

{/* Checking a code over the network */}
<PinInput aria-label="Verification code" isLoading={checking} hasError={rejected} onComplete={verify} />

{/* Entered either way, kept in capitals */}
<PinInput aria-label="Invite code" type="alphanumeric" transform="uppercase" length={6} />

{/* Read in two chunks, letters and digits */}
<PinInput aria-label="Invite code" type="alphanumeric" groups={[3, 3]} />

{/* Submitted with a form, under `otp`, as one string */}
<form onSubmit={handleSubmit}>
  <PinInput aria-label="Verification code" name="otp" required />
</form>

{/* Controlled, with a field-level native attribute */}
<PinInput aria-label="Verification code" value={code} onValueChange={setCode} form="verify-form" />

{/* With a label and helper text; the wiring is done for you */}
<FormField label="Verification code" helperText="We sent a 6-digit code to your phone.">
  {(fieldProps) => <PinInput {...fieldProps} />}
</FormField>
```
