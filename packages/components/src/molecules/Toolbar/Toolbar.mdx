<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Toolbar" tier="Molecule" />

A bar of actions that is a single tab stop. `Tab` moves focus into the toolbar and out again; the arrow keys,
`Home` and `End` move between its items — left and right for a row, up and down for a column. It is a named
`role="toolbar"` built on Radix `Toolbar`, and it hands its `itemVariant`, `size`, `rounded` and `disabled` to the
`Toolbar.Button`s and `Toolbar.IconButton`s inside it as defaults, so a bar of ten says them once. An item's own
props still win.

Use it for a cluster of commands acting on one thing — an editor's formatting bar, a canvas's tools, a row of
table actions — where reaching every command with `Tab` would be tedious. For actions that are only visually
grouped, with no change to how the keyboard moves, use a `ButtonGroup`; for choosing one option from several, a
`ToggleGroup`.

### Import

```tsx
import { Toolbar } from "@dbm-design-system/components";
```

## Properties

`Toolbar` also accepts any other native `<div>` attribute beyond what's listed here (e.g. `onFocus`, `title`) —
passed straight through to the underlying element.

<PropertiesTable of={ToolbarStories} order={propOrder} />

The parts of a toolbar:

- **`Toolbar.Button`** is a `Button` in the arrow-key order. **`Toolbar.IconButton`** is an `IconButton`, taking every
  `IconButton` prop, including `pressed` for a toggle and `tooltip` for a label on hover and focus. Their `variant`,
  `size`, `rounded` and `disabled` default to the toolbar's.
- **`Toolbar.ToggleGroup`** and **`Toolbar.ToggleItem`** are a `ToggleGroup` and its `ToggleGroup.Item`s in the arrow-key
  order, for choosing one option (alignment) or several (text style). They take every `ToggleGroup` prop except `loop` and
  `rovingFocus`, which the toolbar owns; `size`, `rounded`, `disabled`, `orientation` and `dir` default to the toolbar's.
- **`Toolbar.Item`** puts any other single focusable element in the order: a `Select`, a popover or menu trigger, a link.
- **`Toolbar.Group`** is a named cluster; **`Toolbar.Separator`** is a line between items, across the bar's own direction,
  announced as a separator (it takes `className`, `style`, `id` and `data-testid`); **`Toolbar.Spacer`** is flexible empty
  space that pushes whatever follows it to the far end, hidden from assistive tech (it takes the `Spacer` props).

## Variants

### Bar variants

`variant` is how the bar itself is drawn: no surface of its own (`ghost`), a bordered bar (`outlined`) or a tinted
one (`filled`). A ghost bar has no padding, so its items line up with whatever sits beside it.

<Canvas of={ToolbarStories.Variants} />

### Item variants

`itemVariant` is every item's default look. `ghost` keeps a row of icon buttons quiet; `secondary` or `primary` suit a
bar of labelled actions.

<Canvas of={ToolbarStories.ItemVariants} />

### All sizes

`size` sets the bar's padding and gaps and every item's default size.

<Canvas of={ToolbarStories.AllSizes} />

<Canvas of={ToolbarStories.Rounded} />

### Groups and separators

A `Toolbar.Group` is a named cluster that screen readers announce on entry; a `Toolbar.Separator` draws the rule
between clusters. The arrow keys move through every item in order, across groups.

<Canvas of={ToolbarStories.Groups} />

### With a spacer

A `Toolbar.Spacer` takes the free space, so the bar needs more room than its items do: set `fullWidth`, or give the bar a
width of its own.

<Canvas of={ToolbarStories.WithSpacer} />

### Aligning the items

When the bar is wider than its items — it has `fullWidth`, or a width of its own — `align` puts them at the `start`
(the default), the `center` or the `end`. It follows the reading direction, so `start` is the right edge on a
right-to-left page. To split the items instead, with some at each end, put a `Toolbar.Spacer` between them: it takes
the free space, so `align` has nothing left to do.

<Canvas of={ToolbarStories.Align} />

### Attached groups

`Toolbar.Group attached` fuses a group's buttons into one segmented control, as a `ButtonGroup` does, while each stays in
the toolbar's arrow-key order. A group without it keeps its items apart.

<Canvas of={ToolbarStories.AttachedGroup} />

### Single and multiple choice

A `Toolbar.ToggleGroup` is a choice that is part of the bar: one option out of several (a `radiogroup`, where an arrow
key also chooses the item it lands on) or independent toggles (`type="multiple"`, a plain `group`). Its items are
`Toolbar.ToggleItem`s. Unlike a `ToggleGroup` placed in a toolbar directly, it doesn't add a tab stop of its own: the
arrow keys of the toolbar run straight through it.

<Canvas of={ToolbarStories.ToggleGroups} />

### Toggle buttons

A `Toolbar.IconButton` with `pressed` (or `defaultPressed`) is a toggle: its state is announced with `aria-pressed`
and drawn with a filled icon. Control it with `pressed` and `onPressedChange`.

<Canvas of={ToolbarStories.Toggles} />

<Canvas of={ToolbarStories.Vertical} />

### A column on a phone, a row from md up

`orientation` also takes a mobile-first map keyed by breakpoint. The arrow keys that move between items follow
whichever layout is showing.

<Canvas of={ToolbarStories.ResponsiveOrientation} />

### Wrapping onto more lines

When there are more items than fit, `overflow` decides what happens. `visible` (the default) lets the bar overflow its
container. `wrap` wraps a horizontal bar's items onto more lines; the arrow keys still follow the order the items are
written in.

<Canvas of={ToolbarStories.Wrapping} />

### Scrolling in one line

`overflow="scroll"` keeps one line and scrolls it. An edge fade and a button show at whichever end has more; the buttons
are for a pointer (they are not in the tab order and are hidden from assistive tech), and the arrow keys scroll the item
that takes focus into view. A trackpad or a swipe scrolls it too.

<Canvas of={ToolbarStories.Scrolling} />

### Scrolling in a column

A vertical bar scrolls the same way once it has a height of its own to respond to — here a container 10rem tall.

<Canvas of={ToolbarStories.ScrollingColumn} />

### Sticky

`sticky` keeps the bar at the top of the page as the reader scrolls, with a surface behind it and a shadow while it is
stuck. It is built on `Affix`, like `Alert`'s `sticky`: `scrollContainerRef` names the box that scrolls when it isn't the
page (here, the framed box), and `stickyOffset` leaves room for a header that is sticky too.

<Canvas of={ToolbarStories.Sticky} />

### Disabled

A disabled item can't be focused, so the arrow keys skip it. `disabled` on the toolbar disables every item.

<Canvas of={ToolbarStories.Disabled} />

### Icon buttons with tooltips

`tooltip` on a `Toolbar.IconButton` shows its name on hover and keyboard focus (`true` uses the `aria-label`; any other
content is shown instead), so the three-line `Tooltip` wrapper isn't needed.

<Canvas of={ToolbarStories.WithTooltips} />

### A select and a popover

`Toolbar.Item` puts a `Select`, or a popover or menu trigger, into the arrow-key order. `Enter` or `Space` opens it,
`Escape` (or choosing an option) gives focus back to it, and the arrow keys carry on along the bar. In a vertical bar a
`Select`'s own `ArrowUp` and `ArrowDown` open its list instead of moving along the bar.

<Canvas of={ToolbarStories.WithSelectAndPopover} />

### Wrapped in a tooltip, or a link

A `Tooltip` wraps a toolbar item as it would a button. `Toolbar.Item` puts any other single focusable element — a link,
a menu or popover trigger — into the arrow-key order.

<Canvas of={ToolbarStories.Wrapped} />

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use a toolbar for several commands that act on the same thing and are used together — formatting, tools, view controls.
- Give it a name (`aria-label`, or `aria-labelledby` pointing at a visible label), and name each `Toolbar.Group` too.
- Build it from `Toolbar.Button`, `Toolbar.IconButton`, `Toolbar.ToggleGroup` and `Toolbar.Item`, so every command is in the arrow-key order.
- Give each `IconButton` an `aria-label`, and add a `Tooltip` where an icon alone is not clear.
- Say `itemVariant` and `size` once on the toolbar, and override only the odd item out.
- Keep a toolbar short — a handful to a dozen items — and group related commands with separators.

</Callout>
<Callout tone="danger" title="Don't">

- Don't put a text field, or anything else that needs the left and right arrow keys itself, into a toolbar: the toolbar takes them for moving between items. A `Select` or a popover trigger is fine in a row; in a column the `Select` takes up and down for its own list.
- Don't use a toolbar for navigation or for a list of unrelated actions; it is one tab stop, so a command inside it is
  harder to discover than one that is a tab stop of its own.
- Don't put a plain `Button` in a toolbar and expect the arrow keys to reach it: only `Toolbar.Button`,
  `Toolbar.IconButton` and `Toolbar.Item` are in the order.
- Don't put a plain `ToggleGroup` in a toolbar to choose among options: it is a tab stop of its own. Use `Toolbar.ToggleGroup`.
- Don't hide the only way to do something in a toolbar item that is disabled with no explanation.

</Callout>
</div>

## Best practices

- Put the commands people use most first: focus lands on the first item when someone tabs in, and returns to the last one
  they used when they tab back.
- Prefer `ghost` items on a ghost or filled bar and `secondary` on an outlined one, and keep `primary` for the one command
  the bar exists for — usually last, pushed to the end with a `Toolbar.Spacer`.
- Stack a long bar on a phone with an `orientation` map, or give it an `overflow` of `wrap` or `scroll`, rather than letting it overflow its container.
- Use `sticky` for a bar that has to stay in reach of a long page or editor, and give the scrolling box to `scrollContainerRef` when the page itself isn't what scrolls.
- Give an icon button a `tooltip` where the icon alone is not clear — it also shows on keyboard focus.
- Keep related toggles together in a `Toolbar.Group`, and set each one's `pressed` from the state it controls so the bar
  always shows what is on.
- A toolbar is a surface for commands, not a layout: don't nest one inside another, or put them in a table cell.

## Accessibility

<Callout tone="info" title="One tab stop, arrow keys inside">

- Renders `role="toolbar"` with `aria-orientation`, named by `aria-label` or `aria-labelledby`. A dev-mode console warning
  fires once if it has neither, and once for a `Toolbar.Group` with neither.
- It is a single tab stop (a roving tab index): `Tab` enters it on the item that last had focus (the first, the first time)
  and the next `Tab` leaves it. Inside, the **Right** and **Left** arrows move through a row, **Down** and **Up** through a
  column, and **Home** and **End** go to the first and last item. By default they wrap at the ends (`loop={false}` stops
  there). `Enter` and `Space` press an item.
- In a right-to-left page pass `dir="rtl"`: Radix doesn't read the page, so without it Left would still go backwards.
- A `Toolbar.ToggleGroup` adds no tab stop of its own (the toolbar owns focus; the group turns its own roving focus off): single is a `radiogroup` of `radio` items, with `aria-checked`, where an arrow key also chooses the item it lands on, and multiple is a plain `group` of toggle buttons with `aria-pressed` — not a `toolbar` inside a toolbar.
- A `Select` or popover trigger in `Toolbar.Item` keeps its own keyboard behaviour: it opens with `Enter` or `Space`, and focus returns to it when it closes.
- With `overflow="scroll"` the scroll buttons are `aria-hidden` and out of the tab order (the arrow keys already move along the bar and the browser scrolls the focused item into view, kept clear of the edge fade), so a keyboard or screen reader user meets the same one tab stop. The focus ring is drawn inside each item there, since a scrolling box would cut off a ring drawn outside it.
- A `tooltip` on an icon button opens on hover and keyboard focus and closes with `Escape`; the button is named by its `aria-label`, so the tooltip is never the only name.
- A disabled item is not focusable, so the arrow keys skip it; the toolbar's `disabled` disables every item natively.
- A toggle (`pressed`) is announced with `aria-pressed`; its pressed look is a filled icon as well as a colour, so the state
  is never colour alone.
- A `Toolbar.Group` is a named `role="group"`; a `Toolbar.Separator` is announced as a separator, with its orientation
  across the bar's own; a `Toolbar.Spacer` is hidden from assistive tech.
- Every item is at least 24 × 24px (WCAG 2.5.8), at every size, and keeps its own focus ring. The separator is decoration:
  each item is identified by its label, not by the line between items.
- Radix handles the focus movement; the toolbar adds no key handling of its own. A text field inside needs the arrow keys
  and would lose them, so keep fields out of a toolbar.

</Callout>

## Code examples

```tsx
<Toolbar aria-label="Text formatting" variant="outlined">
  <Toolbar.Group aria-label="Text style" attached>
    <Toolbar.IconButton icon={TextBIcon} aria-label="Bold" tooltip pressed={bold} onPressedChange={setBold} />
    <Toolbar.IconButton icon={TextItalicIcon} aria-label="Italic" tooltip />
  </Toolbar.Group>
  <Toolbar.Separator />
  <Toolbar.ToggleGroup aria-label="Alignment" defaultValue="left">
    <Toolbar.ToggleItem value="left" icon={TextAlignLeftIcon} aria-label="Align left" />
    <Toolbar.ToggleItem value="center" icon={TextAlignCenterIcon} aria-label="Align centre" />
  </Toolbar.ToggleGroup>
  <Toolbar.Separator />
  <Toolbar.Button leadingIcon={LinkIcon}>Link</Toolbar.Button>
  <Toolbar.Spacer />
  <Toolbar.Button variant="primary">Save</Toolbar.Button>
</Toolbar>

<Toolbar aria-label="Tools" orientation="vertical">…</Toolbar>
<Toolbar aria-label="Actions" orientation={{ base: "vertical", md: "horizontal" }}>…</Toolbar>
<Toolbar aria-label="Actions" itemVariant="secondary" size="sm" rounded overflow="wrap">…</Toolbar>
<Toolbar aria-label="Actions" overflow="scroll">…</Toolbar>
<Toolbar aria-label="Editor" sticky stickyOffset={4} scrollContainerRef={panelRef}>…</Toolbar>
<Toolbar aria-label="Document" fullWidth align="end">…</Toolbar>
<Toolbar aria-label="Document" disabled>…</Toolbar>
<Toolbar aria-label="Text formatting" dir="rtl">…</Toolbar>
<Toolbar aria-label="Document" onFocus={() => trackFocus("document")}>…</Toolbar>

{/* A tooltip wraps an item as it would a button; Toolbar.Item takes any other focusable element */}
<Tooltip content="Make it bold">
  <Toolbar.IconButton icon={TextBIcon} aria-label="Bold" />
</Tooltip>
<Toolbar.Item>
  <Button variant="ghost" asChild>
    <a href="/docs">Docs</a>
  </Button>
</Toolbar.Item>

{/* A visible label names the toolbar */}
<span id="format-label">Formatting</span>
<Toolbar aria-labelledby="format-label">…</Toolbar>
```
