<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Breadcrumb" tier="Molecule" />

A breadcrumb trail shows where the current page sits in a site — the path from the top down to the
page a reader is on, as a row of links ending in the page itself. A compound component: put one
`Breadcrumb.Item` per level inside `Breadcrumb`, each holding a `Breadcrumb.Link` (or, for the last
one, `Breadcrumb.Page`). It renders a `<nav>` around an ordered list, and draws the separators
between items itself.

Choose how big the trail is with `size`, the colour of its links with `tone`, whether they are
underlined all the time with `underline`, and what sits between items with `separator`. A trail that
is too wide for its container wraps onto more lines; with `maxItems`, its middle collapses into a
"…" button that shows the rest when used — a fixed number of items, or, with `"container"`, only as
many as it takes to fit. `compact` swaps the whole trail for a single "back to the parent page" link
(on a phone, or always), and `truncate` keeps the trail on one line and cuts long labels short. `Breadcrumb.Link` is the `Link` atom underneath, so it
handles external addresses and `disabled`, and takes `asChild` to render a router's own link.

### Import

```tsx
import { Breadcrumb } from "@dbm-design-system/components";
```

## Properties

Every part reads `size` and `separator` from `Breadcrumb`, so they are set once, on the root. `ref`
forwards to the `<nav>`. Also accepts any other native `<nav>` attribute beyond what's listed here
(e.g. `onFocus`, `title`) — passed straight through to the root element.

<PropertiesTable of={BreadcrumbStories} order={rootPropOrder} />

Only `Breadcrumb.Item` elements are rendered: a fragment, or plain text, placed among the children is
ignored (with a warning in development), so build the list from items directly rather than wrapping
several in a fragment. Give each item a `key` — its `href` will do. When the items change (a route
change, in a layout that keeps the breadcrumb mounted), the trail starts over: collapsed again if it
is long, instead of staying expanded from the last page. Items with no `key` of their own can only be
told apart by position.

### Breadcrumb.Item properties

One level of the trail — the `<li>`. It draws the separator after its content, except when it is the
last item. Also accepts any other native `<li>` attribute beyond what's listed here (e.g. `title`) —
passed straight through to the underlying element.

<PropertiesTable of={BreadcrumbItemStories} order={itemPropOrder} />

### Breadcrumb.Link properties

A link to a page above the current one. It is the `Link` atom, so it also takes `external`,
`disabled`, `asChild` and the native anchor props. Also accepts any other native `<a>` attribute
beyond what's listed here (e.g. `onClick`, `title`) — passed straight through.

<PropertiesTable of={BreadcrumbLinkStories} order={linkPropOrder} />

### Breadcrumb.Page properties

The current page: plain text marked `aria-current="page"`, so a screen reader announces it as the
current page. Also accepts any other native `<span>` attribute beyond what's listed here (e.g.
`title`) — passed straight through to the underlying element.

## Variants

### All sizes

<Canvas of={BreadcrumbStories.Sizes} />

### Tones

`tone` sets the colour of every link in the trail: `"info"` (the default) is the standard link
colour, `"brand"` follows the active brand theme, and `"neutral"` is quiet secondary text. The current
page is always primary text. On hover, a `"brand"` or `"info"` link keeps its colour and gains an
underline in that same colour; a `"neutral"` link darkens to the primary text colour, and gains one.

<Canvas of={BreadcrumbStories.Tones} />

### Underlined links

By default a link is underlined only while hovered. `underline` keeps every link underlined at rest
too, in the link's own colour — worth turning on where colour alone is a weak cue, such as a trail set
right next to body text.

<Canvas of={BreadcrumbStories.Underline} />

### Separators

`"chevron"` is the default and points along the reading direction, so it flips under right-to-left
text. Anything other than the two named values — a short string, or an element — is drawn as given.

<Canvas of={BreadcrumbStories.Separators} />

### With icons

An icon before the text of a link, or of the current page. It is decorative, so the item keeps its
text.

<Canvas of={BreadcrumbStories.WithIcons} />

### Collapsed with maxItems

With more items than `maxItems`, the middle ones are replaced by a "…" button. By default the first
item and the last two stay visible. Use the button to reveal the rest — keyboard focus moves to the
first item it revealed.

<Canvas of={BreadcrumbStories.Collapsed} />

### Collapsing to fit the width

`maxItems="container"` collapses only as many items as it takes for the trail to fit its own width,
and measures again whenever that width changes. Drag the bottom-right corner of the box: items give
way one at a time, and come back as it widens. It is measured in the browser, so a server-rendered
page shows the full trail until the page loads. The first item, the "…" button and the last two
items stay (by default — `itemsBeforeCollapse` and `itemsAfterCollapse` choose); once the trail can collapse no further it wraps (or, with `truncate`, cuts labels
short). A collapse is held back while keyboard focus is on an item it would hide, so focus is never
dropped — the trail catches up as soon as focus moves.

<Canvas of={BreadcrumbStories.ContainerCollapse} />

### Choosing what stays visible

`itemsBeforeCollapse` and `itemsAfterCollapse` set how many items stay on each side of the button.
The last item, the current page, always stays.

<Canvas of={BreadcrumbStories.CollapseWindow} />

### Compact — back to the parent

`compact` swaps the trail for one link: the item just above the current page, with a back arrow
before it. `"auto"` does it on a phone-width screen (below the `sm` breakpoint) and shows the full
trail from there up; `"always"` does it at every width. A trail of one item has no parent, so it always
shows in full. The compact form replaces everything else — `maxItems` included — and the parent is
never collapsed away.

<Canvas of={BreadcrumbStories.Compact} />

### Compact on a phone

Opened on its own, this story is shown at a phone's width. On this page it sits in the wide page like
every other story, so pick a phone size in the viewport toolbar to see `"auto"` switch.

<Canvas of={BreadcrumbStories.CompactOnAPhone} />

### Truncated labels

`truncate` keeps the trail on one line and cuts a label that doesn't fit short with an ellipsis; labels
give up space in proportion to their length, so the longest lose the most. Drag the bottom-right
corner of the box to change the width. The full text stays in the page for screen readers, and a
plain-text label also carries it as a tooltip (`title`). With `maxItems="container"`, items collapse
first and labels are cut short only when the trail can't collapse any further.

<Canvas of={BreadcrumbStories.Truncated} />

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use a breadcrumb on a site or app with more than two levels of pages, so a reader can jump back up
  the hierarchy in one click.
- Put the trail near the top of the page, above the page's heading, on every page it applies to.
- End it with the current page as `Breadcrumb.Page`, so the reader can see where they are.
- Give each item the same name the page has in the navigation and as its own heading.
- Use `maxItems` on a deep hierarchy, so the trail keeps to a line or two on a narrow screen —
  `"container"` when the width isn't known in advance.
- Use `compact="auto"` where a phone-width screen can't spare even a line or two for the trail.
- Name the navigation with `aria-label` when a page holds more than one breadcrumb.
- Put `"info"` and `"brand"` trails on `bg.surface`. Use `"neutral"` when a trail has to sit on
  `bg.canvas` (or on any background their colours haven't been measured against).

</Callout>
<Callout tone="danger" title="Don't">

- Don't use a breadcrumb as the main navigation, or to show the steps a reader has taken. It shows
  the site's structure, not their history — use `Tabs` or a stepper for sequences.
- Don't make the current page a link to itself; `Breadcrumb.Page` is deliberately not one.
- Don't put a breadcrumb on a top-level page with nothing above it.
- Don't add controls to an item other than the link — an item is one destination.
- Don't hide the trail on small screens; use `compact="auto"` or `maxItems` instead, so the reader still
  has a way back up.
- Don't rely on `truncate` for labels a reader needs to read whole — a cut-off word can't be read, and a
  tooltip only reaches people with a mouse. Wrapping shows every word.
- Don't use a separator that reads as content, such as a word.

</Callout>
</div>

## Best practices

- The first item is usually the home page. An icon alone is enough for it when the link has an
  `aria-label` — `<Breadcrumb.Link href="/" icon={HouseIcon} aria-label="Home" />`.
- With a client-side router, use `asChild` on `Breadcrumb.Link` to render the router's own link, so
  navigation doesn't reload the page.
- Keep labels short. A label that is much longer than its neighbours wraps onto a second line inside
  its own item, which is fine, but a trail of long labels reads better collapsed.
- A numeric `maxItems` counts every item, including the first and the current page. Neither form
  collapses unless at least two items would be hidden — replacing a single item with a button would
  help nobody.
- `compact` and `maxItems="container"` answer different questions: `compact` decides *what* a phone
  shows (one link), `"container"` decides *how many* of the trail fit. Combine them freely — the
  compact form simply takes over where it applies.
- `truncate` is for a trail that must stay on one line, such as a page header with a fixed height.
  Anywhere else, letting it wrap is the more readable choice.
- The default `"info"` tone is the same blue as a `Link` elsewhere, so a trail reads as navigation
  without a second colour to learn. Choose `"brand"` where the surrounding design already leans on the
  accent colour, and `"neutral"` where a trail should stay out of the way.
- Every piece of text the component writes itself is in `labels`, so a translated site replaces the
  whole set in one place. The "…" button's name is a function of the number of hidden items.

## Accessibility

<Callout tone="info" title="A named navigation landmark holding an ordered list, with the current page marked">

The trail is a `<nav>` — a navigation landmark, named "Breadcrumb" (or your own name, through
`labels.navigation` or `aria-label`) so a reader who lists a page's landmarks can find it. Inside is
an ordered list, so a screen reader announces how many levels there are and which one it is on. The
list and its items state their `list` and `listitem` roles outright, because Safari with VoiceOver
otherwise stops treating a list with its markers removed as one. The current page carries
`aria-current="page"`. The separators are hidden from assistive technology: the list structure
already says everything they would.

| Key | Behaviour |
|---|---|
| `Tab` | Moves to the next link — each link, and the "…" button when there is one, is one stop |
| `Shift+Tab` | Moves to the previous one |
| `Enter` | Follows the focused link, or reveals the collapsed items from the "…" button |
| `Space` | Reveals the collapsed items from the "…" button |

The compact form hides every item but the parent with `display: none`, so a screen reader hears one
link, not a list of levels; use `"auto"` (or `"never"`) where a phone reader should hear the whole
path. The link's accessible name is its own text — the back arrow is decorative. With `truncate`, the
ellipsis is only visual: a screen reader reads the full label.

Using the "…" button removes it from the page, so keyboard focus moves to the first item it
revealed rather than dropping to the top of the document. With `maxItems="container"`, a collapse
that would hide the link that has keyboard focus waits until focus has moved on. (The compact form
is a plain media query, so resizing across the `sm` breakpoint with focus on a hidden link can't hold
it back.) A disabled link stays in the tab order, marked `aria-disabled`, matching WAI-ARIA guidance.

**Contrast**, measured in light and dark. On `bg.surface`, an `"info"` link (`text.link`) is 4.71:1 in
light and 8.20:1 in dark, and a `"brand"` link (`text.brand`) is 7.37:1 (Purple) or 6.08:1 (Emerald) in
light and 7.45:1 or 6.49:1 in dark. A `"neutral"` link (`text.secondary`) is 6.88:1 and 10.47:1, and
the current page and a hovered neutral link (`text.primary`) are 14.11:1 and 13.53:1. **Place `"info"`
and `"brand"` trails on `bg.surface`, not `bg.canvas`**, where they fall under the 4.5:1 text floor
(`"info"` is 4.15:1 in light and 4.00:1 in dark there; `"brand"` is 3.63:1 and 3.16:1 in dark). A
`"neutral"` trail is 6.05:1 and 5.10:1 on the canvas, so it is the one to use there. The separators
are `icon.default`: 4.70:1 and 8.21:1 on the surface, and 4.13:1 (light) and 2.96:1 (dark) on the
canvas — a hair under 3:1 in dark mode on the canvas, which the separators are exempt from since
they are decorative and repeat what the list structure and the spacing already show.

A coloured link with no underline at rest is told apart from the current page by its colour and by
the current page's heavier weight; `underline` adds a cue that doesn't depend on colour at all.

</Callout>

## Code examples

```tsx
<Breadcrumb>
  <Breadcrumb.Item>
    <Breadcrumb.Link href="/" icon={HouseIcon}>Home</Breadcrumb.Link>
  </Breadcrumb.Item>
  <Breadcrumb.Item>
    <Breadcrumb.Link href="/products">Products</Breadcrumb.Link>
  </Breadcrumb.Item>
  <Breadcrumb.Item>
    <Breadcrumb.Page>Keyboards</Breadcrumb.Page>
  </Breadcrumb.Item>
</Breadcrumb>

{/* Built from your own data */}
<Breadcrumb>
  {trail.map((crumb, index) => (
    <Breadcrumb.Item key={crumb.href}>
      {index === trail.length - 1 ? (
        <Breadcrumb.Page>{crumb.label}</Breadcrumb.Page>
      ) : (
        <Breadcrumb.Link href={crumb.href}>{crumb.label}</Breadcrumb.Link>
      )}
    </Breadcrumb.Item>
  ))}
</Breadcrumb>

{/* Brand-coloured links, underlined all the time */}
<Breadcrumb tone="brand" underline>
  {/* ... */}
</Breadcrumb>

{/* Collapse only as many items as it takes to fit, and show one link back on a phone */}
<Breadcrumb maxItems="container" compact="auto">
  {/* ... */}
</Breadcrumb>

{/* One line, long labels cut short */}
<Breadcrumb truncate>
  {/* ... */}
</Breadcrumb>

{/* A deep trail that collapses its middle */}
<Breadcrumb maxItems={4} itemsBeforeCollapse={1} itemsAfterCollapse={2}>
  {/* ... */}
</Breadcrumb>

{/* With a router: the router's own link carries the navigation */}
<Breadcrumb.Link asChild href="/products">
  <RouterLink to="/products">Products</RouterLink>
</Breadcrumb.Link>

{/* Translated */}
<Breadcrumb
  labels={{ navigation: "Fil d'Ariane", expand: (count) => `Afficher ${count} pages masquées` }}
  maxItems={4}
>
  {/* ... */}
</Breadcrumb>

{/* A native <a> attribute on Breadcrumb.Link, passed straight through */}
<Breadcrumb.Link href="/products" onClick={() => track("breadcrumb-products")}>Products</Breadcrumb.Link>
```
