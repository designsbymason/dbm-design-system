<ComponentHeader title="Slider" tier="Molecule" />

A single-value slider built on Radix UI's Slider primitive, with a token-driven track, filled
range, and thumb. Accepts both controlled (`value`/`onValueChange`) and uncontrolled
(`defaultValue`) usage — as a plain number, not the array the underlying primitive uses internally
(that shape only matters once a slider has more than one thumb). `onValueCommit` fires once, on
release, distinct from `onValueChange`'s continuous firing while dragging or stepping.

### Import

```tsx
import { Slider } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Reach for `onValueCommit` for anything expensive that should only run once the user settles on a
  value (a network request, an expensive filter) — `onValueChange` fires continuously while
  dragging and is the wrong hook for that.
- Pass `aria-label` (or `aria-labelledby`) — this component has no built-in visible-label slot of
  its own, so one of the two is required for the slider to be announced correctly.
- Set an explicit `height` via `style` whenever `orientation="vertical"` — a vertical slider has no
  intrinsic height, matching the underlying Radix primitive's own documented requirement.

</Callout>
<Callout tone="danger" title="Don't">

- Don't drive `value` from a live control without a real `onValueChange` wired back — Radix always
  defers to the controlled value, which freezes the slider's own drag/keyboard handling.
- Don't reach for `onValueChange` as your only hook if the resulting action is expensive — pair it
  with `onValueCommit` instead, or you'll re-run that action on every pixel of drag movement.
- Don't assume the numeric value alone is enough context for assistive tech on a non-obvious scale
  (e.g. a 1–5 rating) — set `aria-valuetext` with a human-readable equivalent instead.

</Callout>
</div>

## Best practices

- Match `size` to the surrounding layout's density, same as `Input`'s own guidance.
- Keep `step` a "round" value relative to the value's own natural granularity — an oddly precise
  step is confusing to move through via the keyboard.
- Pair with `FieldHelperText` to state the valid range in plain language when `min`/`max` aren't
  self-evident from context (e.g. "Between 0 and 100").
- Turn on `showValue` when no other on-screen element already reflects the current value — it's a
  purely visual convenience for sighted users, since the value is already exposed to assistive tech
  via `aria-valuenow` regardless of whether it's shown.

## Accessibility

<Callout tone="info" title="Keyboard and ARIA state come from Radix's own slider primitive">

- Renders a `role="slider"` element (not a native `<input type="range">`) — `Tab` focuses it, and
  arrow keys (or Page Up/Down, Home/End) change the value, per the WAI-ARIA slider pattern.
- `aria-valuenow`/`aria-valuemin`/`aria-valuemax` reflect the real state directly, kept in sync with
  the visible thumb position automatically. `aria-valuetext`, when set, is announced instead of the
  raw number.
- `aria-invalid="true"` is set automatically while `hasError`, in addition to the visual danger
  ring and thumb outline — the two can't drift out of sync.
- A dev-mode console warning fires once if a `Slider` has no `aria-label` or `aria-labelledby` — a
  slider with no accessible name is invisible to screen reader users.
- A `disabled` slider is skipped by `Tab` entirely and ignores both pointer drag and keyboard
  input — not just visually dimmed while remaining reachable.
- `name` renders a hidden native input for real form submission when the slider sits inside an
  actual `<form>` (or `form` is set) — the same mechanism `Switch`'s own `name` documents, though
  Slider's hidden input carries no `type="range"` semantics of its own; it exists purely for
  form-data participation.
- The unfilled track (`bg.track`) and filled range (`bg.brand`) are both checked against real WCAG
  contrast ratios, not assumed — see [Design tokens used](#design-tokens-used) below.

</Callout>

## Code examples

```tsx
<Slider aria-label="Volume" defaultValue={50} />
<Slider aria-label="Brightness" value={value} onValueChange={setValue} min={0} max={10} />
<Slider aria-label="Price" onValueCommit={runExpensiveFilter} showValue />
<Slider aria-label="Opacity" orientation="vertical" style={{ height: "12rem" }} />
<Slider aria-label="Quality" defaultValue={2} min={1} max={3} aria-valuetext="Medium" />
<Slider aria-label="Volume" onFocus={() => trackFieldFocus("volume")} />

{/* Composed inside a FormField for the label/helper-text wiring — see that
    component's own Docs page for the full pattern. */}
<FormField label="Volume" helperText="Between 0 and 100">
  {(fieldProps) => <Slider {...fieldProps} />}
</FormField>
```
