<ComponentHeader title="NumberInput" tier="Molecule" />

A number input with increment/decrement stepper buttons, wrapping `Input`. Works with real numbers
throughout — `value`/`defaultValue`/`onValueChange` are all typed `number`, not strings you parse
yourself — while the raw native `onChange` (string-based, firing only on direct typing) stays
available for anyone who needs it. `min`/`max` bound the stepper buttons (each disables once the
value reaches that edge) and pass straight through as real native HTML5 validation attributes;
typing itself isn't force-clamped, matching a native `<input type="number">`'s own unopinionated
behavior — only the stepper buttons clamp.

### Import

```tsx
import { NumberInput } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Reach for `onValueChange` first — it fires the same way regardless of whether the value changed
  by typing, a stepper click, or the clear button, and it hands you a real number (or `undefined`),
  not a string to parse.
- Set `min`/`max` whenever the value has a real domain floor/ceiling — they give you free HTML5
  validation and stop the stepper buttons at the right edge, both at once.
- Set `step` to match the value's own natural granularity (`0.5`, `0.25`, `5`) — the stepper always
  rounds away floating-point drift for you, so a decimal step stays clean after repeated clicks.

</Callout>
<Callout tone="danger" title="Don't">

- Don't pass `type` or `suffix` — neither is exposed. `type` is fixed to `"number"` internally, and
  `suffix` is reserved for the stepper buttons themselves.
- Don't expect typing an out-of-range value to be force-corrected live — only the stepper buttons
  clamp to `min`/`max`; typing relies on native HTML5 validation instead, same as a plain
  `<input type="number">`.
- Don't reach for `onChange` as your primary handler — its string value needs your own parsing, and
  it never fires for stepper-button or clear-button changes at all. Use `onValueChange` unless you
  specifically need the raw native event.

</Callout>
</div>

## Best practices

- Match `size` to the surrounding form's density, same as `Input`'s own guidance.
- Keep `step` a "round" value relative to the field's own meaning (whole units for a quantity,
  `0.01` for currency) — an oddly precise step (like `0.3`) is confusing to click through.
- Pair with `FieldHelperText` to state the valid range in plain language when `min`/`max` aren't
  self-evident from context (e.g. "Between 1 and 99").

## Accessibility

<Callout tone="info" title="Real stepper buttons, native HTML5 validation underneath">

- Renders a real native `<input type="number">` — the browser's own Up/Down arrow-key stepping,
  keyboard numeric input handling, and `min`/`max`/`step` constraint validation all apply
  automatically, on top of the visible stepper buttons this component adds.
- The stepper buttons are real, independently-focusable `<button aria-label="Increase value">` /
  `<button aria-label="Decrease value">` elements, each disabled natively (not just visually) once
  the value reaches `max`/`min` — a screen reader announces them as unavailable, not just dimmed.
- Clicking a stepper button returns focus to the input immediately afterward, so keyboard users can
  keep editing without an extra `Tab` back — same pattern as `Input`'s own clear button and
  `PasswordInput`'s own toggle.
- `readOnly` disables both stepper buttons (not just the input) — unlike `PasswordInput`'s own
  visibility toggle (revealing isn't an edit), incrementing/decrementing genuinely changes the
  value, which `readOnly` rules out.

</Callout>

## Code examples

```tsx
<NumberInput defaultValue={1} min={0} max={10} />
<NumberInput value={quantity} onValueChange={setQuantity} step={0.5} />
<NumberInput hasError min={0} />
<NumberInput disabled defaultValue={5} />
<NumberInput
  value={quantity}
  onValueChange={setQuantity}
  onClear={() => setQuantity(undefined)}
/>

{/* Composed inside a FormField for the label/helper-text wiring — see that
    component's own Docs page for the full pattern. */}
<FormField label="Quantity" helperText="Between 1 and 10">
  {(fieldProps) => <NumberInput {...fieldProps} min={1} max={10} />}
</FormField>
```
