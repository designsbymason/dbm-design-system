<ComponentHeader title="PasswordInput" tier="Molecule" />

A password input with a show/hide visibility toggle, wrapping `Input`. Starts masked
(`type="password"`); the trailing toggle switches to `type="text"` so the user can verify what they
typed. Accepts both controlled (`value`/`onChange`) and uncontrolled (`defaultValue`) usage, and
every other `Input` feature except `type`/`suffix` — the visibility toggle owns the trailing slot,
so there's no `suffix` prop to collide with it, and `type` is managed internally rather than
exposed.

### Import

```tsx
import { PasswordInput } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Set `autoComplete="current-password"` on a login form and `autoComplete="new-password"` on a
  signup/change-password form — the latter also signals password managers to suggest a strong
  generated value instead of an existing saved one.
- Pair `hasError` with a nearby `FieldError` so the reason (e.g. a failed strength rule) is visible,
  not just the red border and `aria-invalid`.
- Pass `onClear` together with a real `value`/`onChange` (or rely on the uncontrolled DOM value) so
  the clear button has something meaningful to act on, same as `Input`'s own.

</Callout>
<Callout tone="danger" title="Don't">

- Don't pass `type` or `suffix` — neither is exposed. `type` is managed internally (toggling
  between `password`/`text`), and `suffix` is reserved for the visibility toggle itself.
- Don't drive `value` from a live control without a real `onChange` wired back — a controlled value
  always wins over the user's own typing, freezing the input exactly like `Input`'s own `value`.
- Don't reach for `Input` directly with `type="password"` long-term — that's a stand-in until this
  component exists, not the intended usage; `PasswordInput` is what actually ships the visibility
  toggle.

</Callout>
</div>

## Best practices

- Match `size` to the surrounding form's density, same as `Input`'s own guidance.
- Reveal-then-hide is the user's own choice, not something to automate — don't auto-hide the value
  after a timeout or on blur; that surprises a user mid-review of what they typed.
- Use `minLength`/`pattern` for real HTML5 password-strength validation rather than only a visual
  hint — pair whichever you use with `FieldHelperText` describing the actual rule in plain language.

## Accessibility

<Callout tone="info" title="A real toggle button, not a decorative icon">

- The show/hide toggle is a real, independently-focusable `<button aria-label="Show password">` /
  `<button aria-label="Hide password">` — the accessible name itself changes with the toggle state,
  so assistive tech always announces what activating it will do next, not a static label that goes
  stale.
- Disabling the field disables the toggle too — a disabled password field can't have its masking
  state changed, matching the same all-or-nothing semantics as `Input`'s own `disabled`.
- Clicking the toggle returns focus to the input immediately afterward, so keyboard users can keep
  editing without an extra `Tab` back — same pattern as `Input`'s own clear button.
- Revealing the value only ever changes the native `type` attribute — nothing here copies the value
  anywhere else (no clipboard access, no network request), so the browser's own native `<input>`
  security model is exactly what governs the value's exposure, same as any native password field
  with a reveal toggle.

</Callout>

## Code examples

```tsx
<PasswordInput placeholder="Enter your password" />
<PasswordInput hasError autoComplete="new-password" />
<PasswordInput
  value={password}
  onChange={(e) => setPassword(e.target.value)}
  onClear={() => setPassword('')}
/>
<PasswordInput size="sm" />
<PasswordInput disabled />
<PasswordInput maxLength={64} showCount formatNumber={new Intl.NumberFormat("ar-EG").format} />
<PasswordInput minLength={8} pattern="(?=.*\d)(?=.*[a-zA-Z]).{8,}" />

{/* Composed inside a FormField for the label/helper-text wiring — see that
    component's own Docs page for the full pattern. */}
<FormField label="Password" helperText="At least 8 characters">
  {(fieldProps) => <PasswordInput {...fieldProps} autoComplete="new-password" />}
</FormField>
```
