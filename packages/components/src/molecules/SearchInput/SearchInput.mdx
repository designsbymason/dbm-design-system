<ComponentHeader title="SearchInput" tier="Molecule" />

A search input wrapping `Input`: a fixed leading search icon (swapped for a spinner via
`isLoading`), a clear button, and a debounced `onSearch` callback kept separate from the raw,
per-keystroke `onChange`. `onSearch` also fires immediately — bypassing any pending debounce — on
Enter and when the value is cleared, since those are both "I want an answer right now" moments a
debounce should never delay. Enter never submits a surrounding `<form>` — this is a purely in-page,
`onSearch`-driven control, not a classic submit-to-navigate search form.

### Import

```tsx
import { SearchInput } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Reach for `onSearch` as your primary "run the search" hook — it fires once the user pauses,
  immediately on Enter, and immediately when cleared, so you never need to build your own debounce
  logic on top of `onChange`.
- Set `debounceMs={0}` for a search that's cheap to re-run on every keystroke (filtering an
  already-loaded local list) rather than an expensive one (a network request) — `onSearch` still
  gives you one consistent callback either way.
- Pass `isLoading` while an async search triggered by `onSearch` is still in flight, so the leading
  icon reflects real state instead of looking idle during a slow request.

</Callout>
<Callout tone="danger" title="Don't">

- Don't pass `type` or `prefix` — neither is exposed. `type` is fixed to `"search"` internally, and
  `prefix` is reserved for the search icon (or the loading spinner).
- Don't use `onChange` as your search trigger — it fires on every keystroke with no debounce, which
  is the exact problem `onSearch` exists to solve.
- Don't rely on the clear button alone to reset a controlled value — pair `onClear` with your own
  state setter (e.g. `onClear={() => setQuery("")}`), the same contract `Input`'s and `NumberInput`'s
  own `onClear` already establish.

</Callout>
</div>

## Best practices

- Match `size` to the surrounding layout's density, same as `Input`'s own guidance.
- Keep `debounceMs` in the 200–500ms range for a network-backed search — short enough to feel
  responsive, long enough to avoid firing a request per keystroke on a fast typist.
- Set `autoComplete="off"` for a live search field — browser autofill suggestions rarely make sense
  for a query box, and can visually collide with your own results dropdown if you build one.

## Accessibility

<Callout tone="info" title="A real searchbox, with an Escape shortcut layered on top">

- Renders a real native `<input type="search">`, exposed to assistive tech with the `searchbox`
  role rather than the generic `textbox` role a plain `Input` gets.
- The clear button is a real, independently-focusable `<button aria-label="Clear">`, disabled
  natively (not just visually) when the field is `disabled` or `readOnly`.
- Escape clears the field — matching the common platform convention (macOS Spotlight, browser
  omnibars) — but only when there's a value to clear and `onClear` is set; the key event stops
  there instead of also bubbling to, say, a parent Dialog's own Escape-to-close handler.
- Enter correctly ignores the keystroke that confirms an IME composition (Japanese/Chinese/Korean
  input methods), so `onSearch` never fires against an incomplete or wrong in-progress composition.
- Clicking the clear button returns focus to the input immediately afterward, so keyboard users can
  keep refining their query without an extra `Tab` back — same pattern as `Input`'s own clear
  button.
- The loading spinner shown via `isLoading` is decorative, matching `Spinner`'s own default — pair
  `isLoading` with a visible or `aria-live` results-count update elsewhere if the loading state
  itself needs to be announced.

</Callout>

## Code examples

```tsx
<SearchInput aria-label="Search" placeholder="Search…" onSearch={runSearch} />

{/* Cheap, local filtering — no need to wait out a debounce */}
<SearchInput aria-label="Search" debounceMs={0} onSearch={filterLocalList} />

{/* Reflects a real in-flight async search */}
<SearchInput aria-label="Search" isLoading={isFetching} onSearch={runSearch} />

{/* Controlled, with a working clear button */}
<SearchInput
  aria-label="Search"
  value={query}
  onChange={(e) => setQuery(e.target.value)}
  onSearch={runSearch}
  onClear={() => setQuery("")}
/>

{/* Composed inside a FormField for the label/helper-text wiring — see that
    component's own Docs page for the full pattern. */}
<FormField label="Search products" helperText="Try a name, SKU, or category">
  {(fieldProps) => <SearchInput {...fieldProps} onSearch={runSearch} />}
</FormField>
```
