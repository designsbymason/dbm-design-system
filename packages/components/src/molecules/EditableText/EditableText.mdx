<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="EditableText" tier="Molecule" />

A value that reads as plain text and turns into a field when you activate it: a project name, a title, a note, a
cell in a table. Enter keeps the edit and Escape throws it away, and leaving the field does one or the other, so the
page is never left half-edited. A single line edits in an `Input` and a `multiline` value in a `Textarea`. The text and
the field are the same height at every size, so nothing around them moves when it opens.

### Import

```tsx
import { EditableText } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use it for a value people change now and then, where a permanent field would make the page look like a form: a
  name in a header, a title on a card, a cell in a table.
- Give it a name with `aria-label` (or a `FormField`), so the button and the field say what the value is.
- Keep the default `blurBehavior="commit"` so an edit is never lost by clicking away; use `cancel` only where a
  half-typed value must never be saved.
- Show `showControls` on screens that people use by touch, where there is no Escape key to cancel with.
- Use `activation="doubleClick"` in a row or cell that a single click already selects.
- Use `validate` or `required` to say why a value is refused, near the field, instead of silently ignoring it.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for a value that must be filled in to proceed: a form field that should always be visible belongs in
  an `Input` or `Textarea`, which shows that it can be typed into.
- Don't use it for a long document or rich text; a multi-line field here is for a note or a description.
- Don't rely on hover to say it can be edited on a touch screen: the pencil is shown there without hover, and
  `showControls` makes the way out visible.
- Don't expect `onValueChange` on every keystroke: it is called once, with the committed value. A live counter or
  check reads the draft through `onDraftChange`.
- Don't put a link or a button in `renderValue`: the text is a button, and interactive content inside one is not
  valid.

</Callout>
</div>

## Best practices

- The committed value is yours to save: `onValueChange` is the moment to send it. Set `isLoading` then, so the
  field shows a spinner and refuses further input. For a save that can fail, also keep `editing` controlled and leave
  it open, closing it (or setting `hasError`) when the request answers; ignore the request to close that comes with
  the commit.
- Use `renderValue` for a currency, a date or a status that should read formatted. The field still edits the raw
  string, so keep `renderValue` a pure function of it.
- Use `actionRef` to start an edit from a menu item or a shortcut; with `editing` controlled, set that instead.
- A single-line value that is too wide for its box ends in an ellipsis in both the text and the field, so a long
  value never makes the row taller when it is opened. Use `multiline` where the full value should be read.
- In a heading, set `inheritFont` so the title keeps the heading's type, and pick the `size` that gives the padding
  you want.
- In a table cell, give the cell a fixed width: the text and the field both fill it, so the columns never shift.
- An empty value with no `placeholder` still takes up its row and still shows the pencil, so it can be found.

## Accessibility

<Callout tone="info" title="A real button that becomes a real, labelled field">

- In its resting state the value is a native `<button>`: one tab stop, activated by Enter or Space, and named by the
  field's name and the value together (for example "Project name Apollo"), so the visible text is always part of
  the name. It is described as "Edit" (translatable through `labels`).
- Opening it moves focus into the field with the value selected, and closing it from the keyboard (Enter, Escape or
  the buttons) puts focus back on the button. Leaving by Tab or a press elsewhere leaves focus where the person put
  it.
- Pressing Enter while an input method is composing a character does not commit.
- While `isLoading`, the field keeps focus and its text but cannot be edited, is marked `aria-busy`, and a status
  message ("Saving", translatable through `labels`) is announced; Enter, Escape, the buttons and leaving it wait for
  the answer.
- A refused value keeps the field open, sets `aria-invalid`, and shows the message in an alert, tied to the field
  through `aria-describedby`.
- `readOnly` shows plain text, not a disabled control, so it can be read and selected; `disabled` removes the button
  from the tab order and dims it.
- Escape is handled inside the field and does not reach handlers on its parents in the page. A surrounding overlay
  that listens for Escape at the document level will still see it, so close that overlay only when no field inside
  it is open.
- The confirm and cancel buttons are at least 24 × 24 pixels at every size. On a screen with no hover the pencil is
  always visible, and in Windows high-contrast mode the box is drawn with a system colour when the text can be pressed
  or has focus.

</Callout>

| Key | Behaviour |
|---|---|
| Tab | Moves between the text, or the field and its buttons; leaving the field commits or cancels (`blurBehavior`). |
| Enter, Space, F2 (on the text) | Starts editing. |
| Enter (single line) | Commits the edit. |
| Enter (multiline) | Adds a line. |
| Ctrl or Cmd + Enter (multiline) | Commits the edit. |
| Escape | Throws the edit away and returns to the text. |

## Code examples

```tsx
<EditableText aria-label="Project name" defaultValue="Apollo" onValueChange={save} />

{/* A note: Enter adds a line, Ctrl or Cmd + Enter commits */}
<EditableText aria-label="Notes" multiline maxRows={6} placeholder="Add notes" />

{/* Touch-friendly: confirm and cancel buttons beside the field */}
<EditableText aria-label="Project name" defaultValue="Apollo" showControls />

{/* A cell where a click already selects the row */}
<EditableText aria-label="Owner" defaultValue="Ada Lovelace" activation="doubleClick" />

{/* Refused with a message, kept open */}
<EditableText
  aria-label="Project name"
  defaultValue="Apollo"
  required
  validate={(draft) => (draft.length > 20 ? "Keep it under 20 characters" : undefined)}
/>

{/* A save that can fail: spinner, and the field stays open until the request answers */}
<EditableText
  aria-label="Project name"
  value={name}
  editing={editing}
  onEditingChange={requestEditing}
  onValueChange={save}
  isLoading={saving}
  hasError={failed}
/>

{/* A counter, and the draft as it is typed */}
<EditableText aria-label="Bio" multiline maxLength={160} showCount onDraftChange={checkDraft} />

{/* Formatted at rest, raw in the field */}
<EditableText aria-label="Price" defaultValue="1250" renderValue={(raw) => `$${Number(raw).toFixed(2)}`} />

{/* Started from a menu item */}
<EditableText aria-label="Project name" defaultValue="Apollo" actionRef={actions} />

{/* Submitted with a form, under `project`, as the committed value; with a field-level native attribute */}
<form onSubmit={handleSubmit}>
  <EditableText aria-label="Project name" defaultValue="Apollo" name="project" autoComplete="off" />
</form>

{/* With a label and helper text; the wiring is done for you */}
<FormField label="Project name" helperText="Shown on the dashboard">
  {(fieldProps) => <EditableText {...fieldProps} defaultValue="Apollo" />}
</FormField>
```
