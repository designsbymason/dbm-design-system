<ComponentHeader title="DescriptionList" tier="Molecule" />

A compact key/value display block — real `<dl>` semantics (the native HTML element for a list of
terms and their descriptions), not a repurposed table or a stack of styled `<div>`s. Compose one or
more `DescriptionList.Item`s, each pairing a `DescriptionList.Term` (a field name) with its
`DescriptionList.Details` (the value) — an order summary, an account's details, a resource's
metadata, anything shaped like a short list of facts. Deliberately non-interactive and read-only:
for an editable set of fields, reach for `Form`/`FormField` instead.

### Import

```tsx
import { DescriptionList } from "@dbm-design-system/components";
```

## Properties

`DescriptionList` also accepts any other native `<dl>` attribute beyond what's listed here (e.g.
`onClick`, `title`) — passed straight through to the underlying element. `DescriptionList.Item`
accepts any other native `<div>` attribute, and `DescriptionList.Term`/`DescriptionList.Details`
accept any other native `<dt>`/`<dd>` attribute, in the same way.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `variant="ghost"` whenever a `DescriptionList` sits inside a container that already draws its
  own boundary — a `Card.Body`, an `EmptyState` — so the two borders don't nest.
- Reach for `columns` when a list is really several short, independent facts (a status, a total, a
  reference number) rather than a handful of longer ones — a 2- or 3-column layout reads faster than
  one long vertical list for that shape of data.
- Give a wide value (notes, a long address, anything one column can't comfortably hold) its own
  `DescriptionList.Item` with `span` set to the full column count, rather than truncating it.
- Leave `alignedTerms` at its default of `true` for most single-column lists — a real aligned label
  column reads as more deliberate and premium than several independently-sized terms, and costs
  nothing to opt into.

</Callout>
<Callout tone="danger" title="Don't">

- Don't reach for `columns` greater than `1` and expect the automatic between-item divider, or
  `alignedTerms` — a wrapping multi-column grid drops both (see `columns`'s own prop doc for why);
  give the list its own visual separation instead (`variant="bordered"`, or embed it in a `Card`).
- Don't use `DescriptionList` for anything the reader needs to edit — it renders plain text, with no
  input, validation, or focus handling. Use `Form`/`FormField` for an editable set of fields instead.
- Don't reach for `Table` instead of a `columns`-only `DescriptionList` just because the data has more
  than one row of facts — `Table` is for column-labeled, many-row tabular data; `DescriptionList` is
  for a short, self-describing list of individual facts, each with its own label right beside it.

</Callout>
</div>

## Best practices

- Keep terms short and consistent in phrasing across items in the same list ("Customer", "Status",
  "Total") — a `DescriptionList` reads best as a scannable set of short labels, not full sentences.
- Prefer `orientation="horizontal"` (the default) for most lists — it reads like a familiar label/value
  row. Reach for `"vertical"` when values are long enough that a side-by-side label would crowd them
  (a full address, a multi-line note), or when the whole list sits somewhere narrow to begin with (a
  sidebar panel).
- A list this small rarely needs `Table`'s sorting, striping, or scroll handling — reach for
  `DescriptionList` first for a details panel, and only move to `Table` once the data genuinely grows
  into many uniform rows.
- Set `alignedTerms={false}` when a list's terms are so mismatched in length (one word next to a full
  sentence) that a shared column would leave a lot of empty space next to the short ones — letting each
  term hug its own content instead can read cleaner for that specific shape of data.

## Accessibility

<Callout tone="info" title="Native list semantics carry the structure — no ARIA role needed">

- `DescriptionList` renders a real `<dl>`; `DescriptionList.Item` wraps one `DescriptionList.Term`
  (`<dt>`)/`DescriptionList.Details` (`<dd>`) pair in its own `<div>` — an HTML5-valid grouping
  assistive technology already understands, so no `role`/`aria-*` is added to establish the
  term/details relationship itself.
- Unlike a `<ul>`/`<ol>` with `list-style: none` removed, a `<dl>`'s list semantics don't depend on
  CSS list-marker styling, so the Safari/VoiceOver dropped-list-semantics issue that `List`/`Table`
  guard against doesn't apply here.
- Give the list an accessible name with `aria-label`/`aria-labelledby` when it isn't already named by
  a visible heading right above it (e.g. inside a `Card` with its own `Card.Header`, the heading
  already serves that purpose and neither is needed).
- The details' wrap-below-the-term response to a narrow container (`orientation="horizontal"`,
  `alignedTerms={false}`) is pure CSS `flex-wrap` — verified in a real browser, since layout wrapping
  isn't something a jsdom test can evaluate; see `DescriptionList.stories.tsx`'s hidden
  `ResponsiveLayoutChecks` story.
- `alignedTerms` (the default) makes each `DescriptionList.Item` `display: contents`, so its
  `<dt>`/`<dd>` join the list's own grid directly — this changes nothing in the accessibility tree
  (the term/details are still real `<dt>`/`<dd>` elements, just no longer boxed by their own `<div>`),
  confirmed live rather than assumed; see the hidden `AlignedTermsChecks` story.

</Callout>

## Code examples

```tsx
{/* alignedTerms defaults to true — both terms already share one aligned column */}
<DescriptionList>
  <DescriptionList.Item>
    <DescriptionList.Term>Customer</DescriptionList.Term>
    <DescriptionList.Details>Jane Cooper</DescriptionList.Details>
  </DescriptionList.Item>
  <DescriptionList.Item>
    <DescriptionList.Term>Status</DescriptionList.Term>
    <DescriptionList.Details>Paid</DescriptionList.Details>
  </DescriptionList.Item>
</DescriptionList>

{/* Mismatched term lengths — opt out so each hugs its own content */}
<DescriptionList alignedTerms={false}>
  <DescriptionList.Item>
    <DescriptionList.Term>ID</DescriptionList.Term>
    <DescriptionList.Details>1024</DescriptionList.Details>
  </DescriptionList.Item>
  <DescriptionList.Item>
    <DescriptionList.Term>Estimated delivery window</DescriptionList.Term>
    <DescriptionList.Details>Tuesday, Oct 6</DescriptionList.Details>
  </DescriptionList.Item>
</DescriptionList>

{/* A compact, responsive facts panel */}
<DescriptionList columns={{ base: 1, md: 3 }}>
  <DescriptionList.Item>
    <DescriptionList.Term>Total</DescriptionList.Term>
    <DescriptionList.Details numeric>$1,234.00</DescriptionList.Details>
  </DescriptionList.Item>
  <DescriptionList.Item span={3}>
    <DescriptionList.Term>Notes</DescriptionList.Term>
    <DescriptionList.Details>Leave the package with the front desk.</DescriptionList.Details>
  </DescriptionList.Item>
</DescriptionList>

{/* Embedded in a Card, borderless so it doesn't double up */}
<Card>
  <Card.Body>
    <DescriptionList variant="ghost">
      <DescriptionList.Item>
        <DescriptionList.Term>Customer</DescriptionList.Term>
        <DescriptionList.Details>Jane Cooper</DescriptionList.Details>
      </DescriptionList.Item>
    </DescriptionList>
  </Card.Body>
</Card>
```
