<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Popover" tier="Molecule" />

A floating panel of arbitrary, fully-interactive content anchored to a trigger, built on Radix
Popover. Unlike `Tooltip` (a short, non-interactive hint), a popover's own content stays open until
the user dismisses it — outside click, Escape, or an explicit `Popover.Close` — not just while
hovering. A compound component: compose `Popover.Trigger` and `Popover.Content` inside `Popover`
itself.

### Import

```tsx
import { Popover } from "@dbm-design-system/components";
```

## Properties

`Popover` itself renders no DOM element of its own — it's a plain context provider around
`Popover.Trigger`/`Popover.Content` (matching Radix's own `Popover.Root`), so it has no
`className`/`style`/`id`/`data-testid`/`ref` of its own to accept.

<PropertiesTable of={PopoverStories} order={propOrder} />

### Popover.Trigger properties

The element that opens/closes the popover on click. Also accepts any other native `<button>`
attribute beyond what's listed here (e.g. `onFocus`, `disabled`) — passed straight through.

### Popover.Content properties

The floating panel itself. Also accepts any other native `<div>` attribute beyond what's listed
here (e.g. `onFocus`, `onMouseEnter`) — passed straight through to the underlying content element.

### Popover.Close properties

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Reach for `Popover` when the content needs to stay open and be genuinely interactive (a form, a
  list of actions, a longer read) — reach for `Tooltip` instead for a short, non-interactive hint
  that only needs to be visible while hovering/focused.
- Set `modal` when the popover's own content should be the only thing the user can interact with
  until they finish or dismiss it (e.g. a form) — leave it unset for a lighter-weight popover that
  coexists with the rest of the page (a menu, an info card).
- Pass `asChild` on `Popover.Trigger` with one of this system's own interactive components
  (`Button`, `IconButton`) as the visible trigger — the built-in fallback is deliberately unstyled.
- Turn on `showCloseButton` for a popover substantial enough (a form, a longer read) that a visible
  dismiss affordance genuinely helps, not for a small, quick info bubble relying on outside-click/
  Escape alone.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use `Popover` for a short, non-interactive hint shown on hover — that's exactly what
  `Tooltip` already covers, with the right ARIA role and timing behavior for that case.
- Don't nest a `Popover` trigger inside another `Popover`'s own content expecting independent
  positioning without testing it — Radix's own dismissable-layer stack coordinates nested/stacked
  overlays, and the interaction gets more involved the deeper it goes.
- Don't rely on `defaultOpen` to pre-open more than one `Popover` at once in the same view — Radix's
  own focus-management timing for multiple *simultaneously* uncontrolled-open instances isn't
  reliable (see the `AllSides` story's own code comment); open additional popovers one at a time
  from real user interaction instead, which works correctly.

</Callout>
</div>

## Best practices

- Keep popover content focused — a single form, a short list of actions, one card's worth of
  information. A popover that needs its own scrolling or multiple sections is usually a sign the
  content belongs in a `Dialog` instead.
- Set `aria-label` (or `aria-labelledby`) on `Popover.Content` when it has no visible heading of its
  own, so assistive tech announces something meaningful when it opens.
- Match `side`/`align` to where the trigger actually sits in the layout — `avoidCollisions` (on by
  default) repositions automatically near a viewport edge, but a sensible starting placement still
  reads better than relying on the fallback alone.

## Accessibility

<Callout tone="info" title="Keyboard and ARIA state come from Radix's own popover primitive">

- Renders `role="dialog"` on the content, with `aria-haspopup="dialog"`/`aria-expanded`/
  `aria-controls` kept in sync on the trigger automatically.
- `Tab` moves focus into the content once open (auto-focus); `Escape` closes it and returns focus to
  the trigger, in both modal and non-modal mode.
- Clicking outside the content, a genuine loss of focus outside it, or `Escape` dismisses the popover
  the same way whether `modal` is set or not — Radix's `Popover` has no `Overlay`/scrim sub-part the
  way `Dialog` does, so there's nothing to swallow that dismissal click. What `modal` actually adds:
  the rest of the page becomes `aria-hidden` and gets `pointer-events: none`, so its own elements
  can't be interacted with while the popover is open (a background button's own click handler won't
  fire, live-verified), and `Tab` focus is trapped inside the content until it's dismissed.
- A dev-mode console warning fires once per instance if `Popover.Content` has no `aria-label` or
  `aria-labelledby` — a `role="dialog"` element with no accessible name is invisible to screen
  reader users, and `@storybook/addon-a11y`'s own automated sweep enforces this across every story.

</Callout>

## Code examples

```tsx
<Popover>
  <Popover.Trigger asChild>
    <Button>Open</Button>
  </Popover.Trigger>
  <Popover.Content>
    <Text size="sm">Popover content</Text>
  </Popover.Content>
</Popover>

{/* Modal, with an explicit close button */}
<Popover modal>
  <Popover.Trigger asChild>
    <IconButton icon={GearIcon} aria-label="Settings" />
  </Popover.Trigger>
  <Popover.Content showCloseButton side="bottom" align="end">
    <SettingsForm />
  </Popover.Content>
</Popover>

{/* Controlled open state */}
function Example() {
  const [open, setOpen] = useState(false);
  return (
    <Popover open={open} onOpenChange={setOpen}>
      <Popover.Trigger asChild>
        <Button>Open</Button>
      </Popover.Trigger>
      <Popover.Content>
        <Text size="sm">Popover content</Text>
        <Popover.Close asChild>
          <Button variant="tertiary" onClick={() => setOpen(false)}>Done</Button>
        </Popover.Close>
      </Popover.Content>
    </Popover>
  );
}

{/* A native <button> attribute, passed straight through */}
<Popover.Trigger disabled>Open</Popover.Trigger>

{/* Responsive side — bottom below lg, right from lg up */}
<Popover.Content side={{ base: "bottom", lg: "right" }}>
  <Text size="sm">Popover content</Text>
</Popover.Content>
```
