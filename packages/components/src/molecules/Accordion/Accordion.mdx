<ComponentHeader title="Accordion" tier="Molecule" />

A vertically-stacked set of expand/collapse disclosure panels, built on Radix Accordion — one item
open at a time by default, or several independently. A compound component: compose `Accordion.Item`,
`Accordion.Trigger`, and `Accordion.Content` inside `Accordion` itself, mirroring `Popover`'s own
Radix-shaped sub-parts.

### Import

```tsx
import { Accordion } from "@dbm-design-system/components";
```

## Properties

`Accordion` accepts a single string `value`/`defaultValue` under the default `type="single"`, or a
`string[]` under `type="multiple"` — the value shape always matches whichever `type` is active,
mirroring Radix's own discriminated Accordion props. `ref` forwards to the root `<div>`. Also
accepts any other native `<div>` attribute beyond what's listed here (e.g. `onFocus`,
`onMouseEnter`) — passed straight through to the root element.

### Accordion.Item properties

A single disclosure section within an `Accordion` — an `Accordion.Trigger` and `Accordion.Content`

`onMouseEnter`) — passed straight through to the underlying element.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Reach for `Accordion` when several sections of content compete for the same space and only one
  (or a few) need to be visible at once — an FAQ list, a settings page's collapsible sections.
- Set `headingLevel` to match this accordion's real position in the surrounding page's own heading
  outline, the same concern `Heading`'s own `level` prop addresses.
- Use `type="multiple"` when a reader might reasonably want more than one section open for
  comparison (e.g. comparing two FAQ answers) — leave the default `type="single"` when sections are
  mutually exclusive by nature (a wizard-like set of steps).
- Pass `asChild` on `Accordion.Trigger` for a fully custom trigger row (a leading icon, a secondary
  line of text) — the built-in label+icon row covers the common case.
- Use `variant="ghost"` when embedding an `Accordion` inside a container that already has its own
  border (a `Card`) — the default `variant="bordered"` would otherwise double up on the boundary.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use `Accordion` for a single expand/collapse region with no sibling sections — reach for the
  plain `Collapse` atom instead, which is exactly what `Accordion.Content`'s own animation technique
  is built on.
- Don't set `collapsible={false}` without also setting a `defaultValue`/`value` — with nothing open
  to start, a reader has no way to tell one section is meant to always stay open until they've
  already closed every other one and hit the floor.
- Don't nest interactive form controls that need to survive a section closing (e.g. an in-progress
  multi-step form) inside `Accordion.Content` — closing an item unmounts its content by design,
  the same as `Collapse`'s own behavior.

</Callout>
</div>

## Best practices

- Keep trigger labels short and scannable — a full sentence works, but a trigger crowded with
  secondary detail is better split into the label plus a first line of `Accordion.Content`.
- Prefer `type="single"` (the default) for the common FAQ/disclosure-list case; reach for
  `type="multiple"` deliberately, not as a default, since letting every section open at once can
  defeat the point of using an accordion instead of a plain list of `Collapse` regions.
- `orientation="horizontal"` only changes which arrow-key pair moves focus between triggers — pair
  it with your own layout `className` if a genuinely side-by-side accordion is needed; the built-in
  styling stays a vertical stack either way.

## Accessibility

<Callout tone="info" title="Keyboard and ARIA state come from Radix's own accordion primitive">

- Each trigger is a real `<button>` inside a heading element (`headingLevel`, default `3`), with
  `aria-expanded`/`aria-controls` kept in sync automatically, and its panel carries
  `aria-labelledby` pointing back at the trigger.
- `Tab`/`Shift+Tab` moves focus between triggers and the rest of the page normally; `Up`/`Down`
  arrow keys (`Left`/`Right` under `orientation="horizontal"`) move roving focus directly between
  triggers without leaving the accordion, `Home`/`End` jump to the first/last trigger.
- `Enter`/`Space` on a focused trigger toggles its own item's open state.
- A disabled item's trigger is skipped by both `Tab` and arrow-key navigation, matching native
  `disabled`-button behavior.

</Callout>

## Code examples

```tsx
<Accordion>
  <Accordion.Item value="shipping">
    <Accordion.Trigger>How long does shipping take?</Accordion.Trigger>
    <Accordion.Content>
      <Text size="sm">3-5 business days for standard shipping.</Text>
    </Accordion.Content>
  </Accordion.Item>
  <Accordion.Item value="returns">
    <Accordion.Trigger>What's your return policy?</Accordion.Trigger>
    <Accordion.Content>
      <Text size="sm">Returns accepted within 30 days.</Text>
    </Accordion.Content>
  </Accordion.Item>
</Accordion>

{/* Several items open independently */}
<Accordion type="multiple" defaultValue={["shipping"]}>
  <Accordion.Item value="shipping">
    <Accordion.Trigger>How long does shipping take?</Accordion.Trigger>
    <Accordion.Content>3-5 business days for standard shipping.</Accordion.Content>
  </Accordion.Item>
</Accordion>

{/* Controlled open item */}
function Example() {
  const [value, setValue] = useState("shipping");
  return (
    <Accordion value={value} onValueChange={setValue}>
      <Accordion.Item value="shipping">
        <Accordion.Trigger>How long does shipping take?</Accordion.Trigger>
        <Accordion.Content>3-5 business days for standard shipping.</Accordion.Content>
      </Accordion.Item>
    </Accordion>
  );
}

{/* A native <button> attribute on Accordion.Trigger, passed straight through */}
<Accordion.Trigger onFocus={() => console.log("focused")}>Label</Accordion.Trigger>

{/* A disabled item */}
<Accordion.Item value="shipping" disabled>
  <Accordion.Trigger>How long does shipping take?</Accordion.Trigger>
  <Accordion.Content>3-5 business days for standard shipping.</Accordion.Content>
</Accordion.Item>
```
