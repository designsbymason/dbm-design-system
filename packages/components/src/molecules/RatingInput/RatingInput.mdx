<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="RatingInput" tier="Molecule" />

A rating field: a row of icons (stars by default) of which a person chooses one, with the pointer or the
keyboard. It is a native radio group with one radio for each value, so the arrow keys, a single tab stop, form
submission under `name` and `required` validation are the browser's own, and a screen reader hears "3 out of 5".
The value is a number, `0` for no rating. Icons light up under the pointer before a choice is made, `precision={0.5}`
adds half steps, `clearable` lets a rating be taken back, and `readOnly` shows any value exactly (an average of 4.3
fills a third of the fifth icon) as one image with a text alternative.

### Import

```tsx
import { RatingInput } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Give the rating a name: a visible `FieldLabel` (or a `FormField`), or `aria-label` when the text around it
  already says what is being rated.
- Use `readOnly` with a fractional `value` to show an average, so 4.3 reads as 4.3 and not as 4.
- Use `precision={0.5}` when the choice itself needs finer steps, such as a review that can be 3.5 stars.
- Set `valueNames` when the numbers need meaning ("Poor" to "Excellent"); the names are announced with each choice.
- Use `clearable` for an optional rating, so a person can change their mind and leave it blank.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use it for a value on a long or continuous scale: a `Slider` is for that, and a rating is a short ladder
  of steps.
- Don't rely on the colour alone to show what is chosen: the filled shape against the outline already does, and
  the value name or a visible number below reinforces it.
- Don't use the default stars for something that is not a quality judgment (a priority, a difficulty): pick an
  `icon` that fits.
- Don't use `max` above 10; past that the icons stop being quick to scan.

</Callout>
</div>

## Best practices

- Choose a `size` that fits the space: ten icons at `xl` are wider than a phone. Every choice is a target of at
  least 24px at every size.
- Show a rating's number or name as text somewhere near it as well when it matters; the icons alone are a quick,
  approximate read.
- A required rating that is missing should say so with `hasError` and an error message, not only by colour.
- A `readOnly` rating is not a form control: it has no tab stop. It still submits its value when it has a `name`.
- The scale reads left to right whatever the page's direction, the way a number does.

## Accessibility

<Callout tone="info" title="A native radio group, named, with a single tab stop">

- It is a `radiogroup` of native radio inputs, so a screen reader announces the group's name, each choice ("3 out
  of 5, Good") and which one is chosen. Name the group with `aria-label`, `aria-labelledby` or a `FormField`.
- Tab enters the group on the chosen choice (or the first, if there is none) and leaves it on the next Tab. The
  arrow keys move and choose in one step, as in any radio group.
- With `clearable`, Backspace, Delete and Escape take the rating back and pressing the chosen icon again does the
  same; a rating that is not clearable can't be emptied once it has a value.
- A half step has its own choice ("2.5 out of 5") and is reached by the arrow keys as well as by pressing the left
  half of an icon.
- The hover preview is for mouse pointers only, and stops as soon as the keyboard is used; a touch tap simply
  chooses.
- `readOnly` is one image whose text alternative says the value ("Rated 4.3 out of 5", or "Not rated"), not a group
  of disabled radios.
- `hasError` sets `aria-invalid`; `required` sets `aria-required` and a real form constraint.
- The filled and outline icons differ in shape, so what is chosen does not depend on colour, and both survive
  Windows high-contrast mode, as does the focus ring.
- The fill animates only for people who have not asked for reduced motion.

</Callout>

| Key | Behaviour |
|---|---|
| Tab | Enter the group on the chosen choice, or the first; leave it on the next press. |
| Right, Down | Choose the next value (the next half at `precision={0.5}`). |
| Left, Up | Choose the previous value. |
| Backspace, Delete, Escape | With `clearable`, take the rating back. |
| Pointer | Pressing an icon chooses it; at half steps the left half chooses the half. |

## Code examples

```tsx
<RatingInput aria-label="Rate this recipe" onValueChange={save} />

{/* Half steps, stored as 0 to 5 */}
<RatingInput aria-label="Rating" precision={0.5} defaultValue={3.5} />

{/* Showing an average, which is not a form control */}
<RatingInput aria-label="Average rating" readOnly value={4.3} />

{/* Names for each value, and a rating that can be taken back */}
<RatingInput
  aria-label="Rating"
  valueNames={["Poor", "Fair", "Good", "Great", "Excellent"]}
  showValueName
  clearable
/>

{/* Submitted with a form, as a number, and required */}
<form onSubmit={handleSubmit}>
  <RatingInput aria-label="Rating" name="rating" required />
</form>

{/* With a native attribute on the group */}
<RatingInput aria-label="Rating" title="Your rating" />

{/* With a label and helper text; the wiring is done for you */}
<FormField label="How was it?" helperText="Choose a rating from 1 to 5.">
  {(fieldProps) => <RatingInput {...fieldProps} />}
</FormField>
```
