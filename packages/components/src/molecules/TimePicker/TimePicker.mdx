<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="TimePicker" tier="Molecule" />

A time-of-day field: separate hour, minute, optional second and AM/PM segments you type into or step with the
arrow keys, and a popover of wheels to scroll, swipe or tap, like a phone's time picker, with the chosen row in
the middle. The value is a 24-hour string —
`"14:30"`, or `"14:30:00"` with `showSeconds` — whichever hour cycle is shown, so there is nothing to parse and it
submits as it is. Whether the field shows 12 or 24 hours is chosen with `hourCycle`, never read from the browser's
locale, so a server-rendered page and the client agree. For a start and an end, use `TimeRangePicker`.

### Import

```tsx
import { TimePicker } from "@dbm-design-system/components";
```

## Properties

`TimePicker` also accepts any other native `<div>` attribute beyond what's listed here (e.g. `title`,
`onFocus`) — passed straight through to the group element that holds the segments. `ref` forwards to that group,
and the `id` goes on the first segment (the hour), which is what a `FieldLabel`'s `htmlFor` should point at.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `TimePicker` for a time of day: a reminder, an opening hour, an appointment. For a duration (two hours, ten
  minutes) use a number field; for a date, a date picker.
- Pick `hourCycle` for your users and say so explicitly; the field never guesses it from the locale.
- Use `step` for times that fall on a grid (appointments every 15 minutes), so the arrow keys and the picker only
  offer what is valid, and `min` and `max` for a window.
- Put it in a `FormField` for a visible label, helper text and error text wired together.
- Pass `labels` and `formatNumber` for a language that isn't English or digits that aren't 0–9; the whole field,
  announcements included, follows them.

</Callout>
<Callout tone="danger" title="Don't">

- Don't store or compare the displayed text. The value is the 24-hour string, and it is `""` while the field is
  only partly filled.
- Don't treat a `min`/`max` or `step` violation as refused input: the field flags it and still reports it, so your
  own validation decides what to do.
- Don't expect it to validate natively or block a form submit: it holds a hidden input, which the browser doesn't
  validate. Report an empty required field with the `FormField`'s `error`.
- Don't use it for a time with a date or a timezone attached; the value is only a time of day.

</Callout>
</div>

## Best practices

- Typing works the way a native time field does: a digit that can't start a two-digit number is the whole number
  and moves on (a 7 in the minutes), one that can waits for a second. `Backspace` clears a segment. Keep the
  field for people who know the time; the picker is there for the ones who don't.
- A first digit of a two-digit segment already makes a whole time (a `0` is `00`), so `onValueChange` can report
  an in-between value (`"09:03"`) before the second digit arrives (`"09:30"`). Treat each call as the current
  time, as you would a native input's `input` event, and wait for blur if you only want the final one.
- The picker's wheels choose live, as a phone's does: a fast fling reports every row it passes, so `onValueChange` can
  be called many times in a second, each with the time then in the middle. Debounce your own work on it, or wait for
  the picker to close, if each change is expensive.
- When the owner controls `value`, a change it doesn't apply is undone: the field shows what `value` says.
- In a table row or a toolbar, drop to `size="sm"` or `"xs"`; each size is as tall as an `Input` or a `Button` at the
  same step, so a row of mixed controls lines up.

## Accessibility

<Callout tone="info" title="A group of spinbuttons, with a dialog of listboxes">

- The field is a `role="group"` named by `aria-label` or `aria-labelledby` (a `FormField` supplies the label), and
  each segment is an `<input role="spinbutton">` named for what it is (Hour, Minute…), with its range,
  current value and a text value (`09`, `PM`, or "Empty") announced.
- Each segment is its own tab stop, as in a native time field. `ArrowLeft`/`ArrowRight` move between segments
  (also a colon or space), `ArrowUp`/`ArrowDown` step the segment (wrapping, and along the `step` grid in the
  minutes), `Home`/`End` go to its ends, `Backspace` clears it, and a letter in the AM/PM segment chooses it.
- A phone's keyboard that doesn't report keys is handled through the text it inserts, and the segments ask for a
  numeric keyboard.
- The picker button has an accessible name, and opens a `role="dialog"` holding one wheel per segment, each a
  `listbox` of options (`aria-selected`, `aria-disabled` for what the range rules out) that names the chosen
  option with `aria-activedescendant`. Only one copy of a looping wheel's values is in the accessibility tree; the
  copies that let it loop are hidden. Focus moves to the hours wheel; each wheel is a single tab stop;
  `ArrowUp`/`ArrowDown` choose the next allowed value (looping), `Home`/`End` the first and last,
  `ArrowLeft`/`ArrowRight` change wheel, `Enter` closes, `Escape` closes and returns focus to the button.
- Scrolling a wheel with the mouse wheel, a swipe or a drag chooses the row that stops in the middle, live as it
  passes, and a row that isn't allowed is moved off to the nearest allowed one when the wheel rests. Clicking a
  row chooses it and scrolls it to the middle. A reduced-motion preference turns the scrolling animation off.
- `hasError` and an out-of-range or off-grid time set `aria-invalid`, and `required` sets `aria-required`, on
  each segment (a group can't carry either); `disabled` sets `aria-disabled` and removes the segments from the
  tab order.
- A press on the box's padding or a colon goes to the nearest segment, as in a native time field, so the small
  segments aren't the only target. The picker is the equivalent for a pointer, with options and a button of at least
  24 × 24 pixels; with `showPicker={false}` the segments are the only pointer targets.
- Everything the field says (segment names, AM and PM, "Empty", button names) is in `labels`, and the digits it
  shows and announces go through `formatNumber`, so what a person sees is what a screen reader reads.
- The digits always read left to right, in a right-to-left page too, and the buttons follow the page's direction.
  In Windows high-contrast mode the focused segment and the chosen option are drawn in the system highlight colours.
- A dev-mode console warning fires once per field if it has no accessible name.

</Callout>

## Code examples

```tsx
<TimePicker aria-label="Start time" defaultValue="09:30" />

{/* Controlled, in 24 hours, on a 15-minute grid, inside a working day */}
function Example() {
  const [time, setTime] = useState("");
  return (
    <TimePicker
      aria-label="Appointment"
      value={time}
      onValueChange={setTime}
      hourCycle="24"
      step={15}
      min="08:00"
      max="18:00"
    />
  );
}

{/* A form field with a visible label, helper text and an error */}
<FormField label="Reminder" helperText="In your local time" error={error}>
  {(field) => <TimePicker {...field} showSeconds />}
</FormField>

{/* A native <div> attribute, passed straight through to the group */}
<TimePicker aria-label="Start time" title="Pick a start time" />

{/* Submitted with a form, under a name, as "HH:mm" */}
<form>
  <TimePicker aria-label="Start time" name="start" defaultValue="09:30" />
</form>
```
