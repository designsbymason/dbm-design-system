<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Card" tier="Molecule" />

A surface that groups related content — the container for a self-contained chunk of a page: a summary, a
profile, a product, a plan. It's a compound component, meaning it's made of named sub-parts you compose
together rather than one component with a long list of props: put any of `Card.Media` (edge-to-edge media),
`Card.Header`, `Card.Body`, and `Card.Footer` inside `Card`, in any order — every one is optional.

The card itself carries no padding: each section pads itself and spaces itself evenly from its neighbours,
so `Card.Media` can run edge to edge and is clipped to the card's rounded corners. `size` sets that padding.
A `variant` picks the surface — a border, a shadow, a fill, or none — and a `tone` adds a colour accent.

### Import

```tsx
import { Card } from "@dbm-design-system/components";
```

The card's header — a row for a title (and description) with an optional action on the end. Tinted when the card
has a non-neutral `tone`. Also accepts any other native `<div>` attribute beyond what's listed here (e.g.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use a `Card` to group a self-contained chunk of content that a reader treats as one thing — a plan, a
  profile, an item in a list of items.
- Pick the `variant` for the surface it sits on: `outlined` (the default) for most cases, `elevated` to lift a
  card off the page, `filled` for a quiet card on a plain page, and `ghost` when the card is already inside a
  container that draws its own boundary.
- Make a whole card clickable by rendering it as a link: `<Card asChild interactive><a href="…">…</a></Card>`.
  The link gives it real semantics and keyboard support.
- Put media in `Card.Media` so it runs edge to edge — the card has no padding of its own to fight.
- Use `tone` for a card whose whole subject carries that meaning — a failed payment, a pending review. Pair the
  colour with words in the header, so it doesn't rely on colour alone.
- Lay equal-height cards out in a grid — `Card.Body` grows to fill the spare height, so the footers line up.

</Callout>
<Callout tone="danger" title="Don't">

- Don't put other interactive controls (buttons, links, inputs) inside a card that is itself a link. Nested
  interactive elements are invalid and confusing for keyboard and assistive-technology users.
- Don't set `interactive` on a plain card and stop there — it's styling only. A `<div>` styled as clickable
  can't be reached or activated from the keyboard, and `Card` warns in development when it sees one.
- Don't use a `Card` just to add a border around one element. If there's a single piece of content and no
  sections, reach for a plain bordered container instead.
- Don't nest cards several levels deep — the surfaces compete. Use `ghost` for an inner one, or restructure.
- Don't rely on a tone's colour alone to convey its meaning — not everyone perceives the difference.

</Callout>
</div>

## Best practices

- Keep a card focused on one subject. If a card is accumulating unrelated sections, it wants to be two cards or
  a page section.
- Put the primary action in `Card.Footer`, aligned to the end (the default), and secondary or destructive ones
  before it — or spread a status and an action with `align="between"`.
- Use `size` for density, not decoration: `xs`/`sm` for dense lists of cards, `md` for general use, `lg`/`xl`
  for a card that is the main content of a spacious page.
- Give each card in a list a heading in its header — it's how a screen-reader user skims the cards.
- For a card whose content is mainly a table or a list, use that component's `ghost` variant inside the card
  so the two boundaries don't double up.

## Accessibility

<Callout tone="info" title="A plain container by default — semantics come from what you put in it">

- A `Card` renders a plain `<div>`: it adds no role and is not focusable, so it never adds a tab stop or
  changes how a screen reader reads its content. Put a real heading in `Card.Header` so each card is
  identifiable.
- To make a card a landmark or name it, give it a `role` and `aria-label`/`aria-labelledby` (for example
  `role="region"` with `aria-labelledby` pointing at its heading).
- A clickable card is a real link or button, via `asChild`. The slotted element supplies the role, keyboard
  behaviour (`Enter` on a link, `Enter`/`Space` on a button), and accessible name — which is the card's content
  read as one string, so keep it concise.
- The interactive focus ring is an outline on the card itself, following the card's rounded corners.
- A colour `tone` tints the header behind `text.primary` at 13:1 or better in every theme, and outlines the card
  with the state-identifying border tokens.

</Callout>

## Code examples

```tsx
<Card>
  <Card.Header>
    <Heading level={3}>Team plan</Heading>
    <Badge tone="success">Active</Badge>
  </Card.Header>
  <Card.Body>Up to 10 members and unlimited projects.</Card.Body>
  <Card.Footer>
    <Button variant="tertiary">Cancel</Button>
    <Button>Manage</Button>
  </Card.Footer>
</Card>

{/* Media runs edge to edge, clipped to the rounded corners */}
<Card variant="elevated">
  <Card.Media>
    <img src="/retreat.jpg" alt="A mountain valley at dawn" />
  </Card.Media>
  <Card.Body>Three nights in a quiet valley.</Card.Body>
</Card>

{/* The whole card is a link */}
<Card asChild interactive variant="elevated">
  <a href="/plans/team">
    <Card.Header>
      <Heading level={3}>Team plan</Heading>
    </Card.Header>
    <Card.Body>Up to 10 members.</Card.Body>
  </a>
</Card>

{/* A colour accent, a denser size, and a footer spread across the row */}
<Card tone="danger" size="sm">
  <Card.Header>
    <Heading level={3}>Payment failed</Heading>
  </Card.Header>
  <Card.Body>Your card ending 4242 was declined.</Card.Body>
  <Card.Footer align="between">
    <Text size="sm">Retry by Friday</Text>
    <Button>Update card</Button>
  </Card.Footer>
</Card>

{/* A native <div> attribute, passed straight through to the root */}
<Card title="Billing summary" onMouseEnter={() => prefetch()}>
  <Card.Body>…</Card.Body>
</Card>
```
