<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Pagination" tier="Molecule" />

Page navigation for a list, a table, or a set of search results that is split into pages: a previous and a next
button around a row of page numbers, with a gap standing in for the pages that don't fit. Every control is a
`Button`, laid out as a list inside a `<nav>` element (a *landmark* — a named region of the page that screen-reader
users can jump to), and the current page is marked so it's announced as such.

`pageCount` is how many pages there are, and the current page — counted from 1 — is either controlled by you
(`value` and `onValueChange`) or tracked by the component itself (`defaultValue`). `siblingCount` and `boundaryCount`
set how many page numbers show around the current page and at each end, and the row always keeps the same number of
slots, so the controls don't shift sideways as you move through the pages. With `getPageHref` every control is a real
link, so each page can have its own address. The numbers collapse to a short "Page 7 of 20" between the buttons on a
phone-width screen, or — with `compact="container"` — whenever they don't fit the width the component is given.
`variant` sets how the controls look, `showJump` adds a "Go to page" field for very long lists, and every page change
is announced to screen readers.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `Pagination` when a list or table is too long to show at once and the reader needs to reach a particular page,
  or to know how far through they are. It suits results that stay put while you move between pages.
- Compute `pageCount` from your data — `Math.ceil(totalItems / pageSize)` — and keep the current page in your own
  state (`value` and `onValueChange`), so the rest of the page can react to it.
- Give each pagination on a page its own `aria-label` ("Search results", "Comments"): a screen reader lists
  landmarks by name, and two called "Pagination" can't be told apart.
- Use `getPageHref` when each page has its own address — a server-rendered list, or a router. Links can be
  opened in a new tab, bookmarked, and followed without JavaScript.
- Put a range summary ("Showing 6–10 of 47") and a page-size `Select` beside it under a data table. `Pagination` does
  the page navigation and leaves the rest to you.
- Go back to page 1 when something that changes the number of pages changes — a new filter, a new page size.
- Set `disabled` while the next page is loading, so a second click can't queue another request. The controls stay
  focusable.
- Use `align="end"` under a table, and the default centred alignment under a list of cards or results.
- Add `showJump` for a list of hundreds of pages, where stepping or choosing from the window is slow. It stays
  available in the compact form, where it is the way to reach a page the summary hides.
- Use `compact="container"` where the width isn't the screen's — a sidebar, a resizable panel, a card — so the numbers
  give way to the summary exactly when they stop fitting.
- Use `rounded` for a softer, friendlier look — a consumer app or a marketing page — and leave it off (square-cornered) for a dense,
  data-heavy screen where it should match the table and form controls around it.
- Choose `variant` to suit the surroundings: `ghost` (the default) is quietest, `outlined` gives every control a
  boundary on a plain page, and `filled` gives a soft tint. The current page is always the filled brand colour.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use `Pagination` for content that flows and should keep loading as you scroll, or for a handful of items that
  fit on one screen. A single page (`pageCount={1}`) shows just "1"; usually you'll want to leave the pagination out.
- Don't hand it a `value` and forget `onValueChange`. A controlled component that never hears the change looks
  frozen. Use `defaultValue` if you don't need to know the page.
- Don't give both `value` and `defaultValue`. `value` wins, and `Pagination` warns in development.
- Don't set `compact="never"` on a phone with lots of controls: the row wraps onto more than one line. Leave it on
  `auto`, which collapses to "Page 7 of 20" there.
- Don't put the pagination inside the scrolling area of a long table. It should stay in view, below the table.
- Don't load a page yourself from `onValueChange` in link mode without calling `event.preventDefault()`: the
  browser will still follow the link as well.
- Don't use it for a step-by-step flow (a checkout, a wizard). Those are steps in a sequence, not pages of the same
  content.
- Don't add `showJump` to a handful of pages. The numbers are enough, and the extra field is clutter.
- Don't leave `announce` on if your own content region already announces the change — a screen reader would hear it
  twice. Set `announce={false}`.
- Don't put `compact="container"` in a place that has no width of its own — a shrink-wrapping flex item, say. It
  measures the width it is given, and one that always fits its content always "fits".

</Callout>
</div>

## Best practices

- Keep `siblingCount` and `boundaryCount` at their defaults (1 and 1) unless you have a reason. The row is then seven
  slots plus the previous and next buttons — about 410px at `md` — which is why it collapses to the summary on a phone. A
  wider window makes it wider still.
- The row never changes width as you move, so it's safe to right-align (`align="end"`) or centre it without the
  controls jumping under the pointer.
- Use `showFirstLast` for long lists where jumping to the ends is common — a log, a long archive. For a few pages it
  is clutter.
- Match `size` to the surroundings: `sm` under a dense table, `md` (the default) under a list, and `md` or larger
  where touch is the main input, so the controls are easy to hit.
- `pageCount` can change while the user is on a page — a filter applied, a row deleted. The current page is clamped
  to the new count, but tell your own state too so the page you show matches.
- Translate the text the component supplies with `labels` — the accessible names ("Previous page", "Page 3") and the
  "Page 3 of 20" summary. Anything you leave out stays English.
- With `showFirstLast` and a page count of 100 or more, the compact row ("Page 7 of 200" between four buttons) needs
  about 305px, which is more than a 320px phone leaves once the page has its gutters, so it wraps onto a second line.
  Where that matters, use `showJump` instead of `showFirstLast` on a phone; the field goes on its own line.
- `compact="container"` measures the row while its numbers are showing, and again whenever the component's width
  changes. It grows to fill the space it is given, so in a flex row it takes what the other items leave.
- A paginated table needs its own accessible name and a way to know which rows are showing. The range summary
  ("Showing 6–10 of 47") does both for sighted users; give the table an `aria-label` or a caption for everyone else.

## Accessibility

<Callout tone="info" title="A named navigation landmark, a list of real buttons or links, and the current page announced">

- The component renders `<nav>` containing a list. The list announces how many controls there are; the `<nav>` is a
  landmark that screen-reader users can jump to by name. It's called "Pagination" unless you say otherwise — give each
  one on a page its own `aria-label` (or point `aria-labelledby` at a heading), because two with the same name can't
  be told apart.
- The current page is marked `aria-current="page"`, and every page's accessible name is "Page 3" (translatable through
  `labels`), which contains the number it shows, as label-in-name expects. The previous, next, first, and last
  buttons have names only — they hold an icon.
- The gaps ("…") are decorative and hidden from assistive technology.
- Every control is a `<button>`, or, with `getPageHref`, a real `<a href>` — so a link can be opened in a new tab.
  A modified click (Ctrl, Cmd, Shift, Alt, or the middle button) is left to the browser and doesn't count as a page
  change.
- When a control isn't available — Previous on page 1, Next on the last page, or everything while `disabled` — it is
  `aria-disabled`, not natively `disabled`. It stays in the tab order, so if you press Previous and land on page 1,
  keyboard focus stays on that button instead of falling back to the top of the page.
- Keyboard: `Tab` moves through the controls in reading order. `Enter` activates any control, and `Space` activates a
  button (a link, like every link, responds to `Enter` only).
- When the page changes, "Page 6 of 20" is announced (politely, without moving focus) through a visually hidden
  `role="status"` region that is in the page from the start and only has its text changed — which is what a live
  region needs to be announced reliably. The text is cleared about a second later, so it isn't also read a second time
  when browsing. It uses the `summary` label, so it translates with the rest. Turn it off with `announce={false}` if
  your own content region already announces the change. This is the widely used pattern, but announcements are
  ultimately up to each screen reader, so check the wording in the ones you support.
- When the numbers collapse (on a phone, or in `container` mode) they are removed with `display: none`, so they leave
  the tab order and the accessibility tree along with the screen. What's left — the buttons and the "Page 7 of 20"
  text — is what's read.
- The jump field is a real form: a visible label ("Go to page") tied to a number field with `<label for>`, and a
  submit button, so it works with a keyboard (Enter) and with a touch keyboard that has no Enter key. A number outside
  the range goes to the nearest page rather than raising an error, and the field is emptied afterwards. It is natively
  disabled, not `aria-disabled`, while `disabled` is set, because it is a form control.
- The arrows follow the reading direction: under right-to-left text they flip, and `align` mirrors.
- Contrast: the current page's label on its fill measures at least 6.08:1, the other pages' labels at least 4.63:1
  (including hovered, and on the `filled` variant's tint), and the gap and summary text at least 6.88:1, in every
  theme. The arrow icons are at least 3.99:1, above the 3:1 floor for graphics, and the `outlined` variant's border is
  at least 6.08:1 against the page.
- The smallest size (`xs`) is a 30px square, above the 24px minimum for a target; prefer `md` or larger where touch is
  the main input.

</Callout>

## Code examples

```tsx
// Controlled: you hold the page, so the rest of the page can react to it
const [page, setPage] = useState(1);

<Pagination pageCount={Math.ceil(items.length / 10)} value={page} onValueChange={setPage} />

// Uncontrolled: it tracks the page itself; you're told when it changes
<Pagination pageCount={20} defaultValue={3} onValueChange={(page) => track(page)} />

// Each page has its own address, so every control is a real link
<Pagination
  pageCount={20}
  defaultValue={3}
  getPageHref={(page) => `/results?page=${page}`}
  aria-label="Search results"
/>

// Client-side routing: cancel the browser's navigation and hand the page to your router
<Pagination
  pageCount={20}
  value={page}
  getPageHref={(page) => `/results?page=${page}`}
  onValueChange={(page, event) => {
    event.preventDefault();
    navigate(`/results?page=${page}`);
  }}
  aria-label="Search results"
/>

// A wider window, jump-to-first and jump-to-last, and right-aligned under a table
<Pagination pageCount={200} value={page} onValueChange={setPage} siblingCount={2} showFirstLast align="end" />

// While the next page loads, and a smaller size for a dense table
<Pagination pageCount={20} value={page} onValueChange={setPage} size="sm" disabled={isLoading} />

// A narrow place, such as a sidebar: always the compact summary
<Pagination pageCount={20} value={page} onValueChange={setPage} compact="always" />

// Numbers while they fit the width it is given, the summary when they don't
<div style={{ width: "18rem" }}>
  <Pagination pageCount={20} value={page} onValueChange={setPage} compact="container" />
</div>

// A long list: a jump-to-page field. Type a page and press Enter; out of range goes to the nearest page
<Pagination pageCount={500} value={page} onValueChange={setPage} showJump />

// A different treatment for the controls (the current page is always the filled brand colour)
<Pagination pageCount={20} value={page} onValueChange={setPage} variant="outlined" />

// Round controls: circles, and pills for wide page numbers
<Pagination pageCount={20} value={page} onValueChange={setPage} rounded />

// Your own content region already announces the change, so don't announce it twice
<Pagination pageCount={20} value={page} onValueChange={setPage} announce={false} />

// Translated
<Pagination
  pageCount={20}
  value={page}
  onValueChange={setPage}
  labels={{
    navigation: "Paginación",
    previous: "Página anterior",
    next: "Página siguiente",
    page: (page) => `Página ${page}`,
    summary: (page, pageCount) => `Página ${page} de ${pageCount}`,
  }}
/>

// A native <nav> attribute, passed straight through
<Pagination pageCount={20} value={page} onValueChange={setPage} title="Result pages" lang="en" />
```
