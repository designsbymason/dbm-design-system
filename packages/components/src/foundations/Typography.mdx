# Typography

Three font families, a fluid `clamp()`-based size scale that responds to viewport width without
jumping between fixed breakpoints, and the weight/line-height/letter-spacing scales that pair with
them. Together these cover every text style in the library — no component sets a raw `px`/`rem`
font size, weight, or line-height outside these tokens.

## Fluid type scale

Built with the standard "Utopia" `clamp()` formula — two type scales (ratio 1.2 at a 320px
viewport, 1.25 at 1440px) interpolated so text scales smoothly with the viewport instead of
jumping between fixed breakpoint values. **Sizes at or below `base` are fixed, not fluid** —
scaling small UI text down further on large screens adds nothing and risks going under comfortable
reading size; fluid scaling only kicks in from `md` upward, where it creates a real, felt
improvement in heading hierarchy across screen sizes. Resize this browser window to see the
`md`–`6xl` rows respond; `xs`–`base` stay fixed.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `font-size.xs`–`base` for any UI chrome that should stay a stable, comfortable size
  regardless of viewport — labels, helper text, table cells.
- Use `font-size.md` and up for headings, where fluid scaling actually improves the reading
  experience across screen sizes.
- Pair `font-family.secondary` deliberately, for genuine editorial contrast — not as a default
  heading font.

</Callout>
<Callout tone="danger" title="Don't">

- Don't hardcode a `px`/`rem` font size in component CSS — every size traces to a `font-size.*`
  token, fluid or fixed.
- Don't assume every heading needs the largest available step — match `font-size` to the actual
  information hierarchy of the page, not just "biggest is boldest."

</Callout>
</div>
