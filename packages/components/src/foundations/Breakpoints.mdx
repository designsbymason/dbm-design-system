# Breakpoints

The responsive layout scale, extending past a typical consumer-web set at the top end to cover
enterprise dashboard monitors — a deliberate choice given DBM's target use cases skew toward
data-dense internal tools as much as consumer apps.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Design mobile-first: base styles target the smallest viewport, with `min-width` media queries
  layering on enhancements at each breakpoint upward — not the reverse.
- Test every component across the full scale, not just desktop — responsive behavior is a
  definition-of-done requirement for every component in this library, the same standing as
  accessibility.

</Callout>
<Callout tone="danger" title="Don't">

- Don't hardcode a pixel breakpoint in a media query — reference `breakpoint.*` so the responsive
  scale stays centrally defined and consistent across every component.
- Don't design only for `xl`/`2xl` and treat smaller viewports as an afterthought — DBM
  components are expected to work across the full scale, desktop-first-with-mobile-bolted-on-later
  is explicitly not the standard here.

</Callout>
</div>
