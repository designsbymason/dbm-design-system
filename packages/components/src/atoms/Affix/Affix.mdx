<ComponentHeader title="Affix" tier="Atom" />

A sticky-positioning wrapper — sticky table headers, filter bars, section nav (`axis="vertical"`,
the default), or a sticky lead column in a horizontally-scrolling comparison table, a sticky lead
card in a swiper (`axis="horizontal"`). Wraps `position: sticky` with real stuck-state *detection*:
a hidden sentinel element tracked via `IntersectionObserver` reports when the wrapped content has
actually started sticking, exposed both as a `data-stuck` DOM attribute (for pure-CSS reactions,
e.g. a shadow that appears once stuck) and via the `onStickyChange` callback (for reactions that
need real state, e.g. swapping the label shown in the header). SSR-safe — the observer only ever
attaches client-side.

### Import

```tsx
import { Affix } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Pass `scrollContainerRef` whenever `Affix` lives inside its own scrollable panel (a modal body, a
  dashboard card with `overflow: auto`) rather than the page itself — otherwise the stuck-state
  *detection* measures against the viewport and won't correlate with the panel's own scroll
  position, even though the visual sticking itself still works correctly either way.
- React to `data-stuck` in CSS for purely presentational changes (a border/shadow appearing once
  stuck) — it's already there for free, no `onStickyChange` wiring needed.
- Use `onStickyChange` when the reaction needs real component state — swapping visible text,
  triggering an animation, anything beyond what a CSS attribute selector can express.
- Reach for `asChild` (with `sentinelAs="td"`/`"th"` alongside it) when the sticky element needs to
  be a real HTML `<table>`'s `<td>`/`<th>` itself — a bare `<div>` can't be inserted into a `<tr>`
  without breaking the row.

</Callout>
<Callout tone="danger" title="Don't">

- Don't assume `Affix` needs `scrollContainerRef` just because it's nested inside other elements —
  only a genuinely *scrollable* ancestor (its own `overflow: auto`/`scroll`) changes what the
  stuck-state detection needs to measure against; ordinary non-scrolling wrappers don't.
- Don't expect `edge="end"` to also mirror `data-stuck`'s *meaning* — it still just means "the
  sentinel has left view," now measured from the opposite edge, not a different kind of state.
- Don't skip `scrollContainerRef` for `axis="horizontal"` — page-level horizontal scroll is rare,
  so almost every real horizontal use case (a comparison table, a swiper) needs it, unlike
  `axis="vertical"`, where the whole page scrolling is the common case.
- Don't use `asChild` without `sentinelAs` inside a real `<table>` row — the sentinel still defaults
  to a plain `<div>` even in `asChild` mode (it's always a plain sibling of the sticky element, never
  wrapped inside it — see `Affix.tsx`'s own comment on why), and React itself warns loudly the moment
  a `<div>` lands as a direct child of a `<tr>`: set `sentinelAs="td"` (or `"th"` in a header row) to
  keep the row's markup valid.
- Don't forget the sentinel is a genuine sibling *cell* once `sentinelAs` is `"td"`/`"th"` — it
  occupies a real table column of its own (browsers align columns purely by cell index, with no
  concept of a "skipped" column), so any row *without* a matching placeholder cell at that same index
  will have every column after it silently shift by one. Give every other row in the table a plain
  `aria-hidden` placeholder `<td>` at the same position, sized to match (`space.px` is enough — the
  sentinel itself is 1px). See the `WithinTable` story below for the pattern.
- Don't forget `children` must be a single valid React element in `asChild` mode — `Slot` (the
  underlying Radix primitive) requires exactly one child to merge props onto; it can't be text or a
  fragment with multiple children.
- Don't expect `axis="horizontal"` to work inside a `transform`-driven swiper/carousel (one that
  moves slides via `transform: translateX()` rather than genuine `overflow-x` scrolling) — both
  `position: sticky` and the `IntersectionObserver` this component relies on need a real scroll
  offset to react to; a transform never produces one, so nothing will stick no matter how correctly
  `Affix` itself is configured. This is a real, common gotcha — many hand-rolled or third-party
  carousels use `transform` specifically to animate between slides, not `overflow-x: auto` at all.

</Callout>
</div>

## Best practices

- Reach for `Affix` instead of hand-rolling `position: sticky` directly whenever a consumer needs
  to *react* to the stuck state (a shadow, a swapped label) — that's the real value this component
  adds over the bare CSS property, which offers no way to detect it on its own.
- Keep the wrapped content's own size along the sticking axis stable across the stuck/unstuck
  transition — height for `axis="vertical"`, width for `axis="horizontal"` — `Affix` doesn't reserve
  layout space for it, so a size change on stick can cause a visible content jump.
- Freezing a whole table *column* (not just its header) needs `position: sticky` on every cell in
  that column — it's a per-element CSS property, there's no single declaration that sticks an entire
  `<col>`. Wrap only the header cell in `Affix` (the one real sentinel/detector for that column); give
  the other cells in the same column the same `position: sticky` + `insetInlineStart`/`insetInlineEnd`
  directly, driven by the header's own detected `onStickyChange` state for their matching visual
  treatment. Don't wrap every cell in its own `Affix` — every cell in a column crosses the edge at the
  exact same scroll position, so per-cell detection would just be redundant `IntersectionObserver`s
  re-deriving an answer the header's own one sentinel already has. See the `WithinTable` story below.

## Accessibility

<Callout tone="info" title="A structural wrapper, not an interactive widget">

- `Affix` sets no ARIA role or attributes of its own — it's a plain, non-interactive `<div>`, and
  accessibility is a function of whatever semantic content is passed as `children` (a real
  `<table>`'s `<thead>`, a `<nav>`, etc.), the same way `Box` works.
- The sentinel element used for stuck-state detection is `aria-hidden="true"` and has no visible
  content — it never reaches assistive tech.
- If `scrollContainerRef` points at a genuinely scrollable region, that region itself needs its own
  keyboard-accessibility treatment (`tabIndex={0}` at minimum) per WCAG 2.1.1 — `Affix` doesn't add
  this for you, since it doesn't own that element. This applies equally to `axis="horizontal"`,
  where `scrollContainerRef` is the common case rather than the exception — see every horizontal
  story in this file's own Variants/Playground sections for the pattern (`role="region"` +
  `tabIndex={0}` + `aria-label` on the scrolling container itself).

</Callout>

## Code examples

```tsx
<Affix offset={0}>
  <TableHeader />
</Affix>

<Affix edge="end" onStickyChange={setIsStuck}>
  <FilterBar />
</Affix>

// Inside its own scrollable panel, not the page
const panelRef = useRef<HTMLDivElement>(null);
<div ref={panelRef} style={{ overflow: "auto", height: "20rem" }}>
  <Affix scrollContainerRef={panelRef}>
    <FilterBar />
  </Affix>
  {/* ...panel content... */}
</div>

<Affix data-testid="section-nav" onFocus={trackNavFocus}>
  <SectionNav />
</Affix>

// A sticky lead column in a horizontally-scrolling comparison table
const tableScrollRef = useRef<HTMLDivElement>(null);
<div ref={tableScrollRef} style={{ display: "flex", overflowX: "auto" }}>
  <Affix axis="horizontal" scrollContainerRef={tableScrollRef}>
    <LeadColumn />
  </Affix>
  {/* ...remaining columns... */}
</div>

// A sticky lead column inside a *real* HTML table — asChild makes the <th>
// itself the sticky element (no wrapping div), sentinelAs keeps the hidden
// sentinel a valid sibling <th> inside the same <tr>
const tableRef = useRef<HTMLDivElement>(null);
<div ref={tableRef} style={{ overflowX: "auto" }}>
  <table>
    <thead>
      <tr>
        <Affix asChild axis="horizontal" sentinelAs="th" scrollContainerRef={tableRef}>
          <th>Lead cell</th>
        </Affix>
        {/* ...remaining header cells... */}
      </tr>
    </thead>
    {/* ...table body... */}
  </table>
</div>
```
