<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Badge" tier="Atom" />

A small status, count, or label indicator. Six tones (`brand` is the system's own identity color,
for things like "New"/"Beta" labels; the rest are feedback-type) across two visual weights —
`subtle` (low-emphasis) and `solid` (high-emphasis, the default) — and a five-step `size` scale.
Renders inline as a standalone label by default, or set `anchor` to overlap the corner of another
element instead (the "notification dot on a bell icon" pattern) — `position` and `overlap` tune
where and how tightly it tucks in. A numeric `children` value changing (e.g. an incrementing count)
triggers a brief scale pop automatically, `max` caps runaway counts at a fixed `"{max}+"` ceiling
instead of growing without limit, and `hideZero` removes the badge entirely once a live count
drops back to `0`.

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `dot` for a plain "has updates" indicator with no count, and pair it with `aria-label` (or
  `aria-labelledby`) whenever the dot needs to convey real meaning rather than being purely
  decorative.
- Set `max` on any badge showing an open-ended count (unread messages, cart items) so a large
  number doesn't grow into an unreadably long pill.
- Set `hideZero` on a live count badge so it disappears automatically once the count drops back
  to `0`, instead of sitting there showing an empty-looking "0".
- Leave `anchor` unset for a badge that should just sit inline as one more element in a flex
  layout (a count next to a label inside a `Button`, tab, or input) — `anchor` is specifically for
  overlapping the corner of another element, not general layout.
- Match `overlap` to the anchor's shape: `circular` for round anchors (an `Avatar`),
  `rectangular` (the default) for everything else (an `IconButton`, a custom shape).

</Callout>
<Callout tone="danger" title="Don't">

- Don't pass `children` alongside `dot` expecting it to show — `dot` always renders as a minimal
  dot with no visible content and silently ignores `children`; Badge warns once in development if
  you do.
- Don't override `variant="subtle"` on an anchored count/text badge — that pale fill is meant to
  sit on a card/page background, and reads as barely visible floating over arbitrary anchor
  content with no guaranteed contrasting surface behind it.
- Don't expect `dot`'s fill to follow `variant` — a dot always uses its own contrast-verified
  indicator token regardless of `variant`, since the `subtle` tones are only ever verified as a
  background for text, not as a small standalone graphic.
- Don't forget `aria-label`/`aria-labelledby` on a meaningful `dot` — an unlabeled dot renders
  `aria-hidden` and is invisible to assistive tech even though it's visually present.

</Callout>
</div>

## Best practices

- Match `size` to the density of the surrounding UI: `xs`/`sm` for compact lists and tables, `md`
  (the default) for standard content, `lg`/`xl` for higher-emphasis contexts.
- The defaults (`tone="danger"`, `variant="solid"`) suit the most common alerting case (errors,
  unread counts) — override `tone` for other meanings (`brand` for "New"/"Beta", `success`/
  `warning`/`info` for status) and `variant="subtle"` for lower-emphasis inline labels that
  shouldn't compete with surrounding content.
- For a live-updating count (unread messages, notifications), no extra wiring is needed — the pop
  animation fires automatically whenever `children` changes to a new value.
- Compose Badge inline (no `anchor`) inside other components' own layouts rather than trying to
  position it manually — it's just a `display: inline-flex` span with no positioning opinions of
  its own until `anchor` is set.

## Accessibility

<Callout tone="info" title="A decorative dot by default, a meaningful one when you ask for it">

- **Dev-mode warning** (stripped in production): `children` provided alongside `dot` warns once
  via `console.warn`, since `dot` always renders as a minimal dot with no visible content and
  would otherwise silently discard it.
- **`dot` is `aria-hidden` and purely decorative by default.** Pass `aria-label` or
  `aria-labelledby` to give it `role="img"` and a real accessible name instead, for a dot that
  needs to convey meaning (e.g. "3 unread notifications").
- **A text/count badge needs no extra ARIA** — its visible `children` already provide the
  accessible name.
- **Every `tone` × `variant` background/text pairing is contrast-verified** against WCAG 1.4.3's
  4.5:1 text floor. `dot` mode uses a separate set of tokens (the `-indicator` family, plus
  `bg.neutral`), verified instead against WCAG 1.4.11's 3:1 non-text floor, since a dot has no
  text to lean on — see [Design tokens used](#design-tokens-used) below for the exact tokens.
- **The count-change pop animation is a one-shot transition, not a continuous/looping one**, so
  it isn't gated behind `prefers-reduced-motion` — only continuous animation (spinners, pulses)
  is in scope for that preference in this system.
- **In `anchor` mode, a `bg.surface`-colored ring visually separates the badge** from whatever it
  overlaps — purely decorative, not something assistive tech needs to know about.
- **`hideZero` removes the badge from the DOM entirely** (not just visually) when it hides a zero
  count, so assistive tech never announces it — `anchor`, if set, still renders on its own.
- **`position` is a physical corner, not a logical one** — `top-right` stays at the visual
  top-right in both LTR and RTL rather than mirroring, since `anchor` is arbitrary visual content
  (an icon, an avatar) rather than something tied to reading-flow direction. Matches MUI's own
  `Badge` `anchorOrigin`, which doesn't mirror either.

</Callout>

<Badge>Failed</Badge>
<Badge tone="brand">New</Badge>

<Badge hideZero>{0}</Badge>
<Badge dot aria-label="Unread notifications" />
<Badge size="lg">Failed</Badge>
