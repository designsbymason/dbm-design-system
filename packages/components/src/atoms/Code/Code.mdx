<ComponentHeader title="Code" tier="Atom" />

A short, inline monospace code snippet — a single word, identifier, or short expression sitting
within a line of running text (e.g. "Run `pnpm install` to get started"). Renders as a native
`<code>` with a tinted background pill, sized in the token system's monospace font stack. For
multi-line, syntax-highlighted code with a copy button, a future `CodeBlock` molecule is the
right fit instead — `Code` is deliberately for short, single-line references only.

### Import

```tsx
import { Code } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `Code` for a single word, identifier, command, or short expression referenced inline within
  a sentence — a package name, a CLI command, a variable name.
- Let it inherit the surrounding text's font size (its own default behavior) — it's designed to sit
  inside `Text`/`Heading`/list content at whatever size that content already is, not to introduce
  its own independent size scale.
- Reach for a future `CodeBlock` instead once real multi-line or syntax-highlighted code is needed
  — `Code` intentionally stays single-line only.

</Callout>
<Callout tone="danger" title="Don't">

- Don't use `Code` for multi-line snippets — it has no line-wrapping affordance for a real code
  block, no syntax highlighting, and no copy button.
- Don't override its font size directly — it's designed to inherit from its surrounding context
  (see the Inherits surrounding font size variant above); forcing a fixed size defeats that.
- Don't reach for `Code` to render a keyboard shortcut — use `Kbd` instead, which has its own
  distinct key-cap visual treatment for that specific purpose.

</Callout>
</div>

## Best practices

- Keep the content short — a package name, command, file path, or identifier reads well inline;
  a long unbroken string (e.g. a deep file path) will wrap at the container edge rather than
  overflow, but still reads more naturally as a `CodeBlock`-style reference once it's genuinely long.
- `Code` and `Kbd` are visually similar (both monospace, both pill-shaped) but serve different
  roles — `Code` marks up a literal code reference, `Kbd` marks up a keyboard key or shortcut.
  Don't use one for the other's job even though the visual difference is subtle.

## Accessibility

<Callout tone="info" title="Semantic HTML carries the meaning — no ARIA needed">

- Renders a native `<code>` element, which already communicates "this is a code reference" to
  assistive technology with zero ARIA required.
- No keyboard interaction — `Code` is not an interactive element.
- The background/border pill is purely visual; screen readers announce the text content exactly
  as if it were plain text within the surrounding sentence.

</Callout>

## Code examples

```tsx
<Text>Run <Code>pnpm install</Code> to install dependencies.</Text>
```

```tsx
// Inherits whatever font size its surrounding context is set to
<Text size="lg">
  Set <Code>NODE_ENV</Code> to <Code>production</Code> before deploying.
</Text>
```

```tsx
// A native <code> attribute (lang) passed straight through
<Code lang="bash">pnpm install</Code>
```
