<ComponentHeader title="IconButton" tier="Atom" />

An icon-only button. Shares `Button`'s variant/size scale and loading behavior, but always
requires `aria-label` since there's no visible text to derive an accessible name from. Also
supports an optional `pressed`/`defaultPressed` toggle state (paired with `onPressedChange`) for a
favorite/bookmark/mute-style control — while pressed, the icon switches to Phosphor's "fill"
weight and the button takes on a tone-specific "on" treatment, reinforcing the state visually
beyond color alone.

### Import

```tsx
import { IconButton } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Always pass `aria-label` (or `aria-labelledby`) — it's required by the type, and `IconButton`
  also warns once in development if neither resolves to a value, as a runtime safety net for a
  consumer that bypasses the type (an untyped call site, or an agent-generated one).
- Use `pressed`/`defaultPressed` + `onPressedChange` for a genuine toggle affordance (favorite,
  bookmark, mute) instead of hand-rolling your own active-state styling — the pressed treatment,
  the fill-weight icon swap, and `aria-pressed` all come for free together.
- Match `variant` to emphasis the same way as `Button`: `primary` for the single highest-emphasis
  icon action in a toolbar, `ghost`/`tertiary` for secondary, lower-emphasis ones.
- Reach for `rounded` for floating-action-button-style triggers.

</Callout>
<Callout tone="danger" title="Don't">

- Don't pass `icon` expecting it to render in `asChild` mode — Radix `Slot` always renders
  `children` directly, and `icon` has no fallback role there (it's still required by the type,
  since it's the only accessible-icon path outside `asChild`). `IconButton` warns once in
  development when this happens.
- Don't set `defaultPressed` without pairing it with a real `onPressedChange` if you also intend to
  read the pressed state elsewhere — an uncontrolled toggle manages its own internal state, so a
  parent that needs to know the current value should switch to the controlled `pressed` +
  `onPressedChange` pair instead.
- Don't reach for `IconButton` when the action needs a visible text label as part of the design —
  use `Button` with `leadingIcon`/`trailingIcon` instead; an icon-only control is only appropriate
  when the icon's meaning is unambiguous on its own (and even then, `aria-label` still carries the
  real accessible name).

</Callout>
</div>

## Best practices

- Match `size` to context density, same as `Button`: `sm`/`xs` for compact toolbars and tables,
  `md` (the default) for standard forms, `lg`/`xl` for high-emphasis contexts.
- `isLoading` always makes the button non-interactive (`isDisabled = disabled || isLoading`), even
  if `disabled` is explicitly `false` — you don't need to pass both.
- Choose controlled (`pressed`/`onPressedChange`) over uncontrolled (`defaultPressed`) whenever the
  favorited/toggled state needs to stay in sync with application state elsewhere (e.g. persisted
  per item in a list) — uncontrolled is the right fit for state that's purely local to that one
  button.
- `IconButton`'s box size (all 5 steps, square and circular alike) is deliberately matched to
  `Button`'s own real rendered height at the equivalent size — the two read as visually aligned
  when placed side by side, e.g. an `IconButton` next to a `Button` in the same toolbar row.

## Accessibility

<Callout tone="info" title="Keyboard support and state come from the native button">

- Renders a native `<button type="button">` by default — full keyboard support (`Tab` to focus,
  `Enter`/`Space` to activate) comes for free from the browser, not from custom key handling.
- `aria-label` is required by the type; `IconButton` also warns once in development if it (and
  `aria-labelledby`) both resolve to nothing, since an icon-only button with no accessible name is
  invisible to screen reader users.
- `aria-pressed` is only ever rendered when the button is genuinely a toggle (`pressed`,
  `defaultPressed`, or `onPressedChange` set) — a plain, non-toggle button never gets a stray
  `aria-pressed="false"`. Withheld entirely in `asChild` mode, even when the button is a toggle:
  `aria-pressed` is only a valid ARIA attribute on a role that supports it (e.g. `button`), and
  `Slot` can render onto an element that doesn't (e.g. a native `<a>`, whose `link` role
  disallows it). The pressed visual treatment still applies regardless — only the ARIA attribute
  is withheld, with a development-mode warning explaining why. If the slotted element itself needs
  `aria-pressed`, set it directly on that element.
- `aria-busy="true"` is set automatically while `isLoading`, so assistive tech announces the
  in-progress state; `loadingLabel` (falling back to `aria-label`) is announced in its place.
- In `asChild` mode, the slotted element can't take a native `disabled` attribute (it might not
  even be a `<button>`), so `disabled` instead applies `aria-disabled` plus a click-blocking
  handler — the visual and interactive effect matches native `disabled` even though the DOM
  attribute can't.
- Every `variant` × state (rest, hover, pressed, hover-while-pressed) background/icon-color pairing
  is checked against real WCAG contrast ratios, not assumed — see
  [Design tokens used](#design-tokens-used) below for the exact tokens.
- The loading spinner respects `prefers-reduced-motion` — its spin animation runs at a quarter
  speed (4× the normal duration) for users who've set that OS preference, rather than being
  disabled outright, since the spinner's motion is also its only signal that something is still in
  progress.

</Callout>
