<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Skeleton" tier="Atom" />

A placeholder shape rendered in place of real content while it's still loading — a colored block
that mimics the size and form of what's coming, rather than a generic spinner. Three variants match
common content shapes: `text` for a line of copy (a fixed `1em` tall), `circular` for avatars and
icons, and `rectangular` for images, cards, and other larger blocks. Two animation styles —
`pulse` (the default, a gentle opacity fade) and `wave` (a moving gradient shimmer) — signal that
content is still loading; `animation="none"` renders a static placeholder instead. Purely
decorative and hidden from the accessibility tree by design — pair it with a separate live region
(an `aria-live` element that announces changes to screen readers) elsewhere in the loading UI if
you need to announce loading state to assistive technology. Compose multiple `Skeleton` instances
(via `Stack` or any flex layout) to mirror a real composed layout, rather than expecting one
instance to auto-size to arbitrary content.

### Import

```tsx
import { Skeleton } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Match `variant` to the real content's shape (`circular` for avatars, `text` for lines,
  `rectangular` for images/cards) so the placeholder telegraphs the coming layout instead of
  reading as a generic gray blob.
- Compose multiple `Skeleton` instances (via `Stack` or plain flex) to mirror a real composed
  layout — see "Composed: card loading placeholder" above.
- Set explicit `width`/`height` matching the real content's actual dimensions where you know them
  ahead of time, so nothing jumps or reflows once real content replaces the placeholder.
- Use `animation="none"` in a dense, high-count context (a table with many skeleton cells) where
  many simultaneous animations would be visually distracting.

</Callout>
<Callout tone="danger" title="Don't">

- Don't rely on `Skeleton` alone to announce loading state to assistive tech — it's `aria-hidden`
  by design, non-overridable; pair it with a separate live region elsewhere in the loading UI if
  you need to announce progress.
- Don't expect a sharp, zero-radius corner from `variant="rectangular"` — it always carries this
  system's house soft-radius; use `className`/`style` for the rare case a hard corner is genuinely
  needed.
- Don't pass `children` expecting content-driven auto-sizing or a wrapping "swap to real content"
  mode — `Skeleton` is a standalone placeholder shape with neither; compose separate instances
  instead of nesting real content inside one.

</Callout>
</div>

## Best practices

- Match the number and arrangement of `Skeleton` instances to the real content's actual layout,
  not a single oversized generic block — this is what makes a loading state feel responsive rather
  than jarring once content arrives.
- Keep animation consistent within one loading region — mixing `pulse` and `wave` in the same view
  reads as unpolished, even though either is a perfectly fine default on its own.
- Prefer `pulse` (the default) for most cases; reach for `wave` when a more directional,
  per-line reading motion helps (e.g. multi-line text placeholders).

## Accessibility

<Callout tone="info" title="Decorative by design — pair with a live region for real announcements">

- **Always `aria-hidden="true"`, and not overridable** — this component has no accessible name or
  role of its own and shouldn't be perceived as a UI element by assistive tech, even if a caller
  tries to pass their own `aria-hidden`.
- **No live region of its own.** If you need to announce "Loading…" or a completion state to
  screen reader users, add a separate `aria-live` region elsewhere in the loading UI — `Skeleton`
  deliberately doesn't take this on, since it's a purely visual placeholder.
- **Both animations respect `prefers-reduced-motion`** — automatically switching to a static,
  unanimated appearance rather than being hidden outright, so it still functions as a visible
  placeholder without a continuous, potentially uncomfortable animation.
- **No keyboard interaction.** `Skeleton` renders no focusable content, so there's nothing to tab
  to and nothing to verify for keyboard navigation.

</Callout>

## Code examples

```tsx
<Skeleton variant="circular" width={40} height={40} />
<Skeleton variant="text" width="80%" />
<Skeleton variant="rectangular" animation="wave" />
<Skeleton animation="none" />
<Skeleton variant="text" width="12rem" title="Loading headline…" />
```

```tsx
<Stack direction="row" gap={3}>
  <Skeleton variant="circular" width={40} height={40} />
  <Stack gap={2} style={{ flex: 1 }}>
    <Skeleton variant="text" width="60%" />
    <Skeleton variant="text" width="90%" />
  </Stack>
</Stack>
```
