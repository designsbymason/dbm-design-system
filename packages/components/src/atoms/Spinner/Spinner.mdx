<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Spinner" tier="Atom" />

An indeterminate loading indicator — a rotating ring at a token-driven `size`. Decorative
(`aria-hidden`) and silent to screen readers by default, since a spinner alone rarely tells the
whole story of what's loading; pass `label` (e.g. `"Loading"`) to announce it via `role="status"`
instead. `tone` reuses the same color scale `Icon` uses, defaulting to inheriting `currentColor`
from context (e.g. a colored button) rather than a fixed color. Respects
`prefers-reduced-motion` — the spin slows rather than stops outright, since a fully static spinner
reads as frozen, not as respecting the preference. Reach for `ProgressBar`/`ProgressCircle`
instead once a real, measurable value exists — Spinner is for progress that genuinely can't be
represented as a fill.

### Import

```tsx
import { Spinner } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Pass `label` whenever the loading state should actually be announced to assistive tech —
  Spinner is silently decorative by default, since a bare spinner alone often isn't the most
  useful thing to announce (a surrounding message, or a `Skeleton`, frequently communicates more).
- Let `tone` inherit `currentColor` (the default) when the spinner already sits inside colored
  context — a button, a colored banner — and only set an explicit tone when it's standing alone.
- Switch to `ProgressBar`/`ProgressCircle` as soon as a real, measurable value exists —
  indeterminate conveys strictly less information and should be a bridging state, not the norm.

</Callout>
<Callout tone="danger" title="Don't">

- Don't rely on Spinner's `tone` to communicate status the way `ProgressBar`/`ProgressCircle`'s
  `tone` does — here it's purely a color choice for a loading state, not a semantic signal tied to
  success/warning/danger outcomes.
- Don't try to override `role`, `aria-hidden`, or `aria-label` yourself — Spinner computes and
  always applies these itself from `label`, so a same-named prop is silently ignored (found and
  fixed during review — see Accessibility below).
- Don't treat the absence of `label` as a bug — a decorative, unlabeled spinner is Spinner's
  intended default, not a missing accessible name that needs a warning.

</Callout>
</div>

## Best practices

- Match `size` to context — small (`xs`/`sm`) for an inline indicator next to text or inside a
  button, larger (`lg`/`xl`) for a dedicated loading state filling more of the view.
- Prefer `Skeleton` over Spinner when the loading content's eventual shape is already known (a
  card, a list row) — a shape-matched placeholder reads as faster and less jarring than a generic
  spin.
- `ProgressBar`/`ProgressCircle` share a `size`/`tone` scale conceptually similar to this
  component's own, but with a real `value`/`max` — reach for them instead once progress becomes
  measurable, rather than leaving a spinner running past the point where a real value exists.

## Accessibility

<Callout tone="info" title="role and aria-hidden/aria-label are computed for you, never overridable">

- **Decorative by default (`aria-hidden="true"`), no `role`** — a spinner with no `label` has
  nothing meaningful to announce on its own, so it's silent to assistive tech rather than
  interrupting with an unlabeled status update. This is Spinner's intended default state, not an
  incomplete one — unlike `ProgressBar`/`ProgressCircle`, Spinner never warns about a missing
  accessible name in development.
- **`role="status"` plus `aria-label`, both computed from `label`** — set `label` and the spinner
  becomes a live region announcing that text, no longer `aria-hidden`.
- **All three (`role`/`aria-hidden`/`aria-label`) are always applied last**, after any native props
  spread onto the root — a same-named prop passed by the caller is silently ignored, even though
  TypeScript's JSX checker permits `aria-*`/`role` attributes on any component regardless of its
  declared prop type (a real gap found and fixed during review, the same class of bug already found
  on `ProgressBar`/`ProgressCircle`: enforced via JSX attribute order, not the type system alone).
- **Respects `prefers-reduced-motion`** — the spin animation slows to 4x its normal duration rather
  than stopping outright, staying visible as an in-progress signal.
- Every `tone` here reuses `Icon`'s own already contrast-verified tokens — no new color pairing was
  introduced by this component.

</Callout>
