<ComponentHeader title="Avatar" tier="Atom" />

A person/entity avatar. Renders an image, falling back to initials (and falling back again to a
generic person icon if there are no initials either), with an optional presence `status` dot. A
`name` prop can auto-derive both `initials` and `alt` from one string, and seed `colorful`'s
deterministic per-identity color. `size` accepts a responsive map for per-breakpoint sizing, and
`as` makes the whole avatar polymorphic — render it as `button` (or any other element/component) to
turn it into a real interactive trigger while it keeps generating its own image/initials/status
content exactly as it does by default.

### Import

```tsx
import { Avatar } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Pass `alt` (or `name`, which fills `alt` in for you) whenever the avatar represents a real
  person or entity — Avatar warns in development if it would otherwise render with no accessible
  name at all.
- Pass `name` alone to get auto-derived `initials`, a fallback `alt`, and `colorful`'s identity
  color from one prop, instead of repeating the same string three times.
- Reach for `as="button"` (or `as="a"`, or a router `Link`) when the avatar itself is the click
  target (opening a profile menu, navigating to a profile page) — it keeps Avatar's own generated
  image/initials/status content, unlike wrapping a separate `<button>` around it.
- Use `colorful` for lists of many different people (a roster, a comments thread) so they're
  visually distinguishable at a glance, not just by their (sometimes identical) initials.

</Callout>
<Callout tone="danger" title="Don't">

- Don't pass `initials=""` expecting `name`'s auto-derivation to fill in — an explicitly empty
  string is still a provided value, so it's used as-is (falls through to the generic icon, same as
  any other falsy `initials`) rather than deferring to `name`. Omit `initials` entirely instead.
- Don't treat `colorful` as a status signal — its color is a deterministic hash of identity, not
  meaningful information. Use `status` for anything that actually needs to communicate state
  (online/offline/busy/away).
- Don't set `disabled` on a default, non-interactive avatar expecting a visual effect — it only
  does anything once `as` has made the avatar an interactive trigger.
- Don't rely on the fallback icon tracking every breakpoint of a responsive `size` — `Icon` has no
  responsive size of its own, so it's sized off whichever step applies at the `base` breakpoint
  only.

</Callout>
</div>

## Best practices

- Match `size` to the density of the surrounding UI: `xs`/`sm` for compact lists and tables, `md`
  (the default) for standard content, `lg`/`xl` for profile headers and other high-emphasis
  contexts.
- Pair `status` with a real, live presence source (a websocket/polling connection) — a status dot
  that's wrong is worse than no status dot, since it actively misleads.
- For a loading placeholder while avatar data is still being fetched, compose with `Skeleton`
  (`variant="circular"`) rather than expecting Avatar itself to have a loading state — swap between
  the two based on your own data-loading state.
- For a name tooltip on hover, compose with `Tooltip` rather than expecting Avatar to show one
  itself — `<Tooltip content={name}><Avatar name={name} /></Tooltip>`.

## Accessibility

<Callout tone="info" title="An accessible name is computed for you, not just documented">

- **Dev-mode warnings** (stripped in production): `src` provided without `alt`/`name`, or no
  `src`/`initials`/`name`/`alt` at all — each warns once per instance via `console.warn`, so a
  missing accessible name surfaces during development instead of shipping silently.
- **`role="img"` + `aria-label`** are set automatically on the non-image fallback (initials/icon)
  whenever a name is available, computed from `alt` (or `name`). When both a name and `status` are
  present, they're combined into one announcement ("Jane Doe, Online") instead of two separate
  `role="img"` stops — confirmed live that back-to-back separate announcements were noisy,
  especially across a list of avatars. Without a name, the status dot keeps its own separate
  announcement instead, since there's nothing to merge it into.
- **`role="img"` is skipped when `as` renders a native interactive element** (e.g. `as="button"`)
  — overriding a `<button>`'s own role with `img` is an "aria-allowed-role" violation (confirmed
  via a live `axe` run), since it would hide the element's real interactive semantics from
  assistive tech. `aria-label` still applies regardless of `as`.
- **`disabled`** applies the native `disabled` attribute when `as="button"` specifically (the one
  case a real HTML disabled state exists); every other interactive `as` relies on `aria-disabled`
  plus a click-blocking handler instead, the same pattern `Button`'s own `asChild` mode uses.
- **Keyboard support comes from whichever native element `as` renders** — a `button`/`a` avatar is
  `Tab`-focusable and activates on `Enter`/`Space` (or navigates, for a link) with zero custom key
  handling, the same as any other native interactive element.
- **Focus ring shape matches the avatar's own shape**: fully round for the default `circle`, a
  standardized `sm`-radius square for `shape="square"` — not tied to the square's own, larger
  visual corner radius (see `05-component-api-conventions.md`'s focus-ring convention, established
  via this component).
- Every `colorful` family's background/text pairing, and every hover-state background, is
  contrast-verified per this system's WCAG methodology — see
  [Design tokens used](#design-tokens-used) below for the exact tokens.

</Callout>
