<VisuallyHidden asChild><h2>Intro</h2></VisuallyHidden>

<ComponentHeader title="Input" tier="Atom" />

A single-line text input with optional leading/trailing slots (`prefix`/`suffix` — an icon, a
currency symbol, or plain text), an optional clear (`×`) button, and an error state. Accepts both
controlled (`value`/`onChange`) and uncontrolled (`defaultValue`) usage, mirroring a native
`<input>` directly. `type` controls which kind of value it collects — `text` (default), `email`,
`tel`, `url`, and `search` are what this atom is actually built for; `password` and `number` also
work (a genuine, unrestricted native attribute) but come with their own dedicated `PasswordInput`/
`NumberInput` molecules once those ship, each adding UI this atom doesn't (a visibility toggle,
stepper controls).

### Import

```tsx
import { Input } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Pass `onClear` together with a real `value`/`onChange` (or rely on the uncontrolled DOM value) so
  the clear button has something meaningful to act on — clearing the value itself is the caller's
  own responsibility, not something `Input` does for you.
- Pair `hasError` with a nearby `FieldError` so the reason is visible, not just the red border and
  `aria-invalid`.
- Match a `prefix`/`suffix` icon's own `size` to `Input`'s size yourself — one step down, same as
  this component's own internal clear-button icon — since this slot renders arbitrary content
  as-is, with no visibility into what's inside it to resize automatically.
- Pair `showCount` with `maxLength` — `showCount` alone renders nothing, matching `Textarea`'s own
  convention.

</Callout>
<Callout tone="danger" title="Don't">

- Don't drive `value` from a live control without a real `onChange` wired back — a controlled value
  always wins over the user's own typing, which freezes the input exactly like Checkbox's own
  `checked` does.
- Don't expect changing `defaultValue` after mount to update an already-rendered input — it only
  sets the value at mount time, exactly like a real `<input defaultValue>`.
- Don't reach for this atom long-term with `type="password"`/`type="number"` — use `PasswordInput`/
  `NumberInput` once they ship, since this atom won't grow their dedicated UI (a visibility toggle,
  stepper controls) itself.

</Callout>
</div>

## Best practices

- Match `size` to the surrounding form/table density — the default `md` suits standalone forms;
  drop to `sm`/`xs` inside dense tables or compact filter bars.
- Use `readOnly` instead of `disabled` when a value should stay visible, selectable, and submittable
  in a real `<form>` but not editable — e.g. a computed or pre-filled field. `disabled` is for a
  value that shouldn't participate in the form at all.
- Reach for `Textarea` instead when the expected value can span more than one line — `Input` is
  single-line only, matching a native `<input>`'s own behavior (pressing Enter does nothing here).

## Accessibility

<Callout tone="info" title="Native <input> semantics, nothing custom to break">

- Renders a real native `<input>` — full native keyboard, focus, selection, autofill, and
  form-participation behavior applies automatically, since nothing here reimplements what the
  browser already does correctly.
- `aria-invalid="true"` is set automatically while `hasError`, in addition to the visual red
  border — the two can't drift out of sync, and a same-named consumer prop can never silently
  override it, since this component's own computed value is always applied last.
- Clicking anywhere inside the visual box — the padding, or the `prefix`/`suffix` slots — focuses
  the input directly, matching a native `<input>`'s own click-anywhere-in-box behavior.
- Pair with a `FieldLabel` (via `htmlFor`/`id`) or pass `aria-label`/`aria-labelledby` directly — an
  input with no accessible name is invisible to screen reader users, same requirement as any other
  form control.
- The clear button is a real, independently-focusable `<button aria-label="Clear">`, reachable via
  `Tab` right after the input — not a decorative icon with a click handler bolted on.
- The focus ring's `border-radius` is deliberately tightened to the standardized `sm` step while
  focused, regardless of `size`'s own larger `md` corner radius — see
  [Design tokens used](#design-tokens-used) below.

</Callout>
