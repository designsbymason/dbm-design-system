<ComponentHeader title="Switch" tier="Atom" />

A binary on/off toggle built on Radix UI's Switch primitive, with a token-driven sliding-thumb
track and an optional inline label. Accepts both controlled (`checked`/`onCheckedChange`) and
uncontrolled (`defaultChecked`) usage, mirroring the same pattern as a native
`<input type="checkbox">`.

### Import

```tsx
import { Switch } from "@dbm-design-system/components";
```

## Usage guidelines

<div className="dbm-do-dont-grid">
<Callout tone="success" title="Do">

- Use `Switch` for a setting that takes effect immediately (e.g. toggling notifications on) — that
  instant-effect expectation is what the switch shape communicates, unlike a checkbox's
  pending-until-submit convention.
- Pass `aria-label` (or `aria-labelledby`) whenever there's no visible `children` label, e.g. a
  single icon-only settings toggle.
- Set `loading` while an async toggle request is in flight, instead of leaving the switch appearing
  interactive during a request that hasn't resolved yet.
- Pair `hasError` with a nearby `FieldError` so the reason is visible, not just the red ring and
  `aria-invalid`.

</Callout>
<Callout tone="danger" title="Don't">

- Don't drive `checked` from a live control without a real `onCheckedChange` wired back — Radix
  always defers to the controlled value, which freezes the switch's own click handling.
- Don't expect changing `defaultChecked` after mount to update an already-rendered switch — it only
  sets the value at mount time, exactly like a real `<input defaultChecked>`.
- Don't set both `disabled` and `loading` expecting different behavior — `loading` already disables
  the switch on its own (via the same native `disabled` attribute), so the two compose rather than
  conflict.

</Callout>
</div>

## Best practices

- Reach for `Checkbox` instead when the choice stays pending until an explicit submit/save — the
  convention most users already associate with the checkbox shape, not the switch shape.
- Match `size` to the surrounding density — the default `md` suits a standalone settings list; drop
  to `sm`/`xs` inside a dense table row.
- Let `Switch` generate its own `id` (via `useId`) unless something else — a test, a router, an
  external `aria-describedby` — needs a stable, predictable value to point at.

## Accessibility

<Callout tone="info" title="Keyboard and ARIA state come from Radix's own switch primitive">

- Renders a `<button role="switch">` (not a native checkbox input) — `Tab` focuses it, and `Space`
  toggles it, per the WAI-ARIA switch pattern. Unlike `Button`, `Enter` isn't part of that pattern's
  keyboard contract.
- `aria-checked` reflects the real state directly as `"true"`/`"false"`, kept in sync with the
  visible thumb position automatically.
- `aria-invalid="true"` is set automatically while `hasError`, in addition to the visual danger
  ring — the two can't drift out of sync.
- `aria-busy="true"` is set automatically while `loading`, alongside the native `disabled`
  attribute that actually blocks interaction — a loading switch is genuinely unreachable by `Tab`,
  not just visually dimmed while remaining focusable.
- A dev-mode console warning fires once if a `Switch` has no `children`, `aria-label`, or
  `aria-labelledby` — a switch with no accessible name is invisible to screen reader users.
- The inline `children` label is a real `<label>` associated via `htmlFor`/`id`, so clicking the
  label text toggles the switch too, not just the track itself.
- A `disabled` (or `loading`) switch uses the native `disabled` attribute, so it's skipped by `Tab`
  entirely — not just visually dimmed while remaining reachable.
- `required` sets `aria-required` and marks the switch required for real HTML5 form validation —
  inside a `<form>`, Radix automatically renders a hidden native `<input type="checkbox">` that
  actually participates in submission (including an uncontrolled form with no JS handler), using
  `name`/`value` as its own name/value.
- The unchecked track (`bg.track-strong`) and checked track (`bg.brand`) are both checked against
  real WCAG contrast ratios, not assumed — see [Design tokens used](#design-tokens-used) below.

</Callout>

## Code examples

```tsx
<Switch defaultChecked>Email notifications</Switch>
<Switch checked={isDark} onCheckedChange={setIsDark} checkedIcon={MoonIcon} uncheckedIcon={SunIcon} />
<Switch aria-label="Airplane mode" />
<Switch hasError>Required setting</Switch>
<Switch loading>Saving…</Switch>
<Switch data-testid="notifications-switch">Email notifications</Switch>
<Switch name="notifications" value="enabled" required>Enable notifications</Switch>
<Switch autoFocus onFocus={() => trackFieldFocus('notifications')}>Notifications</Switch>
```
