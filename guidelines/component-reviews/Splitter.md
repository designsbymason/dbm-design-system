# Splitter — build findings

**Layout:** Splitter — built 2026-10-04, item 30 in the molecule build order (`04-component-inventory.md`). **Not yet declared Finalized** (the user declares that). Decision: [ADR-0037](../adr/0037-splitter-is-hand-rolled-on-the-window-splitter-pattern-with-automatic-handles-and-a-percentage-layout.md).

**What it is:** a compound component, `Splitter` + `Splitter.Pane`, that divides its container among panes with draggable, keyboard-operable handles. Orientation (a breakpoint map too), a `line` or `grip` variant, `keyboardStep`, `disabled`, `dir`, `labels`/`formatNumber` (ADR-0021); a layout held by you (`layout`/`onLayoutChange`) or by it (`defaultLayout`), `onLayoutCommit` for saving; per pane `defaultSize`, `minSize`/`maxSize` (percentages or pixels), `collapsible` with `collapsedSize` (nothing, or a strip), `collapsed`/`defaultCollapsed`/`onCollapsedChange`, and render-function `children` that receive `{ collapsed, size }`.

**Decisions put to the user before building:** sizes as percentages with pixel or percentage limits (chosen over percentages only, or mixed fixed and flexible panes); collapsible panes (chosen); no built-in storage (chosen). The rest is in the ADR.

**Composition checkpoints (06 §9):** compound sub-part completeness — `Splitter.Pane` has its own `forwardRef`, JSDoc, pass-through props and a hidden docs-only stories file for its Properties table (ADR-0013); atom reuse — none applies (the handle is its own control), `Icon`/`Divider`/`ScrollArea` appear only in stories and Related cards; consumed-atom defects — none; Radix audit — no Radix primitive underneath, none needed; cross-part ARIA wiring — each handle's `aria-controls` names the two panes' ids (a pane's own `id` or a generated one), tested and axe-clean; composed tab order — every handle is one tab stop in order (checked in Chromium across nested splitters and with a disabled one); nested provider — a splitter inside a pane has its own context and moves only its own panes (checked in Chromium).

**Findings made by looking and measuring, fixed:**
- **A collapsed strip had no way to show a different thing.** A 48px rail wrapped its label into a column of single words. A pane's `children` may now be a function of `{ collapsed, size }`, so a rail shows an icon.
- **Two of my own tests were wrong, not the component:** a measurement taken while the panes were still easing to their size (waiting for the size to settle fixed it), and a `waitFor` whose callback added and removed an element on every poll, which re-triggered itself and hung the run. Colours are now resolved once, outside the polling.
- **Mutation testing** (19 deliberate breakages of the component's logic): 15 caught at once; four survived. One is equivalent (in controlled mode the local state is never read) and one is equivalent (an effect dependency already implied by another); the other two exposed gaps, a disabled double click and an `undefined` label overriding the default, both now tested and caught. A unit test for a resize re-reading a pixel limit was added as well (the browser story already covered it); its mutant stays equivalent.

**Accepted:** at rest the `line` variant is a hairline divider (`border.default`, 1.4:1, the treatment `Divider` has), not a control drawn to 3:1; `variant="grip"` is (the mark is `bg.neutral`, 4.7:1 light and 8.2:1 dark), and the handle's 24px target is not visual. Hover and drag draw the line in the brand colour, and keyboard focus in the focus colour, thicker. Forced colours draws the line and grip in system colours (a background colour would be dropped).

**Tokens:** none added; the handle uses `border.*`, `bg.neutral*`, `space.*`, `radius.full`, `opacity.40` and the motion tokens (every one listed on the Docs page and held to the stylesheet by `Splitter.docs.test.ts`).

**Responsive:** the orientation takes a breakpoint map (checked on a phone-width story in Chromium: stacked, the handle follows); pane sizes are percentages, so a layout keeps its proportions as the container changes (measured), and a pixel limit is re-read as a percentage when it does (measured).

**Tests:** 29 for the pure model (every operation, snapping both ways, limits, infeasible moves, normalisation), 64 for the component (structure, ARIA, defaults, controlled layout, keyboard in both orientations and directions, dragging with the container's size mocked, lengths, collapsing every way, labels, props and warnings, StrictMode, server render, jest-axe), a Docs-page token guard, and 10 hidden real-browser checks (a real drag in both layouts, keyboard in pixels, the 24px target by `elementFromPoint`, collapse out of the tab order and a strip that stays, pixel limits and resize, proportions on resize, right-to-left, focus and forced colours, nested splitters, a phone). A real mouse drag in the browser pane moved a boundary 50% to 79% for 200px of a roughly 690px container.

**Self-verification (real runs):** `tsc` and `eslint` clean; unit project 5,616/5,616; Chromium project 1,078/1,078; `pnpm -r build` clean; component bundle sizes within budget (`Splitter` 3.61KB JS / 0.83KB CSS gzipped); the snippets typechecked against the real components (a planted bad prop and a `"12rem"` limit are both rejected); the Docs page opened in a running Storybook (all template sections, both Properties tables, every "Show code" panel read against its demo, no console errors); Variants in light, Collapsible in Emerald dark.
