# Spacer — Storybook/component review findings

Spacer — comprehensive `06-engineering-standards.md` §9 review pass (2026-09-03). Five findings, all fixed:

1. **Accessibility correctness bug, the exact instance already flagged in `07-storybook-and-documentation-standards.md` §6's "Known gap for Spacer's future review" note.** `aria-hidden="true"` was placed *before* `{...rest}` in the JSX, so a caller passing their own `aria-hidden` prop (e.g. `aria-hidden={false}`) silently overrode Spacer's own "always hidden from the accessibility tree" guarantee — the same recurring bug class already fixed on Skeleton/Button/Checkbox/Affix/Divider/FieldError (`05-component-api-conventions.md` §3). Fixed by moving `{...rest}` before the computed `aria-hidden`, matching Skeleton's own precedent exactly (including the inline comment explaining why). A regression test was added (`"stays hidden from the accessibility tree even if a caller passes their own aria-hidden"`) — confirmed it fails against the reverted ordering before trusting it.
2. **`className`/`style`/`id`/`data-testid` weren't explicitly redeclared on `SpacerProps`.** The type was a bare `Omit<ComponentPropsWithoutRef<"div">, "children">` with no JSDoc — inconsistent with every other reviewed atom (Bleed, AspectRatio, Skeleton), and invisible to Storybook's docgen for the Properties table. Converted to an `interface SpacerProps extends Omit<ComponentPropsWithoutRef<"div">, "children">` redeclaring all four with the same standard JSDoc wording used elsewhere.
3. **No Playground story.** Added, first in the story group. Spacer has no props of its own — every prop is a native escape hatch, none meaningfully live-editable — so all four get `control: false` with a description in `argTypes`, and the Playground's canvas demonstrates Spacer inside a real flex row (the same demo used for the Variants-gallery entry). Confirmed live: the raw Controls panel shows all four as `–`, no stray placeholders.
4. **`NarrowViewport` story removed.** It was the deprecated one-off pattern `07-storybook-and-documentation-standards.md` §2 says `@storybook/addon-viewport`'s toolbar control has superseded — Center/Bleed's own reviews already dropped the equivalent story rather than keep it, and Spacer now matches.
5. **Docs page (`Spacer.mdx`) added** — full 10-section template. Feature-completeness checked against Chakra UI's own `Spacer` (the closest comparable-library component — an identical `flex: 1` utility with no props of its own); no gap found, so Spacer's minimalism is confirmed intentional, not incomplete. Related Components: `Stack` (the flex container Spacer is built to live inside) and `Box` (the generic layout escape hatch).

Live-verified in a running Storybook instance, not just typechecked: the Docs page's TOC, Intro, Playground (canvas + Properties table, all rows non-empty), Variants gallery, Usage guidelines, Accessibility callout, Code examples, Design tokens section ("references no tokens" — `flex: 1 0 0%` is structural, no color/spacing/etc. value with a token home, matching Center's identical case), and Related Components (both live previews rendering real DOM, not broken imports) — across Purple/Light, and again after switching to Emerald/Dark via the toolbar, with zero console errors either time. `title` was already correct (`Atoms/Layout/Spacer`), so the taxonomy needed no change.

Full self-verification: `tsc --noEmit` (package + `.storybook/tsconfig.json`), `eslint --max-warnings 0`, `tsup` build, and the full `unit` Vitest project (883/883, up from 882 — the one new regression test) all clean.

**Finalized 2026-09-03**, at explicit user direction, after the flex-props scope question below was raised and resolved.

**Scope question raised and resolved, same day:** asked whether `Spacer` should grow beyond flex-grow to expose other flex-item properties (shrink, basis, order, etc.). Kept as-is — Chakra UI's own `Spacer` (the direct comparable already checked in this review) is the identical single-purpose `flex: 1` utility with no other flex props, `04-component-inventory.md` scopes this component specifically as a "flex-grow spacer utility" rather than a general flex-item config primitive, and a growing prop surface on a component whose entire job is one CSS declaration cuts against "composition over configuration" (`06-engineering-standards.md` §2) — `style`/`className` already cover the rare case something else is needed. No code change from this question.
