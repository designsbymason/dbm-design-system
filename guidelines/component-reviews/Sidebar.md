# Sidebar — review findings

Twelfth organism, built 2026-10-19 with the `06-engineering-standards.md` §9 checklist applied as it was written. **Not yet Finalized:** only the maintainer declares that, and the open items at the end are what a Finalization should read first.

## Decisions
- Optional `Sidebar.Provider` holds the collapsed and open state so a toggle and a menu button can sit outside the sidebar (in a `Navbar`); a `Sidebar` with none holds its own: [ADR-0104](../adr/0104-sidebar-holds-its-collapsed-and-open-state-in-an-optional-provider-that-a-toggle-and-a-menu-button-outside-it-read-over-props-only-or-an-imperative-ref.md).
- The children are drawn on the page and in a `Drawer` panel below a CSS step (`collapseBelow`), and the panel is never a rail: [ADR-0105](../adr/0105-sidebar-is-drawn-on-the-page-and-in-a-drawer-panel-below-a-css-step-and-the-panel-is-never-a-rail-over-measuring-its-width-or-moving-one-rendered-copy.md).
- The rail keeps an icon where it was, shows an item's text as a tooltip (still its name) and opens a group as a `Menu`; expanded groups open with `Collapse` to three levels: [ADR-0106](../adr/0106-sidebar-collapses-to-a-rail-where-an-icon-stays-put-its-text-is-a-tooltip-and-a-group-is-a-menu-and-expanded-groups-open-with-collapse-to-three-levels-over-hiding-the-column-or-a-tree.md).
- A plain `<div>` root with a landmark per `Sidebar.Nav`, native scrolling for the content, and a width that is a length with one token: [ADR-0107](../adr/0107-sidebar-is-a-plain-box-with-a-landmark-per-nav-its-content-scrolls-natively-and-its-width-is-a-length-with-one-token-over-an-aside-a-scroll-area-or-a-size-scale.md).
- Compound: `Sidebar` (a `<div>`), `Header`, `Content`, `Footer`, `Nav` (a named `<nav>` holding a `role="list"` list), `Section`, `Item`, `Group`, `Separator`, `Toggle`, `MenuButton` and `Provider`, plus the `useSidebar()` hook. Items are parts rather than an `items` prop so a router's own link (`asChild`), a `Badge` and state of their own can be passed.
- `variant` (`outlined`, `filled`, `ghost`) is the sidebar's own look, as `Navbar`'s is, and `currentVariant` (`subtle`, `bar`, `solid`) is the vertical counterpart of `Navbar`'s (`bar` for `underline`).
- **One new token, `sidebar.width`** (16rem), in `03`'s component-token table, since the spacing scale tops out at 8rem. The rail's width, an item's height and the group indent are derived in CSS from `icon-size`, `space` and the item's step, so they need none. **No new colour pairing:** every pairing is one `Navbar` already uses (`text.brand` on `bg.brand-subtle`, `text.on-brand` on `bg.brand`, `text.secondary` on the tint, `border.focus` on the surface).
- `Sidebar.Item` draws its own `<a>` or `<button>` (and `Slot` for `asChild`) rather than the `Link` atom, as `Navbar.Link` does: its look is a full-width row that collapses to an icon. It shares small ideas with `Navbar.Link` (the capture-phase click guard, the external mark, the grow-in marker) but not code; if `NavigationMenu` needs the same, the rows are the third consumer and the shared part moves to `internal/` then (`05` §1).
- Not built, additive later: dragging it wider (`Splitter` composes it), a search or filter inside it (a recipe with `SearchInput`), storing the collapsed state (a recipe: hold `collapsed` yourself), a keyboard shortcut to toggle, reordering and pinning, and a group that is also a page.

## What was found while building it
- **`ScrollArea` was the wrong scroller for the content (a deviation from the plan, which recommended it).** It makes its viewport a tab stop whenever it overflows, so `Tab` landed on an unnamed box before the first item and a real-browser check that tabbed into the first item failed; and Radix wraps its content in a `display: table` box that sizes to the widest label, which stops an ellipsis. `Sidebar.Content` scrolls natively ([ADR-0107](../adr/0107-sidebar-is-a-plain-box-with-a-landmark-per-nav-its-content-scrolls-natively-and-its-width-is-a-length-with-one-token-over-an-aside-a-scroll-area-or-a-size-scale.md)).
- **The toggle changes its name instead of carrying `aria-expanded`** ("Collapse sidebar" / "Expand sidebar", for the press it would answer to, with a tooltip). The plan said `aria-expanded`; a changing name and a state attribute together double-announce, so the name does the work.
- **The collapse button overflowed the rail.** An `IconButton` is 30–61px and the rail's inner width is 24–44px, so at `md` the footer's toggle was clipped out of sight. Inside a sidebar it is the size of an item (`button.toggleBox`), and the rail's header and footer are columns.
- **A count badge covered the icon in the rail** (found by looking at it): it is now a 16px mark on the icon's corner.
- **A group's text and its items didn't line up** (found by looking): the indent is the icon plus the gap, so an opened group's items start under the group's own text, and a nested group steps in by one level.
- **An item was 38px tall, not square with the rail.** The line height of the text added 2px; the item's line height is the icon's size, so the item and the rail are exactly `icon + 2 × padding`.
- **The "end" and right-to-left demos were drawn wrong by the demo frame, not the component** (the frame put the content after the sidebar and read the page's direction): the frame takes `reverse` and `dir`.
- **An accessible name in a flex row has no space between the text and the hidden cue in jsdom** ("Docs(opens in a new tab)"); the tests accept the space or none, as `Navbar`'s do, and a browser's accessibility tree puts one between the boxes.
- **The first real-browser checks failed on mistakes in the checks:** a width measured against a box that has a 1px border, a name queried without its badge ("Inbox" for "Inbox 12"), a content element found by a class name that `Avatar` also uses, and a sticky check that put a window-tall sidebar in a 20rem box. Each is now a check that fails when the thing it guards breaks (the first run is what showed they did).
- **Focus after opening the panel is on its first button, not its first link.** Radix's focus scope skips links when it picks where to start, so with the demo sidebar it starts on the first group's button. Left as the library's behaviour (`Navbar` does the same); `Drawer`'s `initialFocus` can change it.

## After the first look (2026-10-19)
- **Section headings are set in capitals** (`text-transform: uppercase`; the name a screen reader reads is unchanged), and the collapse button is a single caret (`CaretLeftIcon` / `CaretRightIcon`, pointing toward the edge while open and away while a rail).
- **Every demo sidebar fills its box.** The demo stage stretches its one child and the frame is a minimum height, so a sidebar is as tall as the dashed box; a hidden check asserts it. A frame that must scroll its content holds a fixed height.
- **A passed `Badge` is shown and tested**: the "Kinds of item" story draws one beside the built-in text badge, unit tests assert its own tone, variant, size, class and style win and that it is one pill, and a real-browser check measures the fills, the pill's height and its place in the rail. The built-in badge's height rule has `Navbar`'s specificity, so `style` always wins.
- **Snippets now mirror their stories** (the demo's header, two sections, groups and footer, the same `current` item, `defaultCollapsed` for the rail, the real controlled example, and no `sticky` in the page-shell one), and were typechecked against the real components again. The footer's name in every demo is "John Doe", in the sidebar's own text size.
- **The built-in badge is `Badge`'s solid brand look** (subtle on a current item drawn as a brand fill, where a solid pill would vanish), as `Navbar`'s now is; a passed `Badge` is unchanged. It is drawn at `Badge`'s own size (`xs` in an expanded item, and a smaller 20px mark in the rail, at the maintainer's direction), so a one- or two-digit count is `Badge`'s circle, and a negative block margin keeps a badged row the height of a plain one (the first version shrank the badge to fit the row, which made two digits an oval).

- **The external-link mark is one step below the item's icon** (12px beside a 16px icon, 16px beside a 20px one) and so is a group's caret, rather than a fixed 12px, at the maintainer's direction.

## Tier 1 additions (2026-10-20)
Four gaps from the first review ([ADR-0109](../adr/0109-sidebar-puts-a-row-control-beside-the-link-works-out-the-current-page-from-a-path-and-shows-a-tooltip-only-for-a-cut-label-over-a-control-inside-the-link-a-router-hook-or-a-tooltip-on-every-item.md)):
- **The phone panel opens on its first item.** Radix's focus scope skips links, so it had started on a group's button (the unit test fails with the fix removed).
- **A cut label has a tooltip,** only when the label's content is wider than its box; a short label has none, and the rail keeps its own.
- **`action`** on an item, a group and a section: a control beside the link, faint until the row is hovered or focused, always on touch and in the panel, absent from the rail. The buttons in it default to ghost, neutral and `xs`. Found while checking it: the row must keep its height with a badge and an action together, which a real-browser check asserts (and fails when the room it leaves is removed).
- **`currentPath`** on the sidebar, `match` on an item: items and groups mark themselves from their `href`, with `current` still winning. The path helper is tested on its own (query, hash, trailing slash, lookalikes, other sites, nested children).
- **Not looked at:** a kebab `Menu` opened from an action in a real touch browser, and a group whose items are drawn by a component of the app's own (its `current` has to be set by hand, as the Docs say).

## Open
- Not run: a screen reader (VoiceOver, NVDA) over the sidebar, the rail's tooltips and flyouts, a group and the panel; a real touch device on the panel (`Drawer`'s open item); and a window resized across the collapse step with focus inside the sidebar (a story can't resize the window).
- The rail's flyout starts 4px inside the rail's own padding, beside its trigger rather than beside the rail (`Menu`'s offset from the trigger). Looks right, and is asserted to be clear of the trigger; moving it to clear the rail would take an anchor on the sidebar, not the item.
- A group's open state in the page's copy is not the panel's (ADR-0105). The Docs say so and say to hold it yourself; moving one rendered copy is the alternative if that proves a real cost.
- A long label is cut with an ellipsis and its full text is not shown anywhere when expanded (only in the rail's tooltip). A tooltip that appears when the label is truncated is additive.
- The width animation is a layout property (`06` §4 prefers `transform` and `opacity`); it is one short transition, off under reduced motion, and the content beside a sidebar reflows each frame. If that costs on a heavy page, an instant swap is a one-line change.
- Emerald has been looked at in dark mode only; its contrast was computed in both, as for the other themes.
