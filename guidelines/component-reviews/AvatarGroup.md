# AvatarGroup

**Tier:** molecule · **Category:** Data Display · **Status:** built 2026-09-26; **Finalized 2026-09-26**, declared by the user after the final review pass recorded below, with the not-verified items and the `labels` bug class in four other components left as they are (see "Finalized" at the end).

## What was built

A single component (not compound), item 20 in the itemized molecule build order (`04-component-inventory.md`): a `<ul>` of `Avatar`s overlapped into a stack, with the ones past `max` collapsed into a "+N" tile. No new dependency, no new token, no component token.

Props: `children` (the `Avatar`s, one each), `size` (also a mobile-first breakpoint map), `shape` and `colorful` (defaults for every avatar, an avatar's own prop winning), `stacked` (default `true`; `false` spaces them by `space.2` and lets a row wrap), `max`, `total`, `onOverflowClick`, `formatNumber`, `labels` (`overflow`, `overflowButton`; a function of the count, so plural rules can be the translator's), and `aria-label` / `-labelledby` / `-describedby`, `id`, `className`, `style`, `data-testid`.

## Decisions taken while building

- **Children only, not an `items` array; the tile a button on request; a `stacked` mode.** The three forks were put to the user before building; each was chosen as recommended. Children keep every `Avatar` prop (`as`, `status`, `onClick`) and match `ButtonGroup` and `ToggleGroup`; `onOverflowClick` makes the tile a `<button>` (the consumer opens the dialog or list themselves, since `Popover` has no `Anchor`, [ADR-0017](../adr/0017-popover-omits-anchor-sub-part-pending-upstream-fix.md)); `stacked={false}` mirrors `ButtonGroup`'s `attached`.
- **Settings reach the avatars through an internal context that `Avatar` reads** — the mechanism of [ADR-0025](../adr/0025-buttongroup-shares-settings-through-a-context-read-by-button-and-iconbutton.md), followed rather than re-decided, so no new ADR. `Avatar` changed additively and stays Finalized (see `Avatar.md`). A group inside another keeps the outer one's settings for whatever it leaves out (the check `06` §9 now asks for), tested.
- **The ring is on a wrapper `<li>`, not on `Avatar`.** A `box-shadow` spread in `bg.surface` (`border-width.2`) around each item reads as a gap where two overlap and follows the item's radius (`radius.full`, or `radius.md` for a square avatar). Each item carries its avatar's shape as `data-shape`, taken from the child's own `shape` prop else the group's; a wrapped avatar (a `Tooltip`) can't be seen through, so the docs say to set `shape` on the group. On another background the ring colour is `--avatar-group-ring-color`, set in `style`.
- **The first avatar is on top.** Each item's layer (`--avatar-group-layer`) counts down from the first, so a presence dot at an avatar's corner is never covered by the next one; `:focus-within` lifts an item above every layer so a button avatar's focus ring is drawn over its neighbours. The list is `isolation: isolate`, so these layers only order the items against one another. Hit-testing proves both.
- **`max` counts avatars, and the tile is extra.** `max={3}` draws three avatars and the tile. `total` is the real number of people when only some are loaded: the tile reads `total` minus the avatars drawn, even when every child fits under `max`; a `total` smaller than the children warns once and is ignored for the ones already drawn. A count over 99 is drawn as "99+" so it fits an `xs` avatar; the accessible name keeps the real count.
- **The tile is an `Avatar`**, never coloured by the group's `colorful` (it stands for people, not a person), named "3 more", or, with `onOverflowClick`, a real button named "Show 3 more". Both names are `labels`, functions of the count.
- **The list roles are stated outright** (`role="list"` / `role="listitem"`), for Safari with VoiceOver under `list-style: none` (`05` §6), with the two `jsx-a11y/no-redundant-roles` suppressions explained at `Entry`, as `Pagination` does.
- **The overlap is one spacing step, `space.2`, at every size** — see the first finding below. It also means the group needs no responsive machinery of its own: a breakpoint `size` reaches the avatars through the context and the overlap doesn't change.

## Findings from the build

- **A proportional overlap clipped two-letter initials from `md` up** (the first version tucked each avatar under the previous by `space.2` at `xs` and `sm` and `space.3` at the rest, about a quarter of the avatar). The Docs page's Playground drew "AK" as "\K" and "MG" as "/G": the covered strip plus the ring is wider than the gap between an avatar's edge and its centred letters. No test could have seen it — the geometry was exactly as designed — and it was found only by looking at the live screenshots. Tried `space.1` (legible but barely a stack) and `space.2` at every size (reads as a stack, initials whole; only a two-letter `xl` avatar's edge touches its neighbour, which the docs say). Changed at the build's end, which deleted the per-size overlap map, the responsive custom-property chain and six media blocks.
- **`react-hooks/refs` flagged the render-time "warn once" ref pattern here** although the same pattern lints clean in `ButtonGroup`, `ToggleGroup` and a dozen others. The cause was not found (bisecting the component narrowed it to the read of the ref itself in this file); the two development warnings (no name; `total` below the child count) are now `useEffect`s keyed on the fact they report, which lints clean and warns once per change (tested). Recorded so a later component that meets it doesn't lose the same time.
- **Two spread bugs found by the type-checker and the browser run, not by reading:** the polymorphic `Avatar` won't take a `"button" | "span"` union for `as` (the tile is two elements), and a story spread its Storybook-only args (`count`, `overflowButton`) onto the `<ul>` — React's console error caught it.

## Final review before Finalizing, 2026-09-26

A full `06-engineering-standards.md` §9 pass against the code and the running component. **Fixed (three), one test strengthened, and one item left for a decision.**

**Fixed**

1. **`max={NaN}` hid every avatar** (a failed parse becomes `NaN`, `slice(0, NaN)` is empty) and drew a tile counting all of them; **`total={NaN}` was silently mishandled**. A `NaN` for either now counts as not given. Found by probing odd inputs, not by any earlier test.
2. **A `labels` object with an explicit `undefined` crashed the render** (`words.overflow is not a function`), and would have blanked a string: the object spread over the defaults replaces a default with `undefined`, and `Partial<AvatarGroupLabels>` allows it (`labels={{ overflow: t?.overflow }}`). Each label now falls back to its default individually. Three tests (NaN `max`, NaN `total` alongside a `max`, undefined labels), each failing with its guard removed (checked; the first NaN-`total` test passed with the guard removed because both values being `NaN` looked the same either way, and was rewritten until it failed).
3. **The 24 × 24px target test measured boxes, not what a pointer can hit.** A tucked-under avatar's hit area is its box less the overlap. The story now hit-tests along each button's middle line at every size and asserts 24px or more unobscured (the smallest is 28px at `xs`); it fails with a 24px overlap (checked).

**The bug class in four other components — fixed the same day, at explicit direction.** Finding 2 is not specific to this component: `Pagination`, `Alert`, `RangeSlider` and `Breadcrumb` (all Finalized) built their `labels` with the same plain spread, confirmed by rendering each with a label set to `undefined` (crashes in `Pagination` and `Breadcrumb`, unnamed controls in all four). All five now use `mergeDefined`, a small helper added to `packages/primitives`; a survey found no other component with a `labels` prop or another spread-merge of an override object. See each component's own review file.

**Checked, no action needed**
- **Baseline:** no `any` or hex; every value in the stylesheet is a token; JSDoc on every prop; `{...props}` precedes `role`, the name and `style`; SSR-safe (no browser API in render); `StrictMode` tested; the context value is memoised; a string, a `null`/`false` and a fragment among the children behave as documented (a fragment is one avatar).
- **Composition:** `Avatar` is the only avatar there is (the tile is one); `Tooltip`-wrapped and `as="button"` avatars take the group's settings; nested groups merge; only a direct child's own `shape` is seen, as the docs say.
- **Accessibility:** list, item and tile names read in the accessibility tree (also right to left, with Arabic labels); tab order is the tile and button avatars only; jest-axe passes for a non-default `as`; the tile's focus ring is drawn over the avatar before it.
- **Feature completeness, considered and not added:** a container-measured `max` and a vertical stack (both already named below); an `onOverflowClick` argument for the hidden count (the consumer already knows `max` and the total).

**Not verified:** a real screen reader; the ring in a forced-colours mode (`box-shadow` is dropped there, so overlapping avatars lose their separator; `Avatar` itself has no border either, so this is the atom's limit as much as the group's); the ring against a background other than `bg.surface` beyond the custom property.

## Gaps named, not built

- **A `max` measured against the group's own width** (as `Breadcrumb`'s `maxItems="container"` does), so a group fits whatever room it's given. Today `max` is a count and a stack that is too wide overflows as one box.
- **A vertical stack** (a column). Uncommon for avatars; a `Stack` of avatars covers the plain case.
- **A tooltip per avatar built in.** Composed with `Tooltip` instead (the docs show it); a group-wide "name on hover" would have to know each child's name.
- **A per-size overlap.** Tried and dropped for the reason in the first finding; revisit only if the avatars' own initials layout changes.
