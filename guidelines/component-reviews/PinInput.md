# PinInput — build and review findings

**Inputs & Forms:** PinInput — built 2026-10-04, item 31 in the molecule build order (`04-component-inventory.md`). **Finalized 2026-10-04** by the user, after the final review recorded at the end of this file. Decision: [ADR-0040](../adr/0040-pininput-is-one-real-input-drawn-as-cells-over-an-input-per-cell.md).

**What it is:** a code-entry field drawn as one cell per character over a single real `<input>`. Flat props (not compound), `ref` to the input; `className`/`style` on the outermost box. Value is a plain string (`value`/`defaultValue`/`onValueChange`), `onComplete`, `length` (default 6), `type` (`numeric`/`alphanumeric`/`text`), `size`, `groups` and `separator`, `placeholder`, `mask` with `revealable` (`revealed`/`defaultRevealed`/`onRevealedChange`), `hasError`/`disabled`/`readOnly`/`required`, `autoComplete` (default `one-time-code`), `name`, `labels`.

**Decisions put to the user before building:** the structure (one input drawn as cells, chosen over an input per cell), the accepted characters (a `type` of numeric, alphanumeric or text), and the first-version extras (mask with show/hide, groups with a separator, `onComplete`, a plain-string value with `name`).

**Composition checkpoints (06 §9):** compound sub-parts — not applicable (flat props); atom reuse — the show/hide button is `IconButton` (ghost, toggle, same size step, so it is the cell's height); consumed-atom defects — none found; Radix audit — not applicable (no Radix); cross-part ARIA wiring — `id`/`aria-labelledby`/`aria-describedby` from a `FormField` land on the input (tested in a `FormField` story and a label test); composed tab order — one tab stop for the field, then the show button; no nested provider.

**Defects found by running it in a real browser, all fixed:**
- **A flex cell's `flex-basis` alone didn't keep it from collapsing.** Cells were 2×2px: a group's intrinsic width is built from its items' widths, not their flex-basis, so the group shrank to nothing. The cell now also has an `inline-size`; it still shrinks with its row.
- **A Tab selects all of an input's text after the focus event**, which left every cell active instead of the first empty one (user-event reproduces this; a real browser does the same). The field puts the selection on the first empty cell on focus and again a frame later, unless a pointer press is on its way to choosing the cell itself (else a quick click was overridden).

**Defect found by the user in Storybook after the first push, fixed (2026-10-04):** typing a character the `type` rejects (a letter in a numeric field) moved the active cell on while leaving the first one empty, and typed over a selected character it would have deleted it. The change handler cleaned the value but the caret had already moved past the cell, and a rejected key replaced the selection before being cleaned. A native `beforeinput` listener now blocks input whose characters are all rejected, so nothing changes; a paste that is only partly accepted still gets through and is cleaned, and a change cut back to the code it already holds re-reads the selection. Neither the unit tests nor the first real-browser stories typed a rejected key, which is why it was missed. Two new tests (jsdom and Chromium) fail without the fix; unit 5,810/5,810, Chromium 1,113/1,113.

**Feature round (2026-10-04, from the review's gap list):** `isLoading` (a spinner after the cells that never gets squeezed, the field set aside with `readOnly` and `aria-busy` so it keeps focus and its value, and a `labels.loading` status message in a region that is in the page before it has anything to say); `transform` (`uppercase`/`lowercase`, applied before the cut to length because a letter can become two); `alphanumeric` made consistent with `text` (letters of any script plus the digits 0 to 9); and a one-time shake when `hasError` turns on after mount (detected by comparing with the last render so a field that starts invalid doesn't shake; `motion.duration.slow`; none under reduced motion; an error is still carried by `aria-invalid` and the error text, not by the shake or the colour). Also found while looking at it: with a full code the caret sat past the last cell, so typing did nothing; a full code now has its last cell selected, so typing replaces it. A responsive `size` map was considered and dropped: the cells already shrink with the container. Tests added in jsdom and Chromium (spinner and announcement, readOnly while loading, cells not moving when loading starts, the shake starting and ending, transform, the full code); nine mutants across both rounds were killed.

**Behaviour worth stating:** a caret between characters becomes the next character selected (typing overwrites); the arrow keys are handled (the browser would only collapse the selection); a press is mapped to the nearest cell from the cells' rectangles (the input keeps the pointer, so a phone's long-press paste still works); `maxLength` is not set (the browser would cut a paste before it could be cleaned), the value is cleaned and cut in the change handler; a value that isn't a string reads as empty; an invalid `length` falls back to 6 with a development warning; `groups` that don't add up to `length` warn and leftover cells make a last group.

**Contrast (measured by the existing token record, no new pairing):** the character is `text.primary` on `bg.surface` (13.5:1 dark, higher light); the placeholder and separator are `text.tertiary` on `bg.surface` (8.2:1 dark, above 4.5 light), both decorative and `aria-hidden`. The border is `border.default`, a decorative cell edge like `Input`'s; the active cell's border and ring are `border.focus` (≥4.16:1). A disabled field is exempt.

**Tokens:** no new tokens. A cell's height is `Input`'s own formula (line plus two paddings) from existing font-size, line-height and space tokens, so a cell is exactly as tall as a `Button` or `Input` of the same size (checked at all five sizes in Chromium).

**Responsive:** the cells shrink together and stay square inside a narrow container (checked at 17rem with eight `xl` cells in two groups and a show button: no overflow).

**Tests:** 69 unit tests (native input and autofill hint, one cell per character and hidden from assistive technology, invalid length warning, typing, rejected characters per type, paste cleaned and cut, `onComplete` once per filling and not for a value passed in or a paste cut back to the same code, controlled/uncontrolled, overwrite semantics, arrow keys/Home/End, Backspace, active cell and caret, click-to-cell, groups and separator and their dev warning, placeholder, mask/reveal/controlled reveal/labels with `undefined`, error/disabled/read-only/required, form submission under `name`, label wiring, ref/id/testid/aria on the input and `className`/`style` outside, handler composition and a handler stopping the arrows, always left to right, a non-string value, `autoFocus`, StrictMode, jest-axe in three configurations), a Docs-page token guard (`PinInput.docs.test.ts`), and 11 hidden real-browser stories (typing and completing, paste, Tab lands on the first empty cell, text inserted all at once, clicking a cell, size equals `Button` at five sizes, a narrow container, left-to-right in a right-to-left page). **Mutation check:** six deliberate breaks (no overwrite selection, no change guard on `onComplete`, no frame-later selection, no character cleaning, a pointer press ignored, the caret shown when disabled) — four were killed at once; the change guard and the disabled caret survived, so two tests were added (a paste cut back to the same code; becoming disabled while focused) — the guard mutant is now killed, and the caret's own `!disabled` turned out redundant with the active cell's (removed).

**Self-verification (real runs):** `pnpm lint` (eslint plus both typechecks) clean; unit project 5,809/5,809 including the new file; Storybook (Chromium) project 1,112/1,112 (one unrelated `TimePicker` width check failed once under the full run's load and passed on two isolated reruns); `pnpm build` clean; `PinInput` 3.47KB JS / 1.61KB CSS gzipped, within the 10KB budget; the snippets typechecked against the real components; the Docs page opened in a running Storybook (all template sections, 12 canvases, 30 Properties rows, no error text); the All sizes story in light and the Masked story in dark mode, with a click on the second cell moving the ring to it.

**Known limits:** a code longer than 32 cells is refused (falls back to 6); `text` takes letters only (of any script) and drops anything outside the Basic Multilingual Plane, so one character is always one cell and one selection index; the field doesn't reset with a native form reset, like the other controls here that hold their own value.

## Final review before Finalization (2026-10-04)

A full `06-engineering-standards.md` §9 pass over the finished component. **Prop order:** the types file, the Docs page's `propOrder`, the stories' `argTypes` and the rendered tables now agree (content props, then look, then state, then escape hatches); `placeholder` was out of place in the types file and `autoFocus` was only inherited, so it is redeclared where it belongs. Read live after a dev-server restart: the native Controls panel (32 rows, no inert "Set …" placeholders), the Properties table (every row described, defaults shown for the fifteen props that have one, "Value options" showing only real values) and the Playground. Findings, all fixed:

1. **An input method mid-composition had its selection changed under it.** Widening the caret onto the next character while a Japanese, Chinese or Korean composition was running would have ended the composition. The selection is left alone from `compositionstart` to `compositionend` and settled afterwards; the consumer's composition handlers still run. A unit test and a deliberate break confirm it.
2. **A very narrow container could shrink a cell under 24px** (WCAG 2.5.8). Cells now have a `space.6` minimum width, so an extreme width overflows rather than shrinks them; the narrow-container story asserts every cell is at least 24px.
3. **Forced colours was unchecked.** A hidden real-browser story emulates `forced-colors: active` and asserts the active cell keeps a solid outline and the caret is drawn in `CanvasText`; changing the colour makes it fail.
4. **Invalid combinations were silent.** `value` with `defaultValue`, and `revealable` without `mask`, now warn once in development.

**Also verified, no change needed:** computed attributes (`aria-invalid`, `aria-busy`, `type`, `minLength`, `inputMode`) win over a consumer's same-named props (tested); a server render with every cell; one tab stop for the field and then the show button, forwards and back; Enter submits a surrounding form as in any text field; all 14 "Show code" panels read against their demos in the live Docs page; all four themes by eye (the ring follows the brand colour; characters are legible in each); the Docs page opened after the types change.

**Contrast and visibility, one judgment for the user:** an empty cell is drawn with `border.default`, like `Input`, which is 1.40:1 against the surface in dark mode. That is a decorative edge by the system's rules, but for a cell-based field the boxes are the main sign of how many characters to enter, and in dark mode an empty cell is very faint. `border.neutral` (3.00:1 dark, 2.32:1 light, the resting-to-hover step of `Input`) would make the boxes plainly visible; it would also remove the hover step on the cells. Left as is when the component was Finalized: the cells keep `Input`'s resting border, a deliberate, accepted choice (revisit it for `Input` and `PinInput` together if the resting border is ever strengthened).

**Known and accepted:** the field doesn't reset with a native form reset (state, like the other controls here); a code longer than 32 cells falls back to 6; `text` and `alphanumeric` take letters in any script but drop characters outside the Basic Multilingual Plane; not run on a real iOS or Android device (the structure is chosen for autofill and long-press paste, but only a device shows it).

**Self-verification (real runs):** `pnpm lint` clean; unit project 5,836/5,836; Storybook (Chromium) project 1,118/1,118; `pnpm build` clean; `PinInput` 4.23KB JS / 1.90KB CSS gzipped within the 10KB budget; Foundations token coverage in sync.
