# PinInput — build and review findings

**Inputs & Forms:** PinInput — built 2026-10-04, item 31 in the molecule build order (`04-component-inventory.md`). **Not yet declared Finalized** — only the user does that; this records the build-time review. Decision: [ADR-0040](../adr/0040-pininput-is-one-real-input-drawn-as-cells-over-an-input-per-cell.md).

**What it is:** a code-entry field drawn as one cell per character over a single real `<input>`. Flat props (not compound), `ref` to the input; `className`/`style` on the outermost box. Value is a plain string (`value`/`defaultValue`/`onValueChange`), `onComplete`, `length` (default 6), `type` (`numeric`/`alphanumeric`/`text`), `size`, `groups` and `separator`, `placeholder`, `mask` with `revealable` (`revealed`/`defaultRevealed`/`onRevealedChange`), `hasError`/`disabled`/`readOnly`/`required`, `autoComplete` (default `one-time-code`), `name`, `labels`.

**Decisions put to the user before building:** the structure (one input drawn as cells, chosen over an input per cell), the accepted characters (a `type` of numeric, alphanumeric or text), and the first-version extras (mask with show/hide, groups with a separator, `onComplete`, a plain-string value with `name`).

**Composition checkpoints (06 §9):** compound sub-parts — not applicable (flat props); atom reuse — the show/hide button is `IconButton` (ghost, toggle, same size step, so it is the cell's height); consumed-atom defects — none found; Radix audit — not applicable (no Radix); cross-part ARIA wiring — `id`/`aria-labelledby`/`aria-describedby` from a `FormField` land on the input (tested in a `FormField` story and a label test); composed tab order — one tab stop for the field, then the show button; no nested provider.

**Defects found by running it in a real browser, all fixed:**
- **A flex cell's `flex-basis` alone didn't keep it from collapsing.** Cells were 2×2px: a group's intrinsic width is built from its items' widths, not their flex-basis, so the group shrank to nothing. The cell now also has an `inline-size`; it still shrinks with its row.
- **A Tab selects all of an input's text after the focus event**, which left every cell active instead of the first empty one (user-event reproduces this; a real browser does the same). The field puts the selection on the first empty cell on focus and again a frame later, unless a pointer press is on its way to choosing the cell itself (else a quick click was overridden).

**Behaviour worth stating:** a caret between characters becomes the next character selected (typing overwrites); the arrow keys are handled (the browser would only collapse the selection); a press is mapped to the nearest cell from the cells' rectangles (the input keeps the pointer, so a phone's long-press paste still works); `maxLength` is not set (the browser would cut a paste before it could be cleaned), the value is cleaned and cut in the change handler; a value that isn't a string reads as empty; an invalid `length` falls back to 6 with a development warning; `groups` that don't add up to `length` warn and leftover cells make a last group.

**Contrast (measured by the existing token record, no new pairing):** the character is `text.primary` on `bg.surface` (13.5:1 dark, higher light); the placeholder and separator are `text.tertiary` on `bg.surface` (8.2:1 dark, above 4.5 light), both decorative and `aria-hidden`. The border is `border.default`, a decorative cell edge like `Input`'s; the active cell's border and ring are `border.focus` (≥4.16:1). A disabled field is exempt.

**Tokens:** no new tokens. A cell's height is `Input`'s own formula (line plus two paddings) from existing font-size, line-height and space tokens, so a cell is exactly as tall as a `Button` or `Input` of the same size (checked at all five sizes in Chromium).

**Responsive:** the cells shrink together and stay square inside a narrow container (checked at 17rem with eight `xl` cells in two groups and a show button: no overflow).

**Tests:** 48 unit tests (native input and autofill hint, one cell per character and hidden from assistive technology, invalid length warning, typing, rejected characters per type, paste cleaned and cut, `onComplete` once per filling and not for a value passed in or a paste cut back to the same code, controlled/uncontrolled, overwrite semantics, arrow keys/Home/End, Backspace, active cell and caret, click-to-cell, groups and separator and their dev warning, placeholder, mask/reveal/controlled reveal/labels with `undefined`, error/disabled/read-only/required, form submission under `name`, label wiring, ref/id/testid/aria on the input and `className`/`style` outside, handler composition and a handler stopping the arrows, always left to right, a non-string value, `autoFocus`, StrictMode, jest-axe in three configurations), a Docs-page token guard (`PinInput.docs.test.ts`), and 11 hidden real-browser stories (typing and completing, paste, Tab lands on the first empty cell, text inserted all at once, clicking a cell, size equals `Button` at five sizes, a narrow container, left-to-right in a right-to-left page). **Mutation check:** six deliberate breaks (no overwrite selection, no change guard on `onComplete`, no frame-later selection, no character cleaning, a pointer press ignored, the caret shown when disabled) — four were killed at once; the change guard and the disabled caret survived, so two tests were added (a paste cut back to the same code; becoming disabled while focused) — the guard mutant is now killed, and the caret's own `!disabled` turned out redundant with the active cell's (removed).

**Self-verification (real runs):** `pnpm lint` (eslint plus both typechecks) clean; unit project 5,809/5,809 including the new file; Storybook (Chromium) project 1,112/1,112 (one unrelated `TimePicker` width check failed once under the full run's load and passed on two isolated reruns); `pnpm build` clean; `PinInput` 3.47KB JS / 1.61KB CSS gzipped, within the 10KB budget; the snippets typechecked against the real components; the Docs page opened in a running Storybook (all template sections, 12 canvases, 30 Properties rows, no error text); the All sizes story in light and the Masked story in dark mode, with a click on the second cell moving the ring to it.

**Not yet done (for the final review):** a forced-colours emulation check of the active cell and caret (they use an outline and `CanvasText`, by construction); a Safari/iOS check of the autofill and long-press-paste paths (the structure is chosen for them, but only a device shows it); all four brand/mode themes by eye (two looked at); a keyboard walk through the Docs page's own Playground; the Emerald themes' ring contrast against the cell, taken from `border.focus`'s record rather than measured here.

**Known limits:** a code longer than 32 cells is refused (falls back to 6); `text` type excludes spaces and anything outside the Basic Multilingual Plane, so one character is always one cell and one selection index; the field doesn't reset with a native form reset, like the other controls here that hold their own value.
