# TagsInput — build and review findings

**Inputs & Forms:** TagsInput — built 2026-10-10, item 22 in the ⚪ build order and the last molecule (`04-component-inventory.md`). **Not Finalized**: the §9 pass below is the build-time pass; the user declares Finalized. Decision: [ADR-0049](../adr/0049-tagsinput-draws-chips-and-its-own-entry-in-one-wrapping-box-and-adds-on-enter-separator-blur-or-paste-over-the-input-atom-or-a-combobox.md).

**What it is:** a field holding a list of short typed values as removable chips. Flat props, `ref`, `id`, `data-testid` and `aria-*` on the entry `<input>`; `className`/`style` on the outer box. `value`/`defaultValue`/`onValueChange` (a `string[]`, a new array each time), `inputValue`/`defaultInputValue`/`onInputValueChange` (the pending text), `placeholder`, `size`, `tone`/`variant` (Tag's own; `brand` and `subtle` by default), `separators`, `addOnBlur`, `allowDuplicates`, `maxTags`, `maxTagLength`, `transform`, `validate`, `clearable`, `required`, `hasError`/`disabled`/`readOnly`, `name`/`form` (one hidden input per tag), `autoComplete`/`inputMode`/`enterKeyHint`/`spellCheck`/`autoCapitalize`, `formatNumber`, `labels`.

**Composition checkpoints (06 §9):** compound sub-parts — not applicable (flat); atom reuse — `Tag` (removable, one step below the field), `Icon`, `FieldError`, `VisuallyHidden`, `useAnnouncement`; the entry is its own `<input>`, not `Input`, for the reason in the ADR; consumed-atom defects — none found; Radix audit — not applicable; cross-part ARIA wiring — a `FormField`'s `id`/`aria-labelledby`/`aria-describedby` land on the entry (and the group), tested; composed tab order — each chip's remove button, then the entry, then clear-all, forwards and back (tested in jsdom and Chromium); no context provided.

**Deviations from the approved plan:**
- **List semantics:** the plan put the entry in the list as a `role="none"` item. axe failed it (`aria-required-children`). The list is now `display: contents` with only chips in it and the entry outside it, in the same flex-wrap box; axe passes and the list is announced as exactly as many items as tags (checked in Chromium). Not checked in Safari.
- **The entry is not detached from a surrounding form** (as `EditableText`'s open field is): Enter in an empty entry must submit the form, which implicit submission only does for a form owner. The entry has no `name` and no native `required`, so it contributes nothing to the data or the validation; the tags and the hidden validating control are what the form sees. A hidden story checks both Enter behaviours and that pressing a submit button reads pending text as a tag first.
- **Height:** the plan hoped for an empty field exactly as tall as an `Input`. A chip row is taller than `Input`'s line, so the block padding is the nearest token step per size, and an invisible zero-width chip keeps the row at chip height. Measured against an `Input` of the same size: xs +4.0px, sm +2.5px, md −0.6px, lg −2.7px, xl −3.9px; adding the first tag moves nothing.
- **Required validity:** the hidden validating control must not be read-only (a read-only control is barred from constraint validation); found by a failing real-browser check.
- **Targets:** the clear-all button had a 12px glyph box; it now has a `space.6` minimum.

**Known limits:**
- A refused typed-separator piece stays in the entry with the separator removed; a paste is added piece by piece and what is refused is counted, not itemized, in the announcement (the first reason is shown).
- Tab goes through every chip's remove button, so a very long list is a long tab sequence. A roving model is the recorded alternative (ADR-0049).
- `display: contents` on the list relies on the browser exposing the list role through it. Chromium and axe: yes. Safari with VoiceOver, and a real phone: not run.
- The chip row is as tall as a chip at every size; the field is within a few pixels of an `Input`, not equal to it.
- A tag can't be edited in place, only removed and re-added.
- No suggestions list: a later, additive layer from `Combobox`.

**Contrast (no new pairing):** the typed text is `text.primary` and the placeholder `text.tertiary` on `bg.surface` (13.53:1 and 8.21:1 in dark); the chips are `Tag`'s own, verified on `bg.surface`; the clear-all hover fill is `bg.neutral-subtle` under `icon.default`, `Input`'s own clear-button pairing.

**Tokens:** one new component token, `tags-input.entry-min-width` (`8ch`), the narrowest the typing area gets before it wraps beneath the chips; row added to `03-token-system-spec.md`. Nothing else new.
