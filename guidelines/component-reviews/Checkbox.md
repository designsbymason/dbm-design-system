# Checkbox — Storybook/component review findings

*(Migrated from `07-storybook-and-documentation-standards.md` §6 during the guidelines retrofit pass, 2026-08-31 — this file's own content is unchanged from what was there, just relocated. See `07`'s own status table for this component's current Docs-page/Finalized status.)*

**Inputs:** Checkbox — ✅ done (2026-08-23 — comprehensive `06-engineering-standards.md` §9 review, worked one finding at a time across 11 findings): (1) no `Playground` story — the old `Default` story had only `size` wired to a real control; replaced with a full `Playground`, including a `radio` control for `defaultChecked`'s tri-state (`false`/`true`/`"indeterminate"`) and `checked` deliberately `control: false` with a documented reason (driving the controlled prop live without a real `onCheckedChange` wired back would freeze the checkbox, since Radix always defers to a controlled value — the Playground demonstrates the uncontrolled path instead, matching `Tag`'s own precedent for this class of component). (2) Confirmed 6th instance of the JSX-attribute-ordering bug (`05-component-api-conventions.md` §3) — `{...props}` now spreads before the computed `id`/`checked`/`defaultChecked`/`onCheckedChange`/`disabled`/`aria-invalid`/`className`. (3) `AllSizes`/`States`/`IconOnly`/`SelectAllPattern` stories' `render` functions fixed to accept and spread `args`. (4) `aria-label`/`aria-labelledby`/`id`/`className`/`style`/`data-testid` all redeclared on `CheckboxProps` with full JSDoc (previously undocumented, working only via native inheritance). (5) Dev-mode warning added for no accessible name (no `children`/`aria-label`/`aria-labelledby`), matching Button/ProgressBar/ProgressCircle/Spinner/Tag. (6) The unchecked box's `:hover` state was reusing `border.focus` (meant for focus rings only) — fixed to `border.neutral-strong` (added in Phase 23, previously unconsumed by any component). (7) Three `play`-function interaction stories added (`ClickInteraction`, `DisabledInteraction`, `SpaceKeyInteraction` — Space only, not Enter, since the WAI-ARIA checkbox pattern's keyboard contract differs from a native `<button>`'s). (8) Two keyboard-interaction unit tests added at the Vitest layer, mirroring #7 (Tab-then-Space toggles; a disabled checkbox is skipped by `Tab` entirely, via native `disabled` — unlike `Tag`'s `aria-disabled`-based pattern, which stays focusable). (9) Feature-completeness gap (Chakra's custom-icon-override pattern) — built at explicit direction rather than deferred: `icon`/`indeterminateIcon` props added (`PhosphorIcon`, defaulting to the system's own `CheckIcon`/`MinusIcon`), wired into a live Controls-panel select (`argTypes.mapping`, same pattern as Button's `leadingIcon`/`trailingIcon`) and a new `CustomIcons` demo story. (10) No micro-interaction on the checkmark/dash appearing — added a `checkboxIndicatorIn` scale+fade-in animation (`motion.duration.fast` / `motion.easing.emphasized`) on `.indicator`, which only mounts into the DOM on check/indeterminate (Radix's own conditional-mount behavior), so it plays once per state change — a one-shot transition, not a continuous/looping animation, so it's outside `06-engineering-standards.md` §4's `prefers-reduced-motion` requirement (same carve-out as Badge's pop and Tooltip's fade-in). (11) `Checkbox.mdx` Docs page added from scratch, full 10-section template — Related Components links to `Switch`/`FieldLabel`/`FieldError`, none of which have their own Docs page yet, so their cards deep-link to `/story/...--default` instead of a `--docs` route (a new, documented exception to the otherwise Docs-only linking precedent, since every previously-written `RelatedCard` happened to link between already-finalized siblings). A real bug caught and fixed while writing this page: the first-drafted Accessibility section cited `03-token-system-spec.md` by filename in reader-facing prose, which `07-storybook-and-documentation-standards.md`'s own §4 rule prohibits ("never reference an internal `guidelines/*.md` path in visible page content") — reworded to state the contrast claim standalone. **The same violation still exists, unfixed, in the already-finalized `Button.mdx`** (`` `03-token-system-spec.md`'s methodology`` in its own Accessibility section) — flagged here rather than fixed, since Button is finalized and changing it needs explicit confirmation first. Full self-verification, whole package: `tsc` (package + `.storybook`), `eslint`, `tsup` build, and both Vitest projects (`unit`: 713/713, `storybook`: 274/274) all clean.

**Final review pass** (2026-08-23, same day): re-verified the full checklist end to end rather than assuming the 11 incremental findings already covered everything, the same discipline as Button's own final pass — and found two more real gaps. (1) Feature-completeness against Radix itself, this component's own direct upstream primitive, not just MUI/Chakra/Ant: Radix's `Checkbox` accepts `required`/`name`/`value`/`form` and automatically renders a hidden native `<input type="checkbox">` inside a `<form>` so it participates in real HTML5 form submission and validation — but `CheckboxProps` (extending `ComponentPropsWithoutRef<"button">`, which has no `required` of its own) silently blocked `required` at the type level, and `name`/`value`/`form`, while structurally inherited and already working, were undocumented and invisible in the Properties table. Fixed: `required`/`name`/`value`/`form` added to `CheckboxProps` with full JSDoc (no component-code change needed beyond the type — all four already flowed correctly through the existing `{...props}` spread), wired into live Playground controls, and verified two ways: live in Storybook (`required` toggling `aria-required` on the real DOM node) and via a real `<form>`/`FormData` submission test in `Checkbox.test.tsx` proving `name`/`value` actually post through Radix's own hidden input, not just type-checked. (2) The `has no accessibility violations` test only ever exercised default-styled checkboxes (unchecked/checked/indeterminate/labeled) — `hasError`'s red-border/`aria-invalid` pairing and `disabled`'s dimmed-opacity rendering were never actually run through axe, only assumed safe by inference (same gap class Button's own final review closed for its variants). Extended the test to cover both; zero violations, confirming the assumption held but wasn't previously verified. Also re-confirmed live, beyond what individual fixes already checked: full Docs page render (all 10 sections, `required`/`name`/`value`/`form` rows correctly populated in the Properties table and Playground panel, `form` correctly excluded from live controls), the `States`/`Select-all` galleries at 375px mobile width (no overflow/clipping), and Purple/Emerald × Light/Dark (all 4 combinations render correctly — Emerald hadn't been spot-checked for Checkbox before this pass). Full self-verification, whole package: `tsc`, `eslint`, `tsup` build, and both Vitest projects (`unit`: 715/715, `storybook`: 274/274) all clean. **Finalized 2026-08-23** — per that section's own note, don't make further changes to Checkbox (code, stories, docs, or its tokens) without asking first. **Raw Controls-panel order fixed, 2026-08-24 (same fix and same day as Button's — see the shared root-cause note in `07-storybook-and-documentation-standards.md` §4.1):** the raw per-story Controls panel showed `disabled` jumping to the very front, ahead of `size`/`hasError`/`checked`/`defaultChecked`/`onCheckedChange`/`icon`/`indeterminateIcon` — `disabled` was purely inherited from `ComponentPropsWithoutRef<"button">`, never redeclared on `CheckboxProps`. Fixed by explicitly redeclaring `disabled?: boolean` on `CheckboxProps` (Omitting it from the native extends first, matching the existing `checked`/`defaultChecked`/`onChange` pattern), moving `children` to the top of the interface and `icon`/`indeterminateIcon` ahead of `required`/`name`/`value`/`form` to match `propOrder` exactly. Zero behavioral/DOM/token change. Full self-verification: `tsc`, `eslint`, `tsup` build, both Vitest projects (`unit`: 715/715, `storybook`: 274/274) all clean; live-reconfirmed (after a required dev-server restart — see `07-storybook-and-documentation-standards.md` §4.1) the raw Controls panel and Docs page Properties table both now read `children, size, hasError, checked, defaultChecked, onCheckedChange, icon, indeterminateIcon, disabled, required, name, value, form, aria-label, aria-labelledby, id, className, style, data-testid` — an exact match to `propOrder`.
