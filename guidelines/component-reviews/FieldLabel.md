FieldLabel — ✅ done (2026-08-29 — comprehensive `06-engineering-standards.md` §9 review, worked one finding at a time across 7 findings): (1) `Default` story renamed to `Playground`, every prop wired live via `args`/`argTypes` (`children`, `htmlFor`, `size`, `required`, `disabled`) — confirmed multiple real, concrete gaps live first, not assumed: `size` showed an inert "Choose option..." placeholder despite `size="md"` being the real default; `required`/`disabled` both showed inert "Set boolean" placeholders; `children` fell back to a raw "Edit children as JSON" control instead of a proper text input, since it had no explicit `argTypes` entry at all. Immediately following, at explicit direction: `children`/`size`/`required`/`disabled` reordered to content-first in both the type interface and the component's own destructuring (previously `size, required, disabled, children`) — matches `FieldError`'s/`FieldHelperText`'s own established precedent. (2) `AllSizes`'s dead Controls panel fixed (`render` ignored `args` entirely, the same bug already fixed on `CloseButton`/`FieldError`/`Checkbox`) — `size`/`children`/`htmlFor` correctly stay fixed per-instance (the whole point of the grid, and each needs a unique `htmlFor` for a valid association), `required`/`disabled` now live and shared; verified live, toggling `required` updates all 5 rendered instances simultaneously. (3) `children` had no JSDoc at all — added (`/** The label text. */`, matching `FieldError`'s/`FieldHelperText`'s own one-line style). (4) `id`/`className`/`style`/`data-testid` redeclared on `FieldLabelProps` with full JSDoc — previously only worked via native inheritance, the same gap already fixed on `FieldError`/`FieldHelperText`/`Checkbox`. (5) `htmlFor` — the single most functionally important prop on this component, despite the component's own top-level JSDoc already leaning on it — was never itself redeclared either, only inherited; added with its own JSDoc, positioned right after `children` (ahead of the visual/behavioral props) given its functional importance, not treated as a generic escape-hatch prop the way `id`/`className`/`style`/`data-testid` are. (6) Judgment call, explicitly declined rather than built: MUI's `InputLabel`/`FormLabel` support an `error` prop that tints the label red when its field is invalid — flagged with the concrete comparable named, reasoned that `FieldError` already exists as a dedicated atom for that exact signal and duplicating it on the label risks two places disagreeing — **declined at explicit direction**, no error-state styling added. (7) `FieldLabel.mdx` Docs page added from scratch, full 10-section template mirroring `FieldError.mdx`/`FieldHelperText.mdx`.
