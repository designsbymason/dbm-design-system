# ProgressCircle — Storybook/component review findings

*(Migrated from `07-storybook-and-documentation-standards.md` §6 during the guidelines retrofit pass, 2026-08-31 — this file's own content is unchanged from what was there, just relocated. See `07`'s own status table for this component's current Docs-page/Finalized status.)*

ProgressCircle — ✅ done (2026-08-23 — comprehensive `06-engineering-standards.md` §9 review, worked one finding at a time, porting every fix already proven correct on `ProgressBar` to its ring-shaped sibling: Playground story added; `bg.track` token reused (no new value decision needed — see its row in `03-token-system-spec.md`'s Contrast verification section); `AllTones`/`AllSizes` stories' `render` functions fixed to accept and spread `args`; `formatValueLabel` added for API parity with `ProgressBar` (both explicitly document sharing the same API); `aria-valuetext`, `aria-labelledby`, `id`/`className`/`style`/`data-testid` all redeclared; three dev-mode warnings added (no accessible name, invalid `max`, `formatValueLabel` without `showValueLabel`); the same same-named-consumer-prop override bug found and fixed via JSX attribute ordering. A ProgressCircle-specific finding not present on ProgressBar: an invalid `max` produced a literal `strokeDashoffset="NaN"` (a real React console warning, arguably worse than ProgressBar's silently-dropped `width: Infinity%`) — fixed with the same `isMaxValid`/`safeMax` guard. Also ProgressCircle-specific: the value label's box originally filled the whole ring (`inset: 0`), visibly crowding/overlapping the ring's own stroke at small sizes and causing axe's contrast check to report Inconclusive instead of Pass — fixed with `inset: 15%` plus per-size font scaling; an initial `overflow: hidden` safety net was caught live (6x-zoom screenshot verification) silently truncating a worst-case `size="xs"` `value={100}` label from "100%" to "00%", and removed in favor of a symmetric, honest overflow. Docs page (`ProgressCircle.mdx`) added following the full template, plus the same synthetic Playground-only "Indeterminate" toggle `ProgressBar` uses. A real bug found while building the Docs page: a live `<ProgressBar>` dropped into `RelatedCard`'s centered preview slot rendered at 0 width (`ProgressBar`'s track is `flex: 1 1 auto` with no intrinsic width of its own) — fixed at the usage site with an explicit `width: var(--dbm-space-24)` wrapper, matching this project's existing precedent for other intrinsically-unsized components in preview slots (`Skeleton`'s explicit width/height on `Avatar.mdx`'s own related card). Separately, the Related Components `Spinner` preview on `ProgressBar.mdx`, `ProgressCircle.mdx`, and `Skeleton.mdx` was found rendering dark instead of on-brand (`Spinner` inherits `currentColor`, and `RelatedCard`'s preview slot forces `text.primary`) — fixed with `tone="brand"` on all three. A final review pass (same day) found two more issues before finalizing: a stale CSS comment describing pre-removal `overflow: hidden` wrapping behavior instead of the actual overflow behavior, and a unit-test coverage gap on the core value→visual mapping (`strokeDashoffset`/`strokeDasharray` had no direct assertion for valid values, custom `max`, or indeterminate mode; `tone` had no dedicated stroke-color test) — both fixed, adding 4 new tests mirroring `ProgressBar`'s own test rigor. Full self-verification, whole package: `tsc`, `eslint`, `tsup` build, and both Vitest projects (`unit`: 688/688, `storybook`: 270/270) all clean. **Finalized 2026-08-23** — per that section's own note, don't make further changes to ProgressCircle (code, stories, docs, or its tokens) without asking first.
