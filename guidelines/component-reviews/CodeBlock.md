## What was built

A single component (not compound), item 21 in the itemized molecule build order (`04-component-inventory.md`): syntax-highlighted code in a `<figure>` around a scrollable `<pre><code>`. No new dependency and no component token; twelve semantic tokens in existing categories.

Props: `code` (required; the text, never HTML), `language`, `highlighter`, `title`, `size`, `showHeader`, `showLanguage`, `showLineNumbers`, `startLine`, `highlightLines` (`[2, "4-6"]`), `wrap` with `defaultWrap` / `onWrapChange` and `wrapToggle`, `maxHeight`, `collapsible` with `collapsedLines` and `expanded` / `defaultExpanded` / `onExpandedChange`, `copyable`, `stripPrompt`, `copiedDuration`, `onCopied`, `labels` (`wrap`, `copy`, `copied`, `copyFailed`, `expand`, `collapse`, `highlighted`, `region`), and `aria-label` / `-labelledby` / `-describedby`, `id`, `className`, `style`, `data-testid`.

Files: the component and its stylesheet; the highlighter, as plain data in and out (`tokenize.ts` the choice of who highlights, `builtinGrammars.ts` the nine built-in grammars, `checkedTokens.ts` the checks on what an app supplies, `engine.ts` the scan and plain lines they share, `grammars/` the opt-in languages as `CodeLanguage`s (a shared `kit.ts` and a file per language), `languages.ts` their public entry, `registry.ts` what an app has registered, `tokenizeTypes.ts` the shared types); `useCodeScroll.ts` and `useCollapsedHeight.ts` (the scroll frame and a wrapped collapsed block's height), `copyToClipboard.ts` and `textToCopy.ts` (the clipboard, and what a shell block puts on it), `highlightLines.ts`, `diffNumbers.ts` (the hunk-header parser); and `browserProtocol.js` with its `.d.ts`, which only the hidden real-browser stories use. Props and files as of the post-Finalization passes at the end of this file; the sections between record how they got there.

## Decisions taken while building

- **Highlighting is a small built-in tokenizer** — the fork in the road, put to the user (built-in, over a highlighting dependency or bring-your-own) and chosen as recommended: [ADR-0026](../adr/0026-codeblock-highlights-with-a-small-built-in-tokenizer-over-a-highlighting-dependency-or-bring-your-own.md). The user also chose all four extras (line numbers and highlighted lines, a title, wrapping, collapsing).
- **`code` is a prop, not `children`.** A JSX string child loses or mangles whitespace and needs a template literal anyway; an explicit `code` string is exact, agent-friendly, and is precisely what the copy button copies. Its native `onCopy` (a selection was copied) is a different event, so the callback for the button is `onCopied`.
- **Syntax colours are semantic tokens in the existing `text` category** (`text.syntax-keyword` … `-deleted`), shared across both brands like `text.link`, plus two surfaces: `bg.code-block` and `bg.code-highlight`. Every colour was measured against both surfaces in all four themes (4.5:1 or more; `03-token-system-spec.md` has the numbers). The highlighter's ten kinds are the whole palette.
- **A highlighted line is a band and an edge accent**, not colour alone (4px in `border.focus`, transparent on every other line so nothing shifts). Line numbers are drawn by CSS (`attr(data-line)`), so they are never selected, copied or read as code; a wrapped line is indented past the number by padding and a negative first-line indent, so it continues under its own text.
- **Everything stays in the page when collapsed.** A collapsed block clips its own height (`overflow-y: hidden`, exactly N lines and no part of the next), with a fade. Find-in-page and the copy button use all of it, and the expand button is a real button with `aria-expanded` and `aria-controls`, saying how many lines it will reveal.
- **The scrolling area is a named tab stop only while it overflows** — [ADR-0019](../adr/0019-table-owns-an-overflow-aware-scroll-container-and-puts-native-props-on-the-table-element.md)'s pattern, with its own small hook (`useCodeScroll`) rather than `Table`'s: a collapsed block clips its height on purpose, which is not something a keyboard can scroll to, so vertical overflow doesn't count while collapsed. Reusing `Table`'s hook would have made a collapsed block a tab stop with nothing to scroll. Sharing one hook is recorded as a gap, since it means changing Finalized `Table`.
- **Copying falls back.** The Clipboard API where the page may use it; otherwise a hidden, selected `<textarea>` and the older `copy` command (still the only route on an insecure page), restoring focus afterwards; and a failure is announced, not silent. `useAnnouncement` gives the timing; the live region is already in the page.
- **The header is always a `<figcaption>`** holding the title and language on one side and the copy button on the other (logical, so it mirrors); without either it holds only the button. One layout, not two. A long title is cut short with an ellipsis and never pushes the button out. *(Since the last pass: `showHeader={false}` draws no header, and `showLanguage={false}` no language label; the buttons then sit in the corner of the code.)*
- **Code stays left to right** in a right-to-left page (`direction: ltr` on the scroll frame); the header follows the page.
- **Text past 30,000 characters is drawn plain** in every language the library ships, so a huge input can't stall the page. (Since the last pass the limit is a property of the language, `maxLength`: an app's own has none.)

## Findings from the build

- **The first dark-mode highlight read backwards.** With `bg.code` (gray.800) as the block, the only highlight band that keeps every syntax colour AA is *darker* (gray.900; a lighter one falls to 3.6–4.1:1), so the highlighted lines were darker than the rest and the un-highlighted lines looked emphasised. Every test passed; a screenshot of dark Emerald showed it. Fixed by giving the block its own background, `bg.code-block` (light: blue.50, the same as `bg.code`; dark: gray.900, a step darker than the inline pill), so the band, `bg.code-highlight` (dark: gray.800), is the lighter one; all colours re-measured.
- **A collapsed block showed 70% of the next line** under the fade, because the frame's bottom padding was inside its height. Also seen only in a screenshot. The height is now the top padding plus exactly N lines, asserted in the browser (the sixth line starts at or below the frame's bottom edge).
- **TypeScript's built-in type names (`number`, `string`, …) weren't coloured** beside a coloured `Array`; ts and tsx now colour them, JavaScript doesn't.
- **The tokenizer's tests found real gaps:** JSX text between tags was coloured as code (`Save` as a type) and `</Button` wasn't a tag (fixed with a small state machine: text mode, expression depth, open-tag depth); selectors inside an `@media` block weren't recognised (a stack of blocks, rules versus declarations); a command after `then` or `do` wasn't a command.
- **A test that measured the thing against itself.** The full-width-band assertion compared a line's width with its parent's, which are equal whether or not the band spans the scrolled content; it now compares with the frame's `scrollWidth`.
- **Mutation checks found seven weak spots** in the first round of mutations: `highlightLines.ts` had no direct tests; a JSX end-of-element counter and quotes in HTML text were untested; the focus restore after the fallback copy was never exercised (a mock of `select()` now moves focus, as a browser may); the right-to-left mirror of the header padding was unchecked; the band-width test above; and one guard (a digit inside a name) turned out to be dead code, since identifiers are consumed whole, and was removed. All closed; 38 mutations now, each seen to fail.
- **Two smaller catches:** the native `onCopy` collided with the callback's first name (a type error); `Range.getClientRects` returns a rect per character, which made a wrapped-line alignment test wrong, not the CSS.

## Follow-up, 2026-09-26 (before Finalize): snippets define their placeholders

A reader asked why the Variants snippets showed `code={source}`. It is a placeholder for the reader's own string (the demo text is long and would swamp the props each variant shows), but nothing in the snippet said so, and some snippets used real inline strings while others didn't — so they weren't pasteable and looked inconsistent. At explicit direction, every snippet that passes a placeholder (`source`, `excerpt`, `command`, `config`, `output`) now defines it in its leading comment, the Playground's snippet starts with `{/* source: the code to show, as a string */}`, and the Docs page states the convention once above the variants. A unit test asserts that every `code={name}` in every CodeBlock snippet, and in the Playground's, is explained in a comment; it fails with one explanation removed (checked). The rule for any component's snippets is now in `07-storybook-and-documentation-standards.md` §4.2.

## Final review before Finalizing, 2026-09-26

A full `06-engineering-standards.md` §9 pass against the code and the running component. **Fixed (three defects), and the checks that found them are now tests.**

**Fixed**

1. **A CSS word made the tokenizer quadratic.** The three CSS rules for a property, a property and a function each wrote a lookahead into the pattern (`[A-Za-z-][\w-]*(?=\()`), which retries from every letter of a long word: 29,000 characters took 0.7 seconds, 1.6 seconds inside a rule (a `data:` URI in a `url()` is exactly such a word), stalling the page. They are one rule now that takes the whole word and decides afterwards by what follows it, so cost is proportional to length. Nine long-word tests (CSS four ways, tsx and html in a tag, bash, json, ts) under a 250ms budget fail with the old rules (checked: the old ones were 700–1,600ms). Found by timing hostile input, not by reading; the earlier "large unterminated input" test had used inputs that don't trigger it.
2. **`code={undefined}`, `null` or a non-string crashed the render** (`code.replace is not a function`), and so did a non-string `language`. `code` is routinely data on its way (`code={snippet?.text}`), and one that hasn't arrived shouldn't take down the page around it. A `code` that isn't a string is now an empty block, with a development warning once, and the copy button copies `""`; a `language` that isn't a string is plain text. Tests for the tokenizer and the component, each failing with its guard removed (checked).
3. **`wrap` and `collapsible` together cut a line in half.** `collapsedLines` counts lines, but the collapsed height was that many *rows*, so a line that wraps onto five rows was sliced after two, and "Show N more lines" said the wrong number (measured: the second line's bottom at 361px against a frame ending at 135px). A wrapped block is now cut where its Nth line ends, measured (`useCollapsedHeight`, on `useSyncExternalStore` like `useCodeScroll`, so it is right on the first frame and re-read when the width changes); an unwrapped block keeps the exact stylesheet height. A real-browser story covers two whole lines, the button's count, expanding, collapsing, and narrowing then widening the container; three mutations fail it (no measuring, no re-read on resize, measuring without `wrap`).

**Checked, no action needed**
- **Baseline:** no `any`, suppression or raw value (every number in the stylesheet is a unitless reset, and `tab-size` is documented as a content format); JSDoc on every prop with the defaults; `{...props}` precedes the name; no `dangerouslySetInnerHTML`, `innerHTML`, `eval` or `Function` anywhere; SSR-safe (a timer only in an effect, `useId`); `StrictMode` tested.
- **Storybook:** all 16 visible stories checked in the running Storybook for inert controls ("Set string" and the like): none; the Playground's controls drive the canvas (title, start line, numbers, wrap, collapse with its button's count, copy button, language, and highlight counted from the start line).
- **Composition:** tab order is the copy button, then the scrolling code (only while it overflows), then the expand button; `IconButton`, `Button`, `VisuallyHidden`, `useAnnouncement` and `mergeDefined` are reused rather than reimplemented.
- **All 39 mutations re-run after the fixes; none survives** (three older ones needed their target text updated after a rename).
- **Feature completeness, considered and not added:** what is already named below; a language auto-detect (a wrong guess is worse than plain text); copying with the line numbers (never wanted).

**Not verified:** a real screen reader; the real Clipboard API against a permission prompt; forced-colours mode (all three were later closed or narrowed, see the post-Finalization pass below).

## Post-Finalization pass, 2026-09-26 (at explicit direction): items 1–3 of the gaps list

Three gaps the user asked to close in one pass. **Finalized status unchanged**, by the three-question test in `06-engineering-standards.md` §9: each corrects a genuine defect against an existing requirement (a screen reader can't tell what is highlighted; a highlight and plain lines that look alike in forced colours; a copied command that doesn't paste), and the one new prop is additive.

- **A highlight is said, not only drawn.** The first line of each highlighted run is preceded by a visually hidden cue, `labels.highlighted(count)` ("Highlighted line:", "3 highlighted lines:"; translatable, a function of the run's length so a long highlight is announced once, not on every line), in `VisuallyHidden` with `user-select: none`. It is never selected or copied (`copy` uses `code`, and a real selection's text is asserted). Tested per run, from `startLine`, translated, and with an `undefined` label.
- **The line numbers were not decoration, and the docs said they were.** Found while checking the cue: Chrome's accessibility tree contained `StaticText "1"`, `"2"` — CSS-generated content is exposed to assistive technology unless it says otherwise, so the sentence in this file and on the Docs page ("a screen reader does not read them") was false. They are now `content: attr(data-line) / ""` (empty alternative text), with a fallback declaration for a browser that doesn't know the syntax; a real-browser story reads the accessibility tree over the Chrome DevTools Protocol and asserts the code and the cue are there and no number is. (Checked the other generated content in the system: `Slider`'s width-reserving sizer is `visibility: hidden`, so it isn't exposed.)
- **Forced colours was worse than recorded.** Emulated in the real browser (the same protocol): every line, not only the highlighted one, drew a solid black 4px bar (a transparent border is drawn in forced colours), and the highlighted line's band was gone, so the highlight looked like all the rest. Plain lines' accent is now the system colour `Canvas` (invisible) and the highlighted line's `Highlight` (visible, still 4px: the one cue left), and the collapse fade, a colour gradient, is removed there. A story emulates forced colours and asserts each; three mutations fail it.
- **`stripPrompt` (default `true`).** In shell code a leading `$ ` is drawn but not copied, so `$ pnpm add x` pastes as `pnpm add x`; `onCopied` receives what was copied. Only `$` and a space count (`$HOME`, `$(cmd)`, `$$` are code), indentation is kept, and lines without a prompt (a comment, a script line, output) are copied as they are: a smarter "transcript" rule that dropped lines without a prompt would have removed real script lines from a mixed block, so the docs say to keep output in its own block. `stripPrompt={false}` copies exactly what is written. Six unit tests for the transform, four for the component; fifteen mutations fail, including a regex that eats `$VAR`, lost indentation, stripping in every language, and the default flipped.
- **Two problems the new tests then found in older code.** The wrapped-collapse hook (added in the final review) re-measured inside its own `ResizeObserver` callback and changed the frame, an ancestor of what it observes, so the browser reported a "ResizeObserver loop" error (benign, but an app's error tracking logs it); it now applies a resize on the next animation frame, with a story that listens for the error while the block resizes (fails without the change). And a hidden story's assertion measured a highlighted line's text position including the new cue; it now starts from the code.
- **A test-runner import that broke the real Storybook, found only by opening the Docs page.** The protocol checks need `vitest/browser`, which throws when evaluated anywhere but the test runner: a top-level import in the stories file made the Docs page and every CodeBlock story fail to load, with every test green. Importing it from TypeScript also made the whole project load its type declarations, which replaced `toHaveStyle`'s typing in unrelated test files. It now lives in `browserProtocol.js` (typed by a hand-written `.d.ts`), imported dynamically inside `send`, and a unit test loads the stories module outside the runner (it fails with a static import, checked).
- **Verified:** lint and both typechecks; all 3,402 unit and 817 real-browser tests; the visual suite; the size checks (`CodeBlock` 7.47KB JS, 1.98KB CSS gzipped); the Storybook build and size check; token coverage; `pnpm audit`. The Docs page checked live (17 canvases, the new section and property row with its default, the corrected accessibility text).
- **Still not verified:** a real screen reader (the accessibility tree is verified, not a person's experience of it), and the real Clipboard API against a permission prompt. Forced colours is now verified by emulation, not on Windows.

## Post-Finalization pass, 2026-09-26 (at explicit direction): more languages (gaps list item 4)

Seven grammars added to the tokenizer: **Python, YAML, SQL, Markdown, Go, Rust and Java**, with aliases (`py`, `yml`, `postgres`, `mysql`, `sqlite`, `md`, `golang`, `rs`). **Finalized status unchanged**: purely additive (a language that used to draw as plain text now has colour), question 1 of the three-question test; the rest of the component is untouched. It follows [ADR-0026](../adr/0026-codeblock-highlights-with-a-small-built-in-tokenizer-over-a-highlighting-dependency-or-bring-your-own.md) as written (the decision there is that a language is added by adding a rule list and its tests), so no new ADR.

- **Structure.** `tokenize.ts` had reached 400 lines, so the shared vocabulary (token types, the scan's state, what a rule is) moved to `tokenizeTypes.ts` and the new grammars live in `grammars.ts`; `tokenize.ts` re-exports the types, so no import elsewhere changed. The engine gained two pieces of state: `lineStart` (YAML keys and Markdown headings only make sense at the start of a line) and `fence` (a Markdown fenced block's lines are drawn as they are, so a snippet of another language inside one is never mistaken for Markdown).
- **Cost stays proportional to length, by construction** *(not so for markdown links and tags and Rust attributes, found later the same day: see the last follow-up)*. Last review's lesson (a lookahead written into a word's pattern goes quadratic) is applied everywhere: a word is taken whole and classified after; a YAML key is looked for once per line, at the line's start; and every string or comment that may never be closed runs to the end of the text as a single match (a Python triple quote, a Rust raw string) instead of failing and being retried from the next opener. Tests time an unbroken 29,000-character word in every new grammar in several positions, and fifteen inputs built to make a match repeat (a Rust raw-string opener 9,000 times, a Python triple quote 9,000 times, a Markdown link opener 7,000 times, and so on), all under 250ms.
- **What each recognises.** Python: keywords, `self`/`cls`, `True`/`False`/`None`, decorators (only where a statement starts, so `a@b` isn't one), string prefixes (`f`, `rb`) and triple-quoted strings, built-in types. YAML: keys at the start of a line (after indentation and a list dash, quoted or not; a colon inside a value doesn't make a key), strings, anchors, aliases, tags, block-scalar markers, `true`/`null`/`yes`, numbers, comments (not a `#` inside a word), document markers. SQL: keywords in any case, types, functions, a doubled quote inside a string, quoted identifiers as names, `@param`/`$1`/`:name` (not the `::` of a cast), both comment forms. Markdown: headings, lists, quotes, rules, inline code, links, bold, HTML, fenced blocks. Go: keywords, built-in types, `func` names including generic ones, raw strings across lines, calls before types (`fmt.Println` is a call, `Server{` a type). Rust: lifetimes versus characters, raw strings of any `#` depth, macros, attributes, numeric suffixes, `fn` names. Java: annotations, text blocks, built-in types.
- **Verification.** Tokenizer: 443 tests, and the invariants (lossless output, the random-text fuzz) now cover 16 languages. **38 mutations, each seen to fail**; five survived the first round and closed real gaps: an unterminated Python triple quote wasn't tested, `a@b` wasn't tested, a YAML value like `title: Note: read this` wasn't (it coloured `Note` as a key), a Go generic function name (`func Map[T any](`) wasn't, and Python's `def`-name rule turned out to be dead code (the call rule already names it) and was removed. The real-browser contrast story now includes every new language, so every colour they use is measured against the block and a highlighted line in all four themes. Checked live in Storybook (all seven, light).
- **Whole pipeline:** lint and both typechecks, all 3,675 unit tests and 818 real-browser tests, the visual suite, the size checks, the Storybook build, token coverage, `pnpm audit`.
- **Cost.** `CodeBlock` grows from 7.47KB to 9.68KB JS gzipped (2.2KB for seven grammars); within budget. All grammars load with the component, whichever language a page uses. Loading a grammar only when its language is used was recorded as a gap, and was done in the last pass below.
- **Not done.** No other languages (C, C++, C#, Ruby, PHP, Kotlin, Swift, TOML); a grammar is added with its tests when there is a need.

## Post-Finalization pass, 2026-09-26 (at explicit direction): opt-in languages and a highlighting hook (gaps list items 19 and 5)

### Follow-up, same day: three quadratic rules the earlier timing tests could not see (found by CI)

After the push, CI failed one test: a markdown "repeat" input took 383ms against its 250ms budget on the slower machine. **It was a real defect, not noise, and older than this session's changes.** Markdown's link rule (`[a](` repeated: 8ms at 7,000 characters, 21ms at 14,000, 80ms at 28,000, four times per doubling) read to the end of the line from every unclosed `[`, and its HTML-tag rule did the same for every unclosed `<a`; Rust's attribute rule did it for every unclosed `#[`. **The earlier claims that "cost stays proportional to length, by construction" and that the repeat inputs "all finish under 250ms" were wrong for these three:** a fixed budget at one size cannot tell linear from quadratic, and the size was small enough that a quadratic passed it locally.

- **Found by scanning, not guessing:** about 3,000 repeating units (every one to three characters over the characters that open something) against 15 languages, timed at 6,000 and 24,000 characters, flagging anything that cost more than six times as much: 783 hits, all markdown (753) and Rust (30); the other 13 grammars had none. After the fix the same scan flags none.
- **The fix.** The link label may not contain `[` and its address may not contain `(`; a tag stops at the next `<`; a Rust attribute stops at the next `[`. An opener that is never closed then fails at the next opener instead of at the end of the line, so the scans do not overlap. The cost: a link whose label contains brackets (`[![a](b)](c)`), an address with nested parentheses and an attribute containing `[` are drawn with the outer construct uncoloured (the inner link still is); the docs already call the tokenizer approximate.
- **The test now measures scaling.** For 47 openers across all sixteen grammars, four times the text must cost less than nine times as much (linear is four, quadratic sixteen), best of three, with a 2ms floor. Each of the three old rules put back (and the two half-fixes) fails it; it was stable over four runs. The old fixed-budget tests stay.

`06-engineering-standards.md` §9's linear-time item now says to test scaling, and to scan, not to trust a budget at one size.

## Post-Finalization pass, 2026-09-26 (at explicit direction): diff line numbers (gaps list item 7)

`showLineNumbers` on a `diff` now numbers it from its `@@ -12,4 +12,5 @@` hunk headers, in an old column and a new column. **Finalized status unchanged**: additive, with no new prop (question 1). - **`diffNumbers.ts`.** `parseDiffNumbers` reads the rows of the diff as drawn and returns each row's `{ old?, new? }` (a removed line an old number only, an added line a new one only, a context line both; a header, a `\ No newline` marker and anything outside a hunk none), or `undefined` when there is no hunk header. A label that is not a string, or blank, is ignored, and a registered one is trimmed. Names are proper nouns, so they are not in `labels` and not translated. `data-language` stays as written.
- **Verification.** Unit tests for the table (aliases, case and spaces, alias-by-what-was-written, prototype names, coercion) and the component (built-in names, raw fallback, `data-language`, opt-in language before and after registering, a registered label ahead of a built-in name and trimmed, and a registered language with no usable label falling back), 12 mutations all seen to fail (one needed the array test above, one, the raw style's capitals, is CSS and needed a real-browser story). Checked live: "TypeScript", "TSX", "C#", "C++" in the Docs page and stories, an unknown name in capitals. Core `CodeBlock` 7.93KB to 8.12KB JS gzipped, the opt-in entry 5.55KB to 5.61KB.

**Print**
- **What prints.** A block is whole and legible whatever the theme on screen: a collapsed block and a `maxHeight` block print in full (the inline height is overridden, hence `!important`), a long line wraps under its own text instead of running off its scroll frame; the copy and wrap buttons, the expand button, the collapse fade, a header that would hold only buttons, and the room kept for corner buttons are dropped. Backgrounds are not printed unless the reader asks and the syntax colours are pale in a dark theme, so a block prints as `CanvasText` on `Canvas` with the emphasis a colour carried: keywords and added lines semibold (`font-weight.semibold`), comments italic (already), a grey gutter (`GrayText`), and a solid edge for a highlighted line. A block that fits a page is not split, and a line never is.
- **Verification.** A real-browser story emulates print media through the DevTools Protocol, in a dark theme: black on white for the block and every token, heavier keywords and added lines, italic comments, no buttons or fade, a highlight as a solid black 4px edge with no band, a grey gutter, twelve lines in a block collapsed to four, a `maxHeight` block in full, a long line wrapped within its frame, no room kept for corner buttons, no header of buttons alone, and the screen look restored after. 17 stylesheet mutations, all seen to fail; two first survived because "not a scroll frame" was asserted only through its effect (there was nothing to scroll), so the computed overflow is asserted. Looked at, not only measured: screenshots of the print rendering in a dark theme.
- **A real defect the print screenshot showed, older than this pass.** In a numbered diff with wrapping (on screen too, not only in print), a short row whose number was a new-only two-digit one (`"    10"`) doubled in height: a wrapped line breaks at spaces and anywhere, and the padded gutter string, a hair wider than its `6ch` box, folded its last number onto a second row. An earlier pass had removed `white-space: pre` from that gutter as "redundant" (it is inherited from the `pre` on screen without wrapping, which is why nothing noticed) and the wrapped-diff test measured only the long row. The gutter is `white-space: pre` again, with the reason in a comment, and both the wrapped-diff story and the print story now measure that every short row is one row (each fails without the fix).
- **Not verified:** pagination (that a block which fits a page is not split, and a line never is; `break-inside` is declared, but a paged layout cannot be asserted from emulated print media, and no PDF renderer was available here to look at a real printed page); the look on a real printer.
