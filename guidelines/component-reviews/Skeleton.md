**Defect found and fixed 2026-09-02 (during `AspectRatio`'s review, not Skeleton's own) — stays finalized, per the three-question test in `06-engineering-standards.md` §9 (a genuine pre-existing defect, not a preference change).** `Skeleton` was rendering with a fully invisible (transparent) background in every live context — its own stories, every other component's Docs page that previews it via `RelatedCard` — across all 4 brand/mode themes, likely since 2026-08-25. Root cause: `bg.scrim`'s `$description` in all 4 `packages/tokens/src/semantic/*.json` files contained the literal text `bg.*/text.*` (missing a space) — CSS parses `*/` as a comment-close token regardless of surrounding context, so this prematurely terminated `bg.scrim`'s own built-CSS comment; the resulting stray, unmatched `*/` later in the same declaration list corrupted CSS's own error-recovery algorithm (which discards an invalid declaration up to its next `;`), silently swallowing the entire `--dbm-bg-skeleton: var(...);` declaration immediately following it in file order. `tsc`/`eslint`/`vitest` all stayed green throughout, since nothing here is TypeScript- or unit-test-visible — this was only catchable by live-checking the actual rendered/computed CSS in a browser, confirming the standing rule in `07-storybook-and-documentation-standards.md` §4.1/§7.1 yet again. Fixed by adding the missing space (`bg.* / text.*`) in all 4 files and rebuilding `packages/tokens`; re-verified live across both brands × both modes, in both Skeleton's own stories and `AspectRatio.mdx`'s `RelatedCard` preview. See `03-token-system-spec.md`'s "Build pipeline decisions" section for the standing rule this added (any token `$description` must avoid an unescaped `*/` sequence, since it's baked verbatim into the built CSS as a comment).
